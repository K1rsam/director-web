# 第一阶段原文识别与结构预览

日期：2026-10-04。新版同名 `src-tauri/target/release/director-desktop-stage13.exe` 已包含此修复；没有构建安装包。

## 为什么旧弹窗不合适

旧 web 第一阶段确有按起止行修正资料/正文归属的能力，但藏在来源页高级折叠项，文案明确仅在归属有问题时使用。确认依据由程序记录。常规“整理资料”先运行来源整理，必要时才用 CLI 判断原行块分类。

桌面版把这个兜底入口前置，又默认选择整份文档、第一集，并要求手写场景与确认依据，容易把多集原文错误归成一场。其确定性解析器漏掉了“故事简介、人物关系、段纲”等前置资料标题。

本次只读核查实际项目：461 行原文中，10 集和 21 场已识别，只有前 24 行资料未确认。问题是局部前置资料，不是正文缺少全部集场。

## 现在的使用方式

导入原文后，程序识别明确的集场和资料标题；正文上方展示识别集数、场数与待处理数量。可以直接整理制作基础，也可以展开“查看分集结构”并在原阅读区查看某集、某场或背景资料。完整原文始终保留。

已导入的旧项目点一次“重新识别”，用当前原文重新计算分类。此操作在本地运行，不调用模型、图片或视频生成；已保存的明确范围决定保留。结果没有变化时，不增加版本。

只有真正无法确定的局部片段才显示用途选择：补充资料，或正文剧情。默认只选当前问题片段，不跨过已经识别的正文，不猜第一集；正文需明确所属集和场景。用户不再填写确认依据，程序按实际选择保存记录。高级行范围调整收起，且只允许调整当前疑点内部的完整行。说者分段等其他问题保留原类型，不能以改成资料掩盖。

本次增加确定性资料标题识别，没有重新引入旧 web 的完整 P1 语义分类执行链。没有明确标题、格式仍有歧义的文本继续局部待确认，后续规则更新可以针对实际样本扩充。

## 原文和版本约束

`source-parser/v2` 只改变结构归属，保留完整文本、SHA-256、UTF-16 行坐标与原话。缺少 `parserVersion` 的旧记录仍按原 v1 规则验证，不因新词法规则突然变成无效成果。

重新识别与局部决定均携带当前原文版本，保存时在同一个短事务内核对；过期页面不能覆盖新范围。旧记录及已提交云端素材不改写。同样的识别结果或范围决定不创建重复版本。
