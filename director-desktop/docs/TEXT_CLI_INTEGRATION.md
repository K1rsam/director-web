# 第一至第三阶段 CLI 执行补齐

日期：2026-10-04。使用同名独立测试客户端 `src-tauri/target/release/director-desktop-stage13.exe`；没有制作安装包，也没有替换旧 `director-desktop.exe`。

## 实际调用与设置

| 操作 | 执行方式 | 前置条件 |
| --- | --- | --- |
| 第一阶段：整理制作基础 | Rust 直接启动本机 Codex CLI；也可配置文本 API | 导入并确认原文集场，保存文本设置 |
| 第二阶段：设计图片提示词 | 同一文本执行器，保存规则和设置快照 | 原文与资产目录；手写完整提示词可以跳过设计 |
| 第二阶段：生成图片 | 已选图片渠道，如即梦 CLI、BH 或 Chrome bridge | 图片提示词、渠道登录和合法参数 |
| 第三阶段：生成分镜文字 | 同一文本执行器与 Rust 原文回读、校验、事务发布 | 已锁定原文与所选集场；不用先配置视频模型 |
| 第四阶段：生成视频 | 已选视频渠道；素材准备和提交时自动预检 | 分镜文字、正确图片绑定与模型参数 |

文本模型调用此前已经使用原生 CLI。本次补齐了可见的设置、登录和执行前校验，没有迁入旧 Node 后端。

在「渠道与设置 → 文本执行 · 阶段 1 / 2 / 3」选择程序、检查账户、登录、选择实际模型及支持的推理强度，再保存本机设置。自动发现支持本机原生程序及常见安装位置；显式指定错误路径会报错，不回退到其他程序。三个阶段上方显示当前文本执行设置；第二阶段明确区分提示词设计与图片出图。

CLI 状态通过原生 `app-server` 的账户、模型与额度接口读取。浏览器登录由官方返回的地址启动，工作台保留本次登录等待并同步结果；可取消等待。实现依据本机 CLI 协议及[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。模型目录不代表账户必然具有某模型的执行权限；未知额度保持未知，不推算可用金额。

每次新文本执行按保存的模型与强度自动检查；工作流快照固定本次解析出的原生程序、版本与设置。已指定的模型不会被静默替换；空模型只有在 CLI 返回默认模型时才能解析。文本 API 使用服务默认推理策略。仅已通过领域校验的原结果可复用；失败回包保留错误和结构化事件，不伪装完成。

## 启动提示修复

之前打开项目直接进入第四阶段，页面又自动请求视频预检，与后台启动时的渠道账户检查竞争同一把锁。冲突被全局横幅显示为「相关任务正在执行」，切到第一、二阶段后仍残留，并不表示这两个阶段正在生成。

现在打开项目进入第一阶段；第四阶段加载只读已有能力，不自动执行预检。准备素材或提交时仍按当前渠道自动检查。导航清除旧提示；实际冲突说明具体渠道或任务。后台能力刷新只有取得执行权才记录尝试时间，避免尚未检查就被错误延后 15 分钟。

项目有图片但没有原文时，图片提示词设计会明确要求先导入原文；已有手写提示词仍可直接生成图片，不要求文本 CLI。截图中「0 集」正是这个输入缺口，不能以已有图片代替原文。
