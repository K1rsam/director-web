# 即梦连接与生图参数修复

## 2026-10-07：按 SHUO 简化 OAuth 连接

对照本机 SHUO Canvas 0.8.0 的 `dreaminaCliApi.js`、`appTopbarDreaminaSession.js` 与 `cliProviderSettings.js`：账户检查与主动授权分开，活动授权页可重新打开，网页授权后自动刷新账户。

- 用户点击「OAuth 登录」或「重新登录」时，直接执行官方 `relogin --headless`。不再先调用 `user_credit` 决定是否允许授权；失效的本地登录、身份缺失和网络检查失败都不会挡住授权入口。启动和后台查询不会触发重新登录。
- 等待授权时点击「打开授权页」复用当前流程。短暂查询失败保留同一设备流程，连续三次网络/超时/查询失败后结束等待；拒绝、过期立即结束，允许用户重新授权。
- 只有实际账户查询取得可验证身份才显示已登录及积分。未登录显示「登录后显示」，真实已登录的零余额仍显示 0。
- 主界面保留登录状态、额度、OAuth/重新登录、退出及刷新。合并重复即梦卡片，CLI 路径和模型更新收进高级设置；缺失的积分分类不填虚构数字。
- Windows 授权页使用 `ShellExecuteW` 的默认 HTTPS 处理器打开，不再将 URL 传给 `explorer.exe`。调用失败向界面返回错误，不再吞掉错误显示成功；授权中可复制同一链接手动打开。原生接口按 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew) 在独立 STA 线程调用并检查返回值。

验证：即梦后端 91 项通过、2 项显式忽略；实际 React 账户卡片 6 种状态通过。上述是本地功能回归，官方网页的最后授权确认仍由用户完成。不提交视频生成。

2026-10-04：截图中的首次尝试被前端账户标签检查拦截，没有创建生成任务。官方 CLI v1.4.19 实际已有登录，安全账户查询读取总积分 14414 和可验证身份。没有退出、重新登录或付费生成。

## 使用当前开发代码

关闭旧客户端，打开 `src-tauri/target/release/director-desktop.exe`。最新本地测试版使用 `--no-bundle` 更新 release exe，内嵌界面并隐藏本地运行进程的终端；旧安装包未更新，正式打包等待用户通知。

1. 打开项目的「渠道与设置」。已有官方登录会在后台检查；也可点「刷新状态与积分」。连接成功后显示总积分与已核实身份，缺失分类不显示虚构的 0。
2. 没有登录时点「OAuth 连接即梦」，在官方网页确认；客户端自动检查结果。CLI 自行保存凭据，工作台不读取或复制 SHUO 私密数据。
3. 第二阶段选择图片模型、尺寸、比例，保存提示词后生成少量试稿。生成成功自动设为当前图片，历史可切回旧图。第四阶段选择参数后点击「准备所选素材」，程序自动检查渠道并保存参数；核对冻结素材及费用后点击「生成所选视频」，无需另点核实或保存。

同一系统用户可能共享官方登录，退出会影响 SHUO，按钮有确认。工作台换账户后只能查询该账户原有任务，原账户任务继续暂停。提交结果未知不会自动重发。

## 图片预设

| 比例 | 1080P 像素预设 |
| --- | --- |
| 16:9 | 1920×1080 |
| 9:16 | 1080×1920 |
| 1:1 | 1080×1080 |
| 4:3 | 1440×1080 |
| 3:4 | 1080×1440 |
| 3:2 | 1620×1080 |
| 2:3 | 1080×1620 |
| 21:9 | 2520×1080 |

1080P 是工作台的像素预设：使用官方 `resolution_type=2k` 的自定义宽高，提交时省略 `ratio`，不是新造的官方枚举。原生 2K/4K 仍通过官方分辨率与比例参数提交，实际输出宽高以渠道结果为准。

模型 3.0/3.1 支持原生 1K/2K；4.0–5.0 支持原生 2K/4K；5.0Pro 支持 1.5K/2K/4K。运行时帮助核验有自定义宽高才开放 1080P。视频选项同样按具体型号核对；VIP 型号可有 4K，不能套用到 fast 型号。非法旧参数显示重新选择，不自动降级。

## 后续试稿卡住修复

随后用户在第二阶段实际创建的图片任务进入 submitting 后退出客户端，没有保存渠道任务 ID，重启归为 submission_unknown。准备参数含 5.0、resolution_type=2k 与 1920×1080；这只能证明准备完成，不能证明 CLI 已发送或渠道未受理。最新提交路径移除持久化意图后的重复帮助检查，保留冻结能力、参数、素材哈希及 CLI 文件身份校验。退出等待完整工作线程保存回执，而非只等子进程停止。

旧未知记录不自动重发或自动关闭。图片页「查看与处理任务」进入记录，找到官方 ID 时绑定并查询原任务；确认未受理时填写依据关闭为 closed_by_user，之后再明确发起新的试稿。原快照、准备材料、错误和事件保留。

视频能力按当前独立官方 CLI 1.4.19 帮助：seedance2.5 为 480p/720p/1080p；seedance2.0_vip 为 720p/1080p/4k；seedance2.0、2.0fast、2.0fast_vip、2.0mini 固定 720p。固定尺寸显示为有效单项，非空失效旧参数仍须明确重选。

## 已生成结果回传修复：图片与视频

用户原图片任务在即梦已成功，官方查询返回 `gen_status=success`，原图位于 `result_json.images[].image_url`。旧解析遗漏 `result_json`，随后把空地址误判为过期。现在按原任务类型读取图片或视频结果，排除封面、缩略图与输入参考；显式任务 ID 别名必须一致。成功缺地址和未知状态归为可恢复查询失败，保留原 ID、原始响应与提交快照。明确过期才标为过期，旧误判记录仍可查询原任务恢复。

原任务已使用同一账户和同一云端 ID 下载，恢复到“林夏”的候选图片；未重新生成、未替用户采用。实际原图 2560×1440，SHA-256 与落盘文件核对通过，画面与用户提供的即梦网页截图一致。此前请求的 1920×1080 是目标尺寸，官方帮助明确模型可能对齐实际输出尺寸；原图不做裁切或缩放。

本机代理访问原图服务器超时，直接访问同一完整签名 HTTPS 地址得到 200。即梦结果下载只在连接错误或超时后重试直连；继续验证 HTTPS，不因 HTTP 拒绝重试路由，不重新提交生成。图片、视频使用相同下载逻辑。

最终核心离线测试 **124 项通过、8 项默认忽略**，其中恢复回归 **13 项**同时覆盖图片与视频的地址暂缺、未知状态、下载地址过期、多结果部分下载与重启、身份及类型错误、已下载结果保护；恢复新增提交为零。视频结果结构与恢复仅通过合成回归，尚未查询或下载真实官方视频，也未验收画面或声音。最新 release exe 的启动与原任务恢复证据见 [结果回传核验](verification/dreamina-result-recovery.json)。本轮只更新 exe，未构建安装包。
