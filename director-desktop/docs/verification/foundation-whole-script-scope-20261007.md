# 全剧资产目录范围与已有基础形象合并

## 问题

阅读第一阶段的某一集会隐式限制主按钮的制作范围。单集流程完成后，界面仍显示“制作完成”，第二阶段切回“全部集数”只能展示已经写入的单集目录，容易误认为这是全文提取结果。本次实际样例的 9 张卡片只对应第 7 集。

原 Web 的 F2、Q1，以及第二阶段 A15/C/D 岗位正文仍包含在桌面 Skill 中。本次未改这些规则、模型、批次容量或原文；问题在桌面的范围传递、完成状态和已有身份合并。

## 修复

- 主操作固定为“整理全剧制作基础”，始终传入当前源文全部集数；阅读单集时另提供“仅整理当前集”。
- 用当前源文版本和 SHA 匹配的已发布基础统计“已整理 n / m 集”。单集流程完成不等于全剧完成；第二阶段提示目录实际覆盖范围。
- F2 可按原 key 描述已登记的基础形象，不再视为新建重复子形象。显式基础形象范围保留批次外使用，替换本批范围；分片继续累积。未知 key、重复 key、隐式改名和来源关系错误仍被拒绝。
- 仅对同一 F2 节点、完整冻结请求、原回包与拒绝回执完全匹配的旧校验错误重验，避免重新调用模型。Q1 保持原有独立恢复策略。

## 验证

- 第一阶段 48 项、文本执行器 59 项回归通过。覆盖已有基础形象不增殖、显式适用范围、禁止隐式改名与重复声明、保存回包复用及请求漂移拒绝。
- 前端 75 项通过；实际 React 主按钮/单集按钮和第一二阶段显示的 6 项隔离检查通过，网络调用为零。
- 全 10 集真实 F2 保存回包只读重验通过：23 个基础资产、31 个形象条目，重验没有调用 CLI 或写入生产数据。
- Windows release 内嵌界面、IPC、普通桌面项目目录及独立启动验证通过，启动生成请求为零。

## 实际运行验收

同名客户端更新后，从原全剧失败任务点击“继续原流程”。原 F2 保存回包重验采用，没有新建 F2 请求；Q1 约 104 秒完成，基础版本更新并覆盖全部 10 集。第二阶段实际显示 31 项形象，基础目录为 23 个资产身份，包括此前第 7 集目录中没有的女主、前世人物、早期变异生物、室内场景及黑衣人等。

只读核对数据库与界面：源文全文及 SHA 不变，来源版本与基础版本匹配，10 个源集数与已发布基础的集数集合完全一致，阻塞项为零。Q1 按原文增加两处分场边界，未改动原文字句。当前项目没有任何图片或视频生成任务。本次证明全文基础目录到第二阶段交接完成，不代表该新项目的图片、分镜和第四阶段全部制作已经验收。

当前 EXE 已更新，仅保留上一轮备用；原有进行中与归档项目仍在。项目原文、数据库、媒体、授权信息及实际运行记录均未加入 GitHub。
