# 图片并行调度与多层直接来源

## 问题与修复

旧执行器每轮每渠道仅执行一个操作，账户检查、提交、查询和下载共用渠道锁，云端已有结果也会拖住后续提交。派生依赖虽可解锁，仍排在整批基础提交之后。

- 即梦图片拆分为提交 8、查询 8、下载 4 个本地工作槽。拿到任务回执即释放提交槽，云端等待不占槽；这些值不是官方云端并发上限。
- 完成事件唤醒调度器；五秒周期只作兜底。下载并自动采用父图后，立即重新检查其子级。独立根和其它分支同时推进。
- 同批图片共享 15 秒身份检查；并发只触发一次检查，配置、授权或退出使旧结果失效。只读预检短暂失败最多延迟重查两次，不重发已受理或结果未知的生成。
- 保留任务锁、持久提交意图、原任务 ID、账户绑定、媒体验证与版本检查。视频保持原提交边界。

## 多层直接父级

父级可以是任意已登记形象，不限定基础版。西装受伤版引用西装版；连续进化引用实际上一形态。第一阶段同包新形象可声明局部 `localKey`，`preparation.fromKey` 精确引用同资产本包的别名；Rust 先编号再解析，支持乱序，正式记录只保存稳定父级 ID。不新增模型岗位，不以名称或数组顺序猜关系。

明确无父级的 REFERENCE 形象不再自动挂到另一已登记 base，避免早期形态错误参考后期形态。兼容仅限旧记录遗漏来源字段的情况。只选最末级时补排缺图祖先、复用已有祖先图；试稿数量包含实际补排的祖先。循环、缺失、重复身份、缺提示词等问题局部阻断，不能留下永远没有父任务的等待。非法分支的半截祖先不泄漏到生成队列。

编辑窗口显示“直接父形象”，正确解析只有 `sourceVariantId` 的记录；来源缺失或歧义不会被误显示并保存为独立形象。

## 验证边界

验证使用隔离临时项目与模拟渠道，不新建真实图片或视频请求。真实用户原批次仅只读核查，不改写资产来源、旧任务快照或历史结果。模拟并发通过不等于已测量官方服务的真实吞吐量。
