# 项目归档与删除

项目页按“进行中 / 已归档”分组。进行中项目可打开或归档；已归档项目可恢复或删除，不能直接进入制作页。

## 操作范围

- 归档只修改本机项目登记状态，暂停该项目的本地队列、查询、下载和自动备份。已有云端任务不取消。正在执行的本地操作需结束后才能归档，避免中断回执持久化。
- 恢复保留项目身份、数据库和媒体。已有云端任务继续查询原 ID；未知提交仍需核对，不自动重发。尚未提交的原队列按原授权继续执行。
- 删除只允许已归档项目，从本机 `projects.json` 移除登记。原目录中的 SQLite、剧本、图片、视频和任务回执全部保留，不删除凭据或取消云端任务。弹窗显示保留目录。
- 删除不会清理磁盘空间，也不是旧版数据库级联删除的复刻。旧版参考为 `director-web-3008-stage2-images/app/actions.ts` 与 `app/page.tsx`：删除入口在归档区，但服务端没有先归档门禁；本桌面端同时在 UI 和 Rust 校验。

## 状态与并发契约

`ProjectSummary.archivedAt` 非空表示归档；`lifecycleVersion` 作为归档、恢复、删除的乐观锁。旧登记没有这两个字段时按未归档、版本 0 兼容，不迁移项目数据库。

`projects.archive / projects.restore / projects.delete` 必须携带 `projectId / expectedVersion`；状态成功变化后版本递增。重复、过期或不合法请求失败，不能通过直接 IPC 绕过先归档要求。

短生命周期锁协调活动状态检查与项目操作预约；本项目的同步操作和异步 worker 持有独立预约，归档见预约会立即拒绝。原有渠道与任务限流继续生效。共享 OAuth 回调在处理项目时重新核对状态，不推进已归档项目。

项目列表和启动不会因为登记路径缺失而初始化空数据库。打开已有项目前只读核对数据库项目 ID，身份不符则失败。重新启动后只恢复未归档项目；移除登记的目录不会自动重新出现。

归档或删除当前打开项目时，界面返回项目库，清空当前工作区并丢弃旧加载结果。项目列表单独控制读取顺序，避免较早返回的请求覆盖新状态。

## 验证入口

- Rust：`src-tauri/src/project_lifecycle_tests.rs`，通过模拟渠道验证调度和回执保留，不调用真实生成服务。
- 前端：`scripts/verify-project-lifecycle-ui.mjs`，实际组件与 App 回调，隔离示例布局；报告在 `docs/verification/project-lifecycle/ui.json`。
- Windows 原生：`--verify-startup <绝对报告路径>`，专用临时项目完成 Tauri IPC 与 UI 归档、恢复、再次归档、删除；不读取生产项目、不启动生成调度。结果见 `docs/verification/project-lifecycle/native/report.json`。

本轮仅更新独立 release 测试可执行文件，不构建安装包，不关闭正在使用的旧客户端。

门禁在新版 Engine 内生效，不构成新旧进程之间的协调。仍运行的旧 `director-desktop-stage13.exe` 不识别归档状态；在同一项目正式使用归档暂停时，应由用户切换到新版，避免旧版继续按旧规则推进任务。本轮没有替用户关闭旧进程。

原生首次测试报告保留在 `native-first/report.json`：项目已经恢复并写入版本 2，测试探针过早点击仍禁用的分类按钮。最终探针等待列表刷新完成后切换分类，未为此改变产品逻辑。
