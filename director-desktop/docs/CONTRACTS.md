# 核心契约 v1

第一、三阶段初版执行修订见 [STAGE13_REWRITE.md](STAGE13_REWRITE.md)。共用 `desktop-runner/v1` 快照及 `workflow_steps` 检查点；仅领域校验后的 `accepted` 结果进入缓存。发布时原子校验源、基础、资产目录与单元版本；新增资产不被旧回包覆盖。`storyboard-draft/v2` 模型仅给原话区间，Rust 物化；正式 `storyboard-delivery/v1` 与媒体/任务契约保持兼容。`unit_dependencies` 只记录连续前置，受影响后继以新版本标记 `continuityStale`，第四阶段提交前阻断。文字中断保留原回包并明确继续，图片/视频的未知提交仍禁止自动重发。

每个项目独立数据库；Rust 是唯一业务写入者。IPC 唯一入口为 `desktop_request({request:{action,...}})`。列表只返回当前摘要，`assets.get` / `units.get` / `jobs.detail` 按需读取正文与任务证据；编辑时合并完整对象并支持 expectedVersion 乐观冲突检查。

## 身份与不可变快照

身份层使用 `baseAssetId`，每个可制作形象有稳定的行 `id` 和 `variantId`。同名人物、相同显示名称不会合并。单元引用 `{assetId,variantId,role,order,mediaId?}`；`mediaId` 必须等于该形象当前图片。媒体是不可变内容哈希文件，同一原图可被多个形象明确关联，每个形象只有一个当前图片选择。内部 `adoptedMediaId`/`adoptions` 承载当前选择，`candidates` 是精确形象的图片关联集合；界面只展示当前图片及其余图片历史。多参考旧成果仍须明确用途和顺序。

提交链：`unitVersion → assetVersion + variantId → adopted mediaId + sha256 → usage + order`。原文版本、提示词、模型/参数、规则快照、渠道及账户身份键一起保存。`{{asset:形象行ID:variantId}}` 在准备时编译为顺序编号；`@图片N` 不是存储身份。源坐标为 UTF-16 半开区间，原文按程序回读，模型不重抄。

源、形象、当前图片和单元更改只使关联尚未提交的冻结结果失效，已提交任务保持原快照。新生成属于新操作、新任务，不覆盖旧媒体文件；生成成功后只切换当前图片指向，旧图进入历史。

准备包冻结 `prompt/ratio/resolution/duration` 及渠道、模型、单元版本。提交前与当前单元和选择逐项比对，不一致须重新准备；界面显示冻结值，不能用当前设置掩盖旧参数。

第四阶段进入页面或切换渠道时调用 `videos.preflight({provider})`，只检查账户与能力，不保存制作参数、不创建任务、不启动授权。`videos.prepare` / `videos.submit` 一次携带 `unitIds,provider,model,ratio,resolution`；准备在能力校验通过后，用一个短事务保存四项参数并过期受影响的未提交素材包。界面不再提供手动核实模型或独立保存按钮。提交只启用已冻结、身份和版本仍有效的准备任务，不重新配图或隐式准备。

成功能力目录同时保存配置和账户指纹，包含 CLI 文件身份或 API 配置、凭据摘要；仅目录成功时间和核实时间均未超过 15 分钟、指纹匹配时复用。旧缓存没有绑定时自动刷新；刷新失败不更新成功时间。请求发起前冻结指纹，返回时配置或凭据变化则丢弃响应。提交前仍验证当前模型容量、素材哈希、原账户和冻结准备回执；能力变化要求修订或重新准备，不降级参数，也不影响原 ID 的查询与下载。

批次逐单元处理，返回 `videoQueueReport {queuedCount,reusedCount,blockedCount,queued,blocked,preflight}`；全局渠道失败或全部阻塞时报错，局部失败明确列出原因，其余就绪单元可先生成。原任务、未知提交、已提交快照不能借自动检查重新生成。

视频采用要求 `metadataVerified`、真实 motion video 流，且生成任务 `unitVersion` 等于当前单元版本。采用记录保存 `adoptedVideoVersion`；历史采用可以预览，但版本不同必须标明当前版本待重新验收。容器与版本校验不替代画面、声音的人工验收。

## 任务状态

`queued → preparing → ready → submitting → submitted/processing → succeeded → downloading → downloaded`。

- `preparing` 只有上传/准备，上传回执不等于云端生成受理。
- `submitting` 在调用前持久化；收到回执后任务 ID 与回执在短事务中保存。
- 未收到有效回执：`submission_unknown`，不进入自动生成队列。
- `auth_required` 暂停轮询，恢复原账户后查询原 ID。
- `query_failed/download_failed` 独立重试；下载先查询原任务刷新地址。生成成功但地址未返回或未解析、状态未识别时属于查询失败，保留原任务 ID、回执、快照和原始查询响应，不推断过期。
- `result_expired` 仅接受渠道明确的过期状态，保留错误；仍可显式查询原任务核对，重新生成是显式新操作。
- `blocked/waiting_dependency/stale` 只影响关联对象。

查询与下载函数不调用 submit。当前每视频渠道 1 路限制本地渠道操作，一次提交返回后可继续提交，因此不限制云端 running 任务数为 1。是否增加云端在途数上限待用户决定。文本最多全局 4 路，同一阶段/连续集按依赖顺序运行，实际同集不超过 2 路。关闭时终止本地 CLI，无托盘服务。

即梦图片和视频按原任务类型解析结果，忽略封面、缩略图、帮助和输入参考地址；显式任务身份字段必须一致。已可靠落盘的结果不会因后续查询错误被降级。即梦结果下载先使用默认连接；仅连接错误或超时才重试直连，继续验证 HTTPS，HTTP 拒绝不触发此回退。该回退只重试结果 GET，不调用生成。

图片生成全部结果可靠下载完成后，在完成事务中自动选择有序第一张为当前图；其他结果及原当前图保留历史。失败或部分下载不切图。旧资产/形象版本生成结果只进入历史，不自动覆盖新版本形象。图片导入成功直接切为当前图，多文件按导入顺序处理。完成选择一次记录，重复恢复不能撤销用户从历史选回旧图的操作。旧项目缺少当前图时只补选最新可靠、版本有效的已有图片；已有当前图不改变，不用未完成任务的部分结果补选。画风确认仍由用户执行，自动当前图不等于画面验收；视频成品仍须人工采用。

即梦 CLI v1.4.19 的 `user_credit` 返回实际 `user_id`。账户键为 `dreamina:official:user:<SHA-256>`，不保存原 UID 或 token。登录状态与积分采用内存缓存，工作区读取不调用远端；每 60 秒只读刷新，提交和原任务查询前在渠道串行锁中再次核对身份。BH 身份与凭据分别处理，实际鉴权与任务归属由渠道响应确认。同步图片回执的 `sync:requestId` 是内部关联号，没有云端查询能力。

即梦准备前须取得可验证的实际账户身份；账户备注仅作显示。BH/Chrome 的账户标签仍须非空，它是用户对同一账户的稳定声明，token 轮换保持标签，登录另一个账户须更换标签。旧的人工即梦标签任务不得静默改绑为新账户键。

OAuth 执行 `login --headless`，只打开即梦官方 HTTPS 授权页，按服务间隔执行 `login checklogin --device_code=... --poll=0`。设备码不进入工作台存储或界面。手动刷新不能绕过轮询间隔或清除有效流程；过期、拒绝终止流程，限速增加间隔。关闭后流程丢弃，重新连接读取官方现有登录，不恢复设备码。官方 CLI 可能与 SHUO 共用系统用户登录，退出操作有明确确认。

调用前的身份核验不能锁住 SHUO 的外部进程：官方 CLI 没有公开账户 pin 参数，查身份与提交是两条命令。执行任务期间应保持共享官方账户不变；不承诺跨进程切号的原子性。

同身份登录恢复只将有原任务 ID 的 `auth_required` 放回查询状态。无 ID 的鉴权失败转为 `stale`，须显式新操作；`submission_unknown` 在鉴权失败和恢复后始终保留，不能借恢复排队重发。回执、快照、媒体身份不变，恢复变化记录事件并触发备份标记。

## 渠道与成本

适配器实现 capabilities/prepare/submit/query/download，未知提交有独立核对入口。未适配模型拒绝提交。BH 启动及每 15 分钟刷新，鉴权失败失效旧目录；目录中不能确定的计费字段显示未知。估算与实际费用单独保存。

Chrome 依赖用户显式配置的本机 bridge 和扩展。新核心直接访问 bridge，不依赖旧 web 后端。任务身份、原生来源、顺序、哈希和原图数量需成立才入库。

首版模型时长参数要求整秒；`3.0` 保持数学值编译为整数 3，`3.5` 返回修订问题，绝不取整、补空镜或删台词。导入音视频时长需实际容器元数据，未知时长不假填。

## 迁移与备份

旧 SQLite 始终只读；不移入账号、订阅、旧 E0–E5 执行链、多代控制器、Sites 或通用画布。只迁源正文、必要资产/原图及已采用分镜，未确认引用明确阻塞。

项目导出使用 SQLite 一致性备份，包内仅 manifest、database、media；拒绝越界路径、链接、重复路径和非法格式，逐文件核验 SHA-256。缩略图可重建。备份恢复生成副本，保留原项目。

## 文字创作与本地退出修订

storyboard.run 明确接收 episodeIds，校验锁定原文中的有效、非重复选择，再按原文顺序冻结 selection.episodeIds。零现有单元可启动；阶段3无视频参数表单。视频模型为空时使用 storyboard-planning/seedance2.5/v1（planningOnly），4–30 秒、图片30/视频10/音频10/总参考50，作为文字创作规格而非实时渠道可用声明。显式模型须有真实已适配目录；快照、文本输入、结果和单元保留规划规格。第四阶段仍独立准备并核查渠道能力，不能以写作规格跳过预检。

jobs.close_unknown 必须 confirmedNotAccepted=true 且填写 reason；仅原子关闭 submission_unknown 且未取得 taskId 的记录为 closed_by_user。用户核对声明与闭合事件在同一事务保存，所有原始生成证据保留；不调用生成、查询或下载。关闭后新的生成仍须显式新操作，不能作为恢复按钮的副作用。

图片排队不会跳过已有任务后假报全部成功：全部阻塞时报错，局部排队返回 queued/blocked 摘要，关联资产独立处理。界面的 preparing、ready、未知、鉴权暂停、查询/下载失败及依赖等待均保留生成占有状态。

即梦 prepare 保存型号能力与 CLI 文件证明；submit 只做本地完整性校验，直接启动真实生成命令，不重复 version/help。关闭先禁止新 worker/text spawn 并隐藏窗口，终止本地子进程，等待所有 ActiveGuard 内的回执/结果事务结束再退出。网络 API 的在途请求可能等到其超时后才释放；无常驻托盘。
