## 使用方式

第一阶段左侧按集场定位，右侧切换「原文与集场 / 制作方向 / 资产目录 / 待处理」。整理按钮只处理所选集。制作方向单独确认保存，模型提案供比较；重新整理不会清掉已确认方向、已有图片设计或当前图片。

第三阶段左侧按集场选择单元，右侧优先阅读完整提示词，可切换镜表、来源与连续性、版本历史。支持复制全文、手改文字、提出要求重做单元和恢复旧版本。无图片或既有单元也可从锁定原文启动文字创作；视频制作参数仍在第四阶段。手改正文会明确标记镜表尚未同步。连续状态受前置变化影响时提示重做相关单元，保留原有文字。

中断、失败或局部阻塞后，使用「继续原流程」。创作机会需要选择时可以全部取消；继续使用同一已核对计划。输入或规则已经变化的旧流程不会覆盖当前成果，应明确启动新流程。

## Rust 核心边界

- 一个小型持久化执行边界供两阶段共用。工作流冻结输入、所选范围、版本、规则内容与渠道设置；SQLite 保存步骤和成果，不新增 Node 后端或通用插件平台。
- 模型回包先保留为 `received`，程序回读原文并完成领域校验后才能 `accepted`。失败的原回包保留为 `rejected`，不进入完成缓存。有效结果可跨重启复用；缓存身份包括规则、模型、输入、执行程序或文本端点。
- 成果用短事务整体发布，核对原文、制作基础、资产目录和所选单元版本。编辑竞争、目录变化或非法回包不会覆盖用户当前内容。未改内容保存不创建重复版本。
- 原文保留完整正文、说者、声道和 UTF16 区间。发声片段与演法证据分开。新模型协议 `storyboard-draft/v2` 只选择 `lineId + quoteStart/quoteEnd`；Rust 填入实际原话，拒绝改词、跳句、重复区间、乱序和代理字符切分。
- 资产形象范围明确为 `UNRESOLVED / GLOBAL / SCENES`。没有有效集场范围时不给第四阶段猜配图；未绑定形象的状态事实进入局部待处理。
- 整集重做保留旧版本；局部重做自动包含共享台词的必要范围。一对一保留单元身份，拆合明确返回替换集合。末态变化仅使必要后继待核对，已提交视频仍保留原快照。

第一阶段两包为 `1.1.0`，第三阶段三岗为 `2.0.0`。后续 Mac 更新先对照这套源引用、形象身份和单元输出契约，再更新规则与必要转换。旧版本任务保存自己的规则快照，不静默混用新规则。
