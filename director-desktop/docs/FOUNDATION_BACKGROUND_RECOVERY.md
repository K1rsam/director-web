# 第一阶段公共背景引用与恢复

本次修复针对桌面端“分集资料引用跨入未声明的别集”的误判。第一批输入本来包含公共背景与本集正文，返回结果引用了故事简介、人物资料等公共背景；原校验要求每个引用都带本集身份，因此把没有集号的背景误判成了别集。

旧版 `director-web-3008-stage2-images/lib/project-foundation.ts` 的 `buildCallInput` 将 `backgroundSources` 明确作为身份、关系和前情依据，不作为正剧已发生事件。桌面端延续这一边界：分集资料可引用本集行及 `kind=context`、没有集号的公共背景。真正引用别集、未知或重复引用、未定位的非背景行仍会失败。跨集错误显示集名、原文行号和来源 ID。原文、背景分类和集场归属均不因引用而修改。

“继续原流程”只在以下条件全部相同的情况下重新校验本次误拒绝的结果：原流程、节点、请求哈希、完整请求快照、规则、模型、执行器身份和对应的原文字任务。历史错误必须精确为这次旧校验错误，步骤与任务保存结果必须一致。重新校验成功后更新原任务及步骤并保留审计；重新校验仍失败则保留失败。其它拒绝原因继续走原流程，不能当成已接受缓存。

项目创建只保留项目库的“名称＋添加项目”，制作阶段不再重复放置新建栏。统一使用应用默认 `projects` 根目录，各项目保存于独立子目录；现有项目的保存位置保持原样。添加成功进入新项目第一阶段，支持 Enter，失败保留输入。

验证分开记录：

- Rust 回归覆盖公共背景、真实跨集、未定位行和精确恢复边界。
- 私有真实响应回放使用原始 `TextRequest`、锁定源和保存结果；仅将执行器身份换成离线计数程序。原第一批重新验收，第二批主动停止，CLI 调用及新增生成任务均为零。此检查不代表全十集已完成。
- 行内创建和项目归档的真实组件回调回归，浏览器布局检查，以及独立目录中的 Windows 桌面 UI/IPC 验证。

验证不重跑用户的生产项目，不提交模型生成，不构建安装包。修复已发布到固定入口 `src-tauri/target/release/director-desktop.exe`，上一轮备用为 `director-desktop-previous.exe`。
