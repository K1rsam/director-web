# 第一阶段形象定位与原流程恢复

真实十集项目的前七批已通过；第七集只提到未来计划中的计分手表，登记为 UNRESOLVED。第八集腕上积分器实际出现后，同一资产/形象 ID 的展示名由“计分手表待定位形象”细化为“计分手表基础形象”，派生来源始终为空。旧合并校验把展示名和派生关系作为同一个不可变条件，误拒绝了这一正常更新。

Rust 仍按资产 ID 与形象 ID 合并，不按姓名匹配。派生来源改变继续拒绝，并显示具体形象与前后来源。未定位形象有本批场景证据时可获得具体名称与 SCENES 范围，并清除旧的未定位说明。已定位形象的其它名称写法保留既有名称；选集重跑临时清空范围不解锁既有名称。本批必须用自己的引用证明适用场，不能靠合并旧引用补足。原文、主体身份/类型、事实身份、派生循环及局部集场校验保留。

“继续原流程”现在也可以重新校验历史错误精确为“已登记形象的名称/来源关系被静默改写”的原始回包。与公共背景引用修复一样，必须绑定同一流程、节点、完整请求、哈希、规则、模型、执行器和原文字任务；不把任意拒绝结果当作缓存。重新校验仍发现派生来源变化时继续拒绝；通过后更新原任务并保留旧错误审计。前面已通过的步骤复用，后面尚未执行的步骤正常继续。

真实结果验证仅通过 SQLite READ_ONLY 一致读事务，重新构造前八批完整 TextRequest，与原请求逐项相同；复用保存的模型原始事件，前七批物化结果与历史一致，第八批接受。构造第九批后主动停止，零 CLI/API 调用、零新增生成任务、原文及 SHA 不变。这证明前八批恢复通过，不代表第九、十集已经生成。

新项目名称/添加项目输入栏只保留在“所有项目”页。对外仍只交付固定当前版与上一版备用，不构建安装包。
