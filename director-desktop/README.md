# 分镜制作工作台

独立重写的本地四阶段客户端：Tauri 2、React/TypeScript、Rust、SQLite。旧 director-web 与 SHUO 不参与新程序的运行。

## 日常使用

日常只打开 `src-tauri/target/release/director-desktop.exe`。上一轮备用程序固定为同目录的 `director-desktop-previous.exe`。每次更新，新版替换主程序，更新前的主程序转为备用，更早的备用删除；不再按阶段或日期新增对外 EXE。历史验证文档中的测试程序名已退役。

本地更新执行 `npm run desktop:update`，不制作安装包。脚本先完成构建，再以固定名称轮换两份程序；构建失败或程序被占用时不轮换。已验证的内部候选可通过 `scripts/update-client.ps1 -PublishOnly -CandidatePath <路径>` 发布。运行中的程序不强制关闭，项目数据与 CLI 工具不参与清理。安装包等待用户明确通知。

第一、三阶段共用 Rust 持久化步骤、原文回读与事务发布，后续 Mac 规则更新按现有契约接入。布局与用法见 [第一、三阶段重写说明](docs/STAGE13_REWRITE.md)。最新公共背景引用修复与原结果恢复见 [第一阶段恢复说明](docs/FOUNDATION_BACKGROUND_RECOVERY.md)，**222 项核心测试**及独立桌面操作记录见 [验证记录](docs/verification/foundation-scope/integration.json)；没有代用户重跑完整十集。

最新第一阶段改为自动识别明确的集场及故事简介、人物关系、段纲等资料标题，显示结构摘要和分集预览；没有常规整稿行号弹窗。旧导入点一次“重新识别”，只在确有歧义时确认局部片段。新版 **193 项核心测试**、实际原文隔离核查和独立启动证据见 [原文结构说明](docs/SOURCE_STRUCTURE.md)；上段 186 项及真实 CLI 调用是前一次更新的证据。

更新脚本显式开启 Tauri `custom-protocol` 以嵌入界面。release 是经过优化的客户端；debug 用于快速编译与排错。Rust 优化级别与 Tauri 页面加载模式是两个独立设置，缺少生产协议的 release 桌面构建现在会直接失败。独立 exe 不需要启动开发网页或终端。旧 0.1.0 安装包保持原样，正式打包等待通知。创建项目后在「渠道与设置」配置渠道。macOS 尚未实机验收。

本项目已核验的独立即梦 CLI 位于 `tools/dreamina/1.4.19/dreamina.exe`。其发布版本、构建版本、下载来源及帮助分别保存在同目录。渠道能力以运行时帮助或实时目录为准。「渠道与设置 → 即梦账户与积分」支持官方 OAuth 网页连接、状态与积分刷新，以及明确退出。已有官方登录会自动复用；新授权的内部设备码仅保留在工作台 Rust 内存，不写入项目、日志或前端。官方 CLI 自行管理凭据，同一系统用户的 SHUO CLI 可能共享登录，退出前有确认。BH、Chrome、文本 API 密钥使用 Windows Credential Manager / macOS Keychain 存储，不写入项目包。

即梦 `user_credit` 返回实际账户 ID，工作台使用其 SHA-256 身份绑定任务；即梦账户备注不再是必填门槛。提交、查询前重新核对实际身份，只有原账户能恢复已保存任务 ID；恢复不触发生成。BH、Chrome 仍需稳定的账户标签，同账户轮换 token 保持标签不变，换账户须更换标签。Chrome 图片方式需要另行配置兼容的本机 bridge 与扩展，新客户端没有内置完整扩展。

图片与视频的模型、尺寸、比例均从对应类型的能力目录选择。即梦图片 5.0 可用 2K/4K 与 1080P 像素预设，8 种比例按实际宽高编译；1080P 使用官方 2K 档的自定义宽高，16:9 为 1920×1080，不冒充官方分辨率枚举。1K、1.5K 只在支持的型号展示；视频尺寸按型号展示。不兼容的旧参数明确要求重新选择，不静默降级。缺失的积分分类显示未知，不编造为 0。

「第一阶段」导入 UTF-8 文本或 DOCX，确认集场边界后建立制作基础；「第二阶段」设计、少量试稿、确认画风、按依赖批量出图，成功生成或导入后自动显示为当前图片，旧图保留在历史中，可点“使用此图”切回；「第三阶段」按已确认集数生成、阅读、编辑和复制独立分镜文字，无需先配置视频模型；未配置视频模型时冻结版本化写作容量规格，配置过模型时使用其已核实容量，第四阶段提交前必须重新核实渠道能力；「第四阶段」准备和核对素材、查看费用估算、提交、下载、预览并采用逐单元视频。

重新生成只有在原图完整保存后才替换当前图片，失败或部分下载时继续使用旧图。图片历史按精确资产和形象区分，手选旧图后不会因重复查询再次切回新图。图片切换仅过期关联的未提交素材包；已提交视频保留原来的图片快照。旧项目没有当前图时补选最新可靠且版本有效的已有图片，已有当前图保持选择；自动选图不代表人工画质验收。

图片生成前显示逐项和总估算；缺少可靠报价时明确显示未知。视频选择参数后点击「准备所选素材」，自动检查渠道并保存参数，再核对冻结的提示词、图片顺序、时长和费用，点击「生成所选视频」。成功核实且匹配当前渠道配置的能力缓存可复用；过期或配置变化自动刷新，不需要手动核实模型或另存参数。缺图、歧义或参考时长未核实只阻塞关联单元，其余就绪单元可先生成。视频结果要有已核验的运动视频流且匹配当前单元版本才能采用，历史采用结果仍可预览并标明版本。

可以先从旧系统导入图片和已采用分镜，完成明确的形象、集场、来源和图片映射，直接使用第四阶段。旧导入采用只读 SQLite，不调用旧执行器。缺少或歧义的图片不会按姓名猜测。

关闭窗口后先停止本地 CLI，等待任务工作线程保存回执或错误后退出；已经受理的云端任务继续。重新打开只查询已保存的原任务 ID。提交结果未知需要核对，任何恢复操作都不会重发生成。图片页显示准备、提交、查询、下载和未知状态；任务页可绑定已有回执，或在用户确认渠道未受理并填写依据后关闭旧记录，再另行发起新生成。关闭旧记录不代表云端取消。同步图片接口没有云端任务 ID，已保存结果只恢复下载。

## 开发与检查

需要 Node.js、Rust stable；Windows 需要 MSVC Build Tools 与 WebView2，macOS 需要 Xcode Command Line Tools。

```text
npm ci
npm run test:frontend
npm run build
npm run desktop:dev
npm run desktop:update                      # Windows 固定主程序与上一版备用，不制作安装包
npm run desktop:build -- --bundles dmg        # macOS
cargo test --locked --manifest-path src-tauri/Cargo.toml --no-default-features -- --test-threads=1
```

浏览器 `npm run dev` 用于界面开发。默认明确显示未连接核心；`?preview=1` 是只读示例，不能提交或修改生产数据。没有第二套 Node 后端。

Codex CLI 默认使用独立执行目录，关闭宿主配置、AGENTS、Skills 发现与其他工具；保留已有登录，模型和强度由项目设置传入。在「渠道与设置 → 文本执行」可检查原生程序、账户、额度和实际模型、网页登录；新执行会自动预检并保存设置快照。自定义文本供应商使用明确的文本 API 配置，推理策略使用服务默认值。结果与事件仍保存到项目，不依赖临时目录恢复。

核心测试通过模拟渠道验证持久化、素材绑定和恢复，不消耗生成费用。官方 CLI 现场测试默认忽略，需要明确执行并指定 `DIRECTOR_TEST_DREAMINA_PATH`；分别检查帮助或现有登录的只读账户数据。账户测试在独立临时项目中排队验证，绝不启动调度器或提交生成。

## 文件与版本

应用目录保存项目注册表。每个项目有独立 `project.sqlite`、不可变 `media/`、派生 `thumbnails/`、文本调用结果与事件记录。媒体数据库路径相对于项目，哈希在导入、准备和导出时核验。项目包使用一致性 SQLite 备份加原媒体；目标机器需重新配置凭据。

自动备份只备份状态数据库，引用不会被自动清理的原媒体。有变化时每 15 分钟保存；保留最多 48 份状态快照、2 份检查点，合计不超过 2 GiB。恢复创建独立副本，不覆盖正在制作的项目。图片、分镜及生成回执保留版本，不混用提交前后素材。

规则包在 `rules/`，编译入核心并按任务保存版本与 SHA-256。8 个主包与 5 张方法卡覆盖四阶段；源文档中的指令文字只作为资料。
