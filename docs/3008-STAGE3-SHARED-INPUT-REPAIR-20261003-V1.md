# 第三阶段精确复用与局部修复减负 V1

日期：2026-10-03。承接[三版复盘V1](3008-STAGE3-THREE-VERSION-REVIEW-20261003-V1.md)，追加实施记录，不覆盖旧诊断或历史请求。本轮没有真实AI调用、增额、重跑已完成两集、提交或推送。

## 1. 本轮实际修改

- 新生产请求使用 `production-compact-v3`。只对发送视图去重，标准原文、来源映射、资产生产卡和旧请求仍保存完整内容。
- 多张资产卡的 `sourceFacts` 全数组精确一致时，后卡引用本请求第一份数组；各卡ID、版本、采用设计、状态变体和适用范围保持独立。权限、引用、文字或扩展字段不同，都不视为同一事实数组。
- `source.context.continuity.previousSource.nodes` 与独立承接包前源节点完全相同时，只存一份原值。局部请求没有独立承接包时，已知完整节点形状可转为列式表，节点ID、类型、来源范围、行号、顺序全部保留。未知形状或额外字段不裁剪。
- 新局部回执修复使用 `production-feedback-repair-v3`，共享精确相同的schema枚举，不重发多份完整坐标目录。展开后与v2输出约束完全相同；提示、修复证据、允许修改范围和严格合并校验不缩水。
- 没有新的重复就不添加新的复用说明；去重收益不足以抵消说明开销时保留原视图。字符压缩不降低原有创作执行时限。

这是格式与精确复用，不是摘要，不删除表演、摄影、幻想方法卡、台词或有用前情。跨集底稿仍是独立接口，没有混入集内 `acceptedContinuity`。

## 2. 版本与自动执行边界

旧v1/v2普通生产和回执修复版本仍能按冻结内容重建。每次新派单保存自己的传输版本、输入指纹和机器编号映射，恢复旧请求不套用新视图。v1旧修复不被偷偷升级为设计v2语义。

新请求继续使用已落地的design-v2：共用制作约定只能为DESIGN；原文事实、角色说法与解释有各自权限，不能自动把所有解释改为设计。普通、可修复的回执问题在连续执行中自动局部修复后继续主创与整编，不需逐岗点击。

仍保留同一准确问题无进展、返修次数上限、越界修改、未知费用、预算停止、原文过期与硬约束冲突的暂停。没有为“一键到底”开放无限重试，也没有提升每集使用量上限。
