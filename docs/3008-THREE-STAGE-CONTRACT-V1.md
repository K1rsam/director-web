## 2. 协议与版本边界

- 原标准正文：`standard-episode-v1`；当前上游入口`upstream-material-v2`继续沿用其保真编译/覆盖/格式凭据。
- 跨集源底稿：`EPISODE_BOUNDARY_SEED_V1`，包含前源和当前开场text、完整节点、源范围、完整原文hash/长度、selectionKind、故事域未知项。集号相邻不证明故事直连。
- 实际消费上下文：`episode-boundary-v1`，包含seed、明确selected run/selectionRevision、来源兼容的actual、已锁定agreements与chainMode。
- 每次请求：`productionSnapshot.version=production-feedback-v1`；冻结本次材料、边界、开场/结尾责任、出集约定。补充材料只能影响后续请求，不能改写旧fingerprint。
- 传输：新快照可选`production-text-reuse-v1`，仅逐字相等且本次JSON可还原时复用原文；原始业务包和历史仍完整保存。异常/未知形状保留原值，不机械截断。
- 统一工作流：`PRODUCTION_WORKFLOW_V1`；预算：`PRODUCTION_BUDGET_V1`；最小制作约定单独保存，不混用剧情事实。

新任务目录`.storyboard-stage3-v2`，历史`.storyboard-stage3`仅查看和导出，不用新引擎续跑。上游原文件、SQLite、配置与未提交成果保留。备份位置见本轮实施记录。

## 3. 跨集实际使用规则

1. 实际稿只从当前生产链明确选定的上集版本取，不取同目录“最新文件”。必须匹配项目/集、通过机械整编校验、无未解决材料/承接问题，且重新核对本次真正的源文/关键约束。
2. actual由最后的整编单元及其当前采用者共同构造。新修入口的回执不能冒领上集结尾；没有尾态回执时保留可读尾单元但不虚构结构化状态。
3. 没有actual时，继续读可用seed。末场定位失败提供完整标准节点选段；明确需要更早前源时以原文hash/范围验证后`FULL_EPISODE_EXPANSION`，不会只给模型无法读取的路径。
4. DIRECT方可按实际状态承接。TIME_JUMP/LOCATION_CHANGE/FLASHBACK/FANTASY/INDEPENDENT/UNKNOWN不无条件继承持物、伤势、知情与身体状态。
5. 未规定但连续动作必须共用的最小DESIGN约定在前集主创启动前登记，供后集入口和前集尾包；不预写镜头。前集已开始后拒绝用后集预测建立倒逼约定。
6. 一致时只记录核对；自由设计差异定位开场及实际依赖，必要时由原整编delta联修。违反源或锁定约定时保留冲突，不能拿actual自动覆盖硬约束。无进展停止重复付费。
7. 正式连续链导出要求范围内必要承接已核对。只做单集/前集不在范围，可按源底稿完成文字并明确“未与上集实际分镜核对”，不无限等待。结构一致不代表创作品质已验收。

## 4. 第三阶段消费回执

每个模型响应根字段`productionFeedback`：

```ts
{
  relation: 'DIRECT'|'TIME_JUMP'|'LOCATION_CHANGE'|'FLASHBACK'|'FANTASY'|'INDEPENDENT'|'UNKNOWN',
  entry: State[], exit: State[], sharedChoices: State[],
  usedMaterialIds: string[],
  needs: {stage:1|2|3,target:string,purpose:string,packageIds:string[],sourceRefs:string[],blocking:boolean}[],
  conflicts: {key:string,problem:string,sourceRefs:string[]}[]
}
type State = {
  key:string, value:string,
  authority:'SOURCE'|'DESIGN'|'CHARACTER_CLAIM'|'INTERPRETATION',
  sourceRefs:string[]
}
```

- `entry`只写本次真正消费的开场状态；`exit`只允许`touchesEnding=true`的请求报告实际尾态，其他必须空。采用尾态来自尾稿，不来自统筹预测。
- `SOURCE`必须引用本次可读、非guidance/对白的来源；说话者主张和解释不升为世界规则。关键状态比较只用SOURCE/DESIGN。
- 补读节点仅在该反馈中可用`boundary:<episode>:<node.id>`定位，不当成本集可制作sourceRefs，也不能要求补演前情。
- `usedMaterialIds`只能是本次确实发送的材料ID。普通后包不反复读取全剧目录，缺料通过坐标反馈。
- 已知资产的stage2 `target`填精确assetKey；不能靠展示名猜ID。新资产/源文语义冲突保留原坐标交执行者定位。程序补读前源用stage1、target=`PREVIOUS_SOURCE`。
- 补料到达可解除对应“未供给”阻塞；真正消费后再记resolved，旧needs和原回执不删。失败不重新生产整套资料。

## 5. 源文与补充资料的失效范围

硬源守卫包括本集标准正文、对白、已确认方向、知情/关系证据、entryFacts和原已发送上下文证据；真正改动不能借元数据刷新放行。新增但未消费的资料、无关资产更新不改旧请求，也不让全剧重新收费。

资产卡有独立版本；只为已经实际消费且发生变化的材料计算返修范围。采用分组、显式依赖和真实集内acceptedContinuity共同决定扩大范围，不用“一集所有包都失效”代替定位。

服务恢复和已完成任务仍有免费核对路径；查询/恢复核对不自动启动模型。真正补写需要明确推进已登记流程或运行当前任务。

## 6. 统一工作台与预算

入口：项目页“选集制作闭环” → `/projects/<id>/production`。沿用毛玻璃、柔和厚边与错相扫光；只有真实生成状态点亮活动标记，环境质感动效不冒充运行。

每次显式推进一项服务动作；一次动作可含若干既有必要岗位，每次调用都先预约同一账本。先首集主创/整编并留执行者实际质量记录，再推进第二集；不要求用户逐集勾审批。

用户关口只用于全剧方向、指定关键设计、真实源冲突、重要变更和费用。未指定关键设计显示NOT_SPECIFIED，不假称已确认。普通局部补料和程序格式整理不另设审批。

本轮真实对照两侧、上游、失败和返修共享最多40次派单/200万已知Token停止线。原生回执未知立即暂停新付费，在途仍保存；Token线不是账单硬封顶。单次任务接受未知风险不能越过共享预算。后续恢复真实native usage以追加reconciliation消除未知，不覆盖最初UNKNOWN记录；模型正文自报数字不当用量。

## 8. 2026-10-01追加：并发、来源权限与局部供给边界

- **先锁约定，再冻结主创请求**：工作流选择/绑定、约定登记和主创开工共用该工作流的持久互斥关口，锁内只核对选定版本并短写约定，不调用模型。开工后即使没有约定也保存封口记录；后到预测不能新增对前稿的约束。开工前已落选的后集提案归档为superseded，不再约束前稿；封口后不能因切版本重新开放。落选旧任务不能绕过该关口开写。
- **不会复活旧尾稿**：引擎与调度器的正常文档写入都推进修订号；相同选定版本的旧修订晚到时拒收。选择代次及文档修订只用于程序核对，不重复塞进模型正文。
- **前情保留，不冒充硬事实**：`upstream-material-v2`只有与标准节点的集号、源版本、绝对UTF16坐标及全文精确吻合的动作片段可作为SOURCE。对白、群体/分行对白、注记、无类型或坐标不可验证的前情仍可阅读，但不得自证世界规则；已识别角色说法保持CHARACTER_CLAIM。旧legacy/standard接收指纹不改变。
- **第二阶段需求坐标统一**：`needs.stage=2`的`sourceRefs`必须来自本次请求的本集`sourceRows`，锚定受影响资产/场景；前情关系写入purpose，不能用previous/context/boundary编号冒充本集供给坐标。无法定位时向第一/第三阶段请求定位。Schema、提示和接收校验采用同一规则。

- **同一资产可有多个局部候选**：按资产与need分别保存、版本化和投递。补p3的材料不能挤掉p1；同need真正更新只影响消费它的依赖。默认设计与局部候选分开，未知出场不变成全剧必带。旧单need字段兼容；未发布的旧多need合并ID如已有消费记录，须按实际消费范围迁移，不能宣称自动零失效。
- **只停必要范围**：尚未生产的后包缺料不会制造“修复不存在正文”的任务。保持3007集内源顺序，先完成可运行前缀，到首个受阻包停止；整编与跨集修复按真实消费依赖展开。
- **预算显示不夸大**：连续链显示跨阶段共享预算；独立单集只显示它实际绑定的任务预算。界面不再把独立任务描述为全项目已经统一记账。

这些是工程接收与执行保证，不替代真实创作质量核对。实际测试及未完成项另见本轮报告。

## 9. 2026-10-01追加：来源接收不是源稿取舍授权

P1已通读、回包结构有效与源稿归属已获确认是不同状态。普通明确格式由程序处理；同号多段正文若存在真实归属冲突，模型不能通过改标资料、合并或重编号使其自动消失。

`sourceEpisodeBranches`保存原文范围、行号、来源引用及用户待定事项；`sourceBranchDecisions`只由本地受信来源确认操作更新。普通AI归属候选、外部文件同名字段、未知旧记录中的文字说明不构成该权限。派生结构以原文范围保护未决分支，其余明确源集号保留，不因缺少一集让后续整串错位。

免费重验已存回包不改原请求、指纹或FAILED历史，也不得触发新派单。接收器技术待核保留全部证据和完成批次；真正源冲突单独交用户决定。人工确认后的新来源版本仍受既有来源/CAS及下游历史保护约束，不强行让旧第三阶段任务续跑。
