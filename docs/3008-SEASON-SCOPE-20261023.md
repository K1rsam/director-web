# 3008 首季范围与续季对接（本地隔离实现）

2026-10-23：`series-season-scope-v1`，目标120–150分钟，135分钟规划中心。本文件记录实现与离线证据；本轮未加载原3008服务、未调用生产模型/图片、未迁移旧项目、未提交推送。本轮按用户明确批准的AOCI局部例外开展，不宣称全系统认知。

## 第一阶段入口

全剧页“先定首季，再投入制作”可显式启用；已有资产/镜头/单元/详细岗位记录/原生workflow或run的旧项目拒绝转换。旧无模式工程保持原范围，不自动重跑。新TXT导入已有固定P1保真集场时可直接轻读选点；尚需P1的来源先保留分季意图，普通资料任务只允许P1，完成后停在F2前等待季终选择。

`GET/POST /projects/:projectId/season-scope` 为鉴权、同源、CAS入口。`enable` 保存分季意图；`generate` 需要明确费用确认，分批轻读完整原集与非EPISODE背景/附录，详细资产不展开；`recover` 只重验保存回包；`lock` 只接受服务端当前候选ID与明确选择。确认actor/时间由服务器填写；确认字段本身不创造授权。现版不代替用户做无授权的自动季终决定。

原件字节hash、正文hash、源序集场/行绑定分别保存。估时按原声、必要动作/观看、同期重叠与转场的共同时间线累加，不用每集平均或总字数决定集数。候选2–3个，缺合适点须说明不足；只允许连续完整原集尾，不支持场内/半集截断。估时与目标完全不相交的候选不能普通锁定后投入制作。

同源已返回回执按输入和规则hash复用；已返回错误格式保留raw，复用原阶段1接收器零模型重验；未知/在途结果禁止普通费用确认重发，NOT_SENT可明确再次发起。费用未知；界面显示阅读批次、最多调用数量与只读刷新。当前P1结构通读不包含叙事共时估时，不能冒称可替代选点阅读；只有已具相同接收合同的回执才复用。

## 真实生产门

- `loadFoundationInputs`、`loadLightScenes` 在locked季模式按实际源序投影生产供料，全文继续保存在来源和计划包中。F2/Q1前、付费租约及旧直接入口均核季范围。
- 分镜输入/新建/继续、TS派发复核和原生coordinator/workflow都绑定同一scopeHash；队列变更后等待，不重新解释旧冻结请求。季模式遇旧缓存内核（没有`seasonScopeVersion`）在创建/runner前拒绝，源码/HMR不算冷加载。
- 资产设计、补项、提示词、视觉事实、自动化与生图create/claim/handoff/import/use/list核实际本季集场；未来服装/形态不凭母身份或父依赖进入本季。图片候选不自动成为采用。
- `production-delivery` 嵌入范围并输出`season-summary.json`；默认为preview，显式final才要求本季全部原集场有实际正时长镜头、实际季终末场与源序正确，逐镜总秒数7200–9000。原始秒数不舍入后过门，不把15/30秒容器或声窗再加一次。机械通过不替代故事/表演/钩子内容审核。

首批采用分镜及后续队列检查，用实际镜头秒数替换已完成部分估时。预计整体范围完全偏离时在未派发边界等待，不扩季、不催读、不凑秒数。严格例外合同可表达真实授权偏离，并标`exception-authorized`；当前UI不提供把已冻结scope直接升级的例外迁移，须在明确裁决后建立相容新版本，旧稿/请求保留。

## planned / closed 与下一季

锁定时自动保存不可变planned包；`GET /projects/:id/season-scope/handoff` 下载最近记录，`?id=...` 下载指定记录。planned包含源快照/版本、全稿阅读索引、本季范围和下一未制作原集，不能启动下一季。

实际整季完成并核源采用后，制作页“实际闭季与续季对接”先一键载入实际尾镜、资产版本及末集源锚的空尾态表，用结构化字段逐项核对填写，再经`POST .../season-scope/handoff` 明确确认全文采用。空表不虚构状态、钩子或自动采用。服务沿既有真实`readProductionDeliveryFile`复验当前来源、选版、承接、回执和导出字节，只接受原生final整季导出，拒绝preview；再绑定官方native store中的实际run/末单元/末镜、逐镜秒数、稳定资产/设计版本、采用图与候选。尾态要有位置、情绪、知识、持物、伤势、原生未兑现钩子、延后项和无未决冲突。语义仍由实际核源审阅负责。

用户另行启动下一季时，在全剧页启用框输入上季项目及实际closed记录ID。服务器回读自己的不可变closed记录及实际源/run/资产/设计证据；planned或自填hash不可代替。新项目须为同一完整源的兼容副本，从精确下一未制作原集开始、新季号递增。此后每次新季生产继续经原生交付读取器复核上季final manifest与complete正文的真实字节，再核原生run和资产证据；记录或引用导出变化会停止。Prisma日期先规范为持久化JSON语义再hash，保留设计与图像证据。

追加稿是新输入版本，原hash与旧包保留；本版拒绝不同正文/原件版本的自动接续。旧资产总库/图片跨项目不自动迁移：按实际用途建立稳定ID/版本继承映射，候选仍为候选，不因复用自动生图。没有泛用跨库迁移平台或自动生产下一季。

## 加载与边界

实际原生能力由鉴权`storyboard?view=runtime`的`kernel.seasonScopeVersion`回读；现有安全冷加载`requiredCapabilities`可要求该字段。`runtimeCodeIdentity`扫描runtime及本季关键TS/API，覆盖阶段1、资产与续季门。必须由新进程与目标codeIdentity核对，不能仅看网页卡片。

`.platform/platform-boundaries.json`将本轮新增Prisma/本地模块与入口归local_only；原全剧page仍为dual_until_split，不能直接同步Sites。本轮未部署。
