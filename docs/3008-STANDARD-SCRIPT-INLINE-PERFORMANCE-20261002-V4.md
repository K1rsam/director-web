# 行中表演分层与局部成品修订｜V4增量

日期：2026-10-02。追加于标准稿V1、混合正文V3及第三阶段局部恢复V1，不覆盖旧结论。

## 目的与已落地范围

修复 `苏尘：咳咳，（掐着手指）我算算……` 的行中表演仍被计为必须发声的旧缺口。原件、原行、覆盖关系和来源坐标不删不改；新接收包把发声与表演分开，模型不必再猜冒号或从原行重构台词。

此语法处理不调用AI或Jev。没有新增付费审查、整集返修或预算扩张。

## 接收框架

仅实际有明确行中提示时使用 PLAN/SLICE/RECEIPT V4、compiler-v4。其他现有稿按原V1/V2/V3输出。

对白节点可新增独立派生字段：

```json
{
  "performance": {
    "version": "inline-performance-v1",
    "spoken": {"text": "咳咳，我算算……", "parts": ["原件UTF16片段"]},
    "cues": [{"text": "掐着手指", "parts": ["提示正文坐标"], "markerParts": ["含括号坐标"], "spokenOffset": 3}]
  }
}
```

示例的parts为说明占位，实际协议是完整 `{kind,unitId,start,end}`，不是字符串。原节点 `.text` 和 `.textAssembly.parts` 仍完整保留，派生字段不重复取得正文所有权。

第三阶段实际消费：

- `dialogue.quote` 只含准确发声正文；原说者、声道、句首cue不变。
- `dialogue.performanceCues` 携带表演、行内坐标和 `quoteOffset`；offset是发声文字中的UTF16位置，不是秒数。
- 正文原行仍供证据；主创在指定文字位置处理表演，不把所有提示搬到句首，也不能把括号重新读进对白。
- 独立读取器从原件重新计算该层，不仅信任哈希或声明。遗漏、篡改正文/提示/位置、未知嵌套字段，即使重新签包也拒收。保存重载、局部切片和两种模型投影均保留此层。

## 不冒充通用自然语言判断

只识别有界、完整的表演短语，例如苦笑、皱眉、点头、掐着手指及明确的逗号分隔组合。引号内、解释性、嵌套、未闭合或未知括号原样保留。`这叫（苦笑）`、`纸上写着（点头）`、`（摇头）这两个字` 有明确字面用法，不拆。

该有限语法不宣称覆盖任意编剧写法。后续如有新的确定格式，应加来源样例和反例后扩展，不能通过“一律删除括号”换取表面接收成功。
