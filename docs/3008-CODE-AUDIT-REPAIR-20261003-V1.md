## 结论与边界

本轮定位并修复八类代码问题，主要影响本机操作接收、上传资源保护、任务恢复、用量可信性与任务列表隔离。先建立失败复现，再修改实现；独立复核另外发现一条真实 API 适配链的记账缺口，已补修并复核。

保留原稿、来源映射、已有创作结果、冻结协议与旧请求；未改创作方法、模型配置、毛玻璃视觉风格或预算停止线。应用新增 AI 派单为 0，不自动续派、不提交或推送 GitHub。

这是下列代码路径的审计与工程回归，不是全站无 bug、实际模型品质或全剧闭环已经通过的承诺。

## 修复清单

| 编号 | 原因与影响 | 修复与保护 |
| --- | --- | --- |
| B01 | 部分入口拿 Next 内部 `localhost` 地址与浏览器 `127.0.0.1` 比较，合法操作也可能被拒绝；本机 Host 校验不一致 | 共用本机来源校验，按实际 Host 和精确端口核对；拒绝外部来源、错端口及异常 Host，不信任转发头 |
| B02 | 媒体类型检查松散；坏 JSON 被当成业务冲突，返回 409，容易误导恢复操作 | 精确接受 JSON/上传表单；接收格式错误 400、类型错误 415、过大 413，真正业务冲突仍按原规则处理 |
| B03 | 请求完整读入后才检查大小，漏报/谎报长度或中文多字节正文能突破检查；大上传可造成不必要内存负担 | 按实际字节边读边限量，超限取消读取；保留既有业务字段与每文件限制，不截断源文或图片 |
| B04 | JSON 解码可静默替换非法 UTF-8 字节，改变实际收到的文字 | 非法编码拒收，不改字后继续；合法中文、文件名和二进制附件原样通过 |
| B05 | 方向任务恢复可能拿另一次生成的候选当作本次已保存结果 | 有生成绑定的任务必须匹配同一 generation；不混接旧候选、不以恢复为由重发付费调用；旧未绑定协议保持兼容 |
| B06 | 缺少资产检查结果时，默认空列表可能被当作“全部资料已保存” | 必须有实际检查数组才允许恢复完成；检查缺失不冒充成功，既有坐标化补料路径不变 |
| B07 | 原生总量与输入/输出矛盾，或组件非法时仍可能记为已知；API 标成 `null` 后预算层又相加成已知 | 矛盾、明确未知、负数、字符串、小数不能恢复成已知用量；已有正文仍保存，后续新付费派单停止。真正缺失总量时仍支持可靠组件推导，合法 total-only/partial 回执保持兼容 |
| B08 | 当前任务列表只按集筛选，而归档列表按项目筛选，边界不一致 | 当前与历史统一按项目和集过滤；不重写记录，旧任务仍可只读与导出 |

JSON 请求上限：闭环/方向 32 KiB、资产采用 16,000 字节、接收核对 8,000 字节、资产操作 64 KiB。上传总量：图片 11 MiB，原文/保真表单 41 MiB；原有图片 10 MiB、源文件 20 MiB 每文件限制仍在。总量限制覆盖表单开销，不用浏览器声明长度代替实际计数。

核心实现：`lib/local-json-request.ts`、七个接收入口、`runtime/production-workflow.mjs`、`runtime/production-budget.mjs`、`lib/deepseek-api.ts`、`runtime/storyboard-archive.mjs`。

## 尚未以本轮测试证明的事项

1. 大规模并发/长时压力、所有页面与所有第三方环境：本轮不是无限范围扫描，不能宣称不存在其他问题。
2. 真实 AI 产稿品质和实际 Token 节省：本轮未增加调用；这些修复防止误恢复和误记账，不伪造节约数字。
3. 现有对照项目未采用的全剧方向、未绑定实际前后集生产链：不会替用户自动确认方向或随意选旧结尾，不能冒称真实跨集闭环已经验收。
4. 服务长期常驻：本轮只安全重载既有开发服务，不把它改成新的系统常驻服务。

后续新稿测试仍按既有权限、采用、源文变更和费用风险门禁执行。普通格式问题尽量局部处理；真正未知费用、源文冲突或硬约束变化仍停止，不通过取消门禁换取“全自动”。
