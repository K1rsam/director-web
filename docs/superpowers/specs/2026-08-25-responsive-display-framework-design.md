# 全局响应式显示框架设计

## 目标

在不改数据库、业务逻辑和原有视觉风格的前提下，重整所有项目、全剧工作台和新建项目共用的显示框架，使 1080P、2K 与更高分辨率下都具有正常字号、间距和内容利用率。

## 已确认问题

- 顶栏保留了固定顶部空隙，旧深色根背景在页面滚动时露出黑条。
- 侧栏、工作区偏移、内容宽度和卡片尺寸依赖固定像素，宽屏下比例失衡。
- 多数正文、表格和状态文字只有 8–11px，各分辨率下都偏小。
- 全剧场次表使用固定高度与内部纵向滚动，和页面滚动形成双滚动条。

## 方案选择

采用“全局响应式设计变量 + 组件网格重排”。它能保留现有结构，改动集中、风险最低。

未采用的方案：

- 按 1080P、2K 分别写固定断点：短期精确，但中间分辨率容易再次失衡。
- 对整页使用 `zoom` 或 `transform: scale()`：实现最快，但会导致模糊、点击区域和滚动尺寸异常。

## 设计

### 页面框架

- 根页面和应用外壳统一使用浅色背景，顶栏贴合视口顶部，不再保留会露底的空隙。
- 侧栏宽度、工作区偏移、页面边距和模块间距使用统一的流动变量，在合理上下限之间随视口平滑变化。
- 主内容占满可用工作区，只保留阅读所需的最大宽度；卡片使用自适应网格，空间不足时自然换列。

### 字体与控件

- 建立统一字号层级，正文和表格以 14–15px 为基础，辅助文字不低于可读下限。
- 标题、按钮、状态标签、行高和内边距按同一比例系统调整，不做单独的 1080P 补丁。
- 1080P 作为舒适阅读基线；2K 及更高分辨率适度增大，不无限放大。

### 场次结构表

- 保留“展开/收起”行为。
- 展开后移除固定高度和内部纵向滚动，所有行随页面自然展开，只使用整页纵向滚动。
- 表格宽度不足时只出现局部横向滚动，避免压缩列内容。

### 影响范围

- 仅调整共享外壳和页面展示样式，必要时修改场次表的展示类名或说明。
- 不改变登录、D1 数据、项目数据、表单提交、Runner、API 或 CLI 行为。

## 验收

- 所有项目、全剧工作台、新建项目滚动时顶部无黑条。
- 1920×1080 与 2560×1440 下字号清晰、内容比例自然，无大块异常留白或卡片挤压。
- 窄桌面窗口下组件能重排，不发生页面横向溢出；宽表允许自身横向滚动。
- 全剧场次表展开后没有内部纵向滚动条。
- 构建、现有自动检查和关键页面访问通过，再发布到当前公开链接。
