# P1 整集归属覆盖标题：通用合入修复

2026-09-14。修复范围是 P1 输出合入与停止原因，不是替业务测试稿收尾。

## 原因

AI 返回整集正文归属，意图是合并重复集标题并保留已有场界。程序把该范围中的纯集标题、空行也变成正文，制造无场界问题。原来的验收覆盖了分批、原文保护和付费断点，却遗漏了“已存在明确场界 + 重复集标题 + 整集归属赋值”的组合。因此此前通过的检查不能证明这种输入可正常推进。

另一个问题是未发出局部修复请求时也报告修复额度耗尽。现在区分 REPAIR_NOT_DISPATCHED 与 BOUNDED_REPAIR_EXHAUSTED。

## 修复边界

新增 fidelity-p1-ownership.ts，在 P1 校验、物化和最终保存前检查冗余归属。仅当独立原文解析已证明整个范围属于同一集、正文均有明确场界、其余只有纯格式，且不存在来源问题时，移除不增加任何归属信息的整集赋值。原文仍由程序复制。

真实缺场、错集、明确指定场号、资料分类及夹带剧情的标题均不走此修正。旧协议、付费请求指纹和原始响应不变；修正范围及来源版本保存于 ownershipCorrections。不会因此重新购买全文检查。

## 验收

- 隔离数据库模拟旧付费结果已保存但物化错误：本地恢复 P1 COMPLETE，零模型调用，原文、旧快照及已完成批次不变；再次执行无重复工作。
- 正反例覆盖真实缺场、错集、明确场号、剧情混合标题和资料分类。
- 主控对本次现场已保存结果只读验证：35 条误报降为 0，剩余结构阻断 0，5 条有来源的内容疑问保留；原文逐字不变，数据库写入 0，模型调用 0。
- P1 全文/断点/停止回归、请求接线和类型检查通过。新回归纳入 verify:stage1-workflow。

现场项目没有在本轮被重启或改成完成状态；上述只读验证不代表该项目后续 P2–P4 已完成。未承诺任意输入不会失败。后续应继续用不同结构的合成输入覆盖岗位输出与物化组合，不能只验证提示词或单个解析函数。
