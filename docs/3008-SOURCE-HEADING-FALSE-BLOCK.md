# 来源标题误报导致无确认入口

2026-09-14，用户反馈9-14-3显示待确认，却没有确认卡片。

## 根因

该项目真正requiredChoices为0。两类聚合待办实际为：

- 背景中的“第 0 集”“第零集”，被机械事实提取当成用途不明的内容。
- 原稿外层“第 1 集”到“第 30 集”标题，紧接着另有“第一集”等重复标题及已保存正文，外层标题遗留在UNRESOLVED分区。

它们属于程序识别问题，不能让用户逐项确认。此前将其描述成“需要你确认作者资料”不准确。

## 通用修复

- 事实提取把严格整行集标题视为FORMAT；包含剧情叙述的行和真正匿名背景仍保留，正文与坐标不变。
- 来源读取只对经验证的重复标题解除误阻断：该段必须只有集标题，紧邻已有EPISODE分区，集号相同，下一分区首行也有同编号明确标题，且无读取问题指向该段。保留原始分区、全部原文与来源版本，增加格式识别说明，不把正文移到别的集。
- 不通过忽略所有UNRESOLVED、隐藏所有技术问题或伪造用户确认来放行。真正存在内容冲突仍需原有确认流程；通用来源确认体验的改进不以本次误报作为制造人工事项的理由。
