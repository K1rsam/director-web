# 标准剧本增量接收：混合对白与画面字幕 V3

日期：2026-10-01。增补既有标准剧本与三阶段接收协议，不替换旧 V1/V2 说明、回执或任务。对应第三阶段追加事件 S3-E0016。

## 目的与范围

真实《神君》首集存在 OS 与 `【字幕：…】` 共处一个物理行的写法。字幕必须进入实际模型材料，但不能被算进发声台词、OS、VO、表演提示，也不能仅为了消除格式诊断整行归为备注。

本次只扩展有明确来源边界的结构接收，不改剧情、原句、说者、声道、角色知情或创作岗位。原始行与来源映射保留。

## 版本约定

| 层 | 混合正文使用的版本 |
| --- | --- |
| 编译计划 | `STANDARD_SCRIPT_PLAN_V3` |
| 标准切片 | `DIRECTOR_STANDARD_SCRIPT_SLICE_V3` |
| 机械回执 | `STANDARD_SCRIPT_MECHANICAL_RECEIPT_V3` |
| 编译器 | `standard-script-compiler-v3` |

只有出现 `BODY_GROUP` 的正文需要 V3。普通 V1、既有对白组及后置提示 V2 的冻结接收和固定指纹保持兼容。外围 `standard-episode-v1` / `upstream-material-v2` 不因此改成新协议，也不自动迁移旧任务。

## 接收结构与消费位置

- 一个 `BODY_GROUP` 拥有完整连续原文范围，只占一份物理源行；第一子项为 `DIALOGUE`，后续为一个或多个 `ONSCREEN_TEXT`。
- 对白包含准确说者、声道、提示和正文片段；正文只扣除已经验证的字幕标记及其内容，不能自由重写。
- 字幕的标签、正文、括号及分隔符均受来源片段约束。子项与布局合计恰好覆盖源范围，不漏字、不重复；嵌套未知字段也拒收，不能通过重新签摘要绕过。
- 第三阶段从标准节点取得台词，独立得到 `source.onscreenTexts`。每项含 `id`、`rowId`、实际 `line`、`kind`、`text`、`parts`、`sourceIds`；`parts` 是相对于该原始 `row.text` 的 UTF16 半开区间。
- 分包时字幕随对应源行过滤，不广播到其他包。保存再读取时验证字幕目录完整且每项一次。
- 新旧两种模型材料投影均保留字幕。实际请求说明其是画面文字、不是第二份台词；共享原始行仅作证据，不要求重复表演。

例如：`甲OS：他终于来了。【字幕：三年前】` 的台词是“他终于来了。”，画面文字是“三年前”。不能让角色念出“三年前”，也不能据此自动推定角色知道其他字幕披露的身份关系。

## 明确支持与保守阻断

支持未被引号包裹的 `【字幕:…】`、`【字幕：…】`、`【SUBTITLE:…】`（英文大小写不敏感），包括对白前部、中部、尾部、多个字幕及无歧义的续行。引号中的同形文字仍按原台词处理。

空字幕、未闭合或嵌套标记、字幕内部换行、多说者与字幕混合、只有字幕却没有对白，以及未支持的 `[SUBTITLE:…]`、标签空白变体等，保持坐标化 `MIXED_DIALOGUE_ONSCREEN_TEXT` 阻断。不能吞掉字幕、猜测重写，或付费调用单类型判断后整行覆盖。

人工局部核对、AI 建议采用接口与网页共同保护 `BODY_GROUP`；不允许旧的单类型 ACTION/DIALOGUE/guidance 候选覆盖。清晰的已接收混合行不新增逐条人工确认。真正未知的单类型格式仍保留原有核对入口。

同轮免费语法兼容另包括：明确中文姓名贴写 `os/vo`、带时间内外字段的点号场头、明确镜头切换与卡点标记。只处理可证明的格式；不能把英文姓名词尾、金额小数或未知注记强行归类。

## 历史材料传输补充

第一阶段新增 `HISTORICAL_EVIDENCE_TABLE_V1` 紧凑发送视图：共享重复的有效性字段，用表内行索引表达检索锚点，并附解码约定。原始 ID、原句、主体、类型、主张级别、适用范围及坐标完整可还原。

未知/缺失字段、无效枚举、重复 ID、表外锚点等整组原样回退；紧凑结果不更短时也不使用。存储证据不改，角色说法不升级事实，既有已付工作指纹保持。该项只减少重复传输，不以字符下降宣称 Token 或费用同比下降。
