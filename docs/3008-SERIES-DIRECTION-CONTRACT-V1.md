# 全剧创作方向卡 V1

2026-09-28。新增设计及纯数据实现，不覆盖旧标准稿规范；实际代码为`lib/series-direction.ts`。尚未自动分析真实全剧、接入网页确认界面或投递到现第三阶段。

## 目的

让各集共享同一部剧的类型、情绪基调和表达边界，不因本集几个搞笑/打斗/悲伤片段重新定义整剧。稳定的是定位与创作准绳，不是把每集拍成相同结构，更不是固定“喜剧占30%”之类配额。

## 一张卡，分清三个维度

| 字段 | 例子 | 为什么分开 |
| --- | --- | --- |
| settingTags | 都市、架空古代、仙侠 | 世界/时代背景，不直接决定喜怒 |
| mechanismTags | 重生、穿越、循环 | 故事机制，不等于高燃或搞笑 |
| arcTags | 逆袭、隐藏身份、战神身份线 | 主线/类型标签，不能提前泄露角色认知或剧情 |
| primaryTone＋secondaryTones | 主调暧昧拉扯，副调轻喜剧 | 稳定情绪取向；允许复合，而非强选唯一题材 |
| audiencePromise | 让观众期待关系被确认、付出被看见 | 一句核心观看回报，不复述全剧梗概 |
| expressionRules | 喜剧来自人物策略反差；情感靠反应与距离推进 | 最多3条具体表达原则，不写每场镜头 |
| avoidances | 不把创伤当笑料；不把每场都处理成口号式爽点 | 最多3条有项目依据的偏离边界 |
| episodeFlexibility | 允许悲伤、悬疑、低谷；局部起伏不改全剧主调 | 防止全局卡压平单集戏剧变化 |

未知维度保持空/候选，不为凑字段加“重生”“战神”。标签来自同版全剧依据或明确制作方向，不是文件名和单集印象。语义规则属于项目创作判断；程序只校验结构、绑定、覆盖和确认，不证明标签贴得正确。

## 形成与定稿流程

1. 保存全剧来源版本与完整生产集清单。按需要分块读，但必须保留完整覆盖记录；不能只看首集/几处高情绪片段称全剧结论。
2. 收集有出处的类型、关系压力、主要回报与情绪走向证据。Jev可以协助多标签候选/局部信号判断，但概率或词频多数票不直接决定主调。
3. 由策划/生成模型做一次精简的全局综合，或消费用户已明确的方向，得到DRAFT。不要再生成一篇几千字的全剧百科。
4. 用户或已明确获授权的项目负责人对候选定稿，确认记录必须绑定该候选hash和源版本。已确认同一决定不重复追问；本模块不会代替生产系统的登录与权限检查。
5. 后续各集读取同一CONFIRMED卡投影。单集规划可以提出不适用/冲突意见，但不能自动改卡；实质方向修改产生新revision、清旧确认，并保留旧卡与受影响清单。

默认只向模型投递精简brief（目标约200–350中文字符，程序上限600 Unicode字符）；来源、覆盖、确认人和hash留在服务端记录，不重复塞入每个岗位的提示词。超过预算明确返修精简，不静默截断关键边界。

## 与单集合作

输入分三层：

- **固定全剧卡**：我们在做什么类型/调性的剧，观众持续期待什么。
- **本集源文与必要证据**：这一集实际发生什么，哪些事实、台词、知情与揭示时点不能变。
- **本集表现方案**：此集可以是缓冲、转折、兑现或低谷；其表演、机位、节奏由第三阶段形成。

全剧主调不是剧情事实的替代物。暧昧剧可以有严肃死亡场，轻喜剧可以有真切悲伤；逆袭标签不能凭空补获胜，战神标签不能提前给所有角色知情。发现定位与源文真正冲突时返回范围明确的问题，不靠局部场景偷偷切换整剧类型。

## 当前代码接口

```ts
createSeriesDirectionDraft(input, sourceContext)
confirmSeriesDirection(draft, sourceContext, approval)
reviseSeriesDirection(previous, nextInput, sourceContext)
projectSeriesDirection(confirmedCard, sourceContext, episodeId, approval)
```

`sourceContext`由受信源存储提供projectId、sourceVersion、episodeIds、evidenceIds；模型不得自行编造覆盖清单。`approval`由受信确认记录提供id、projectId、sourceVersion、draftHash、actorId、confirmedAt，不能直接信浏览器提交的“已确认”。

投影只返回schemaVersion/id/revision/sourceVersion/cardHash/brief。不同episodeId得到相同brief和cardHash；未确认、缺完整覆盖、证据未知、源变更、确认不匹配或正文被改，都不可作为已锁定全剧方向投递。修订返回新DRAFT，不覆盖旧卡。

**命名注意：** 此处sourceVersion指该卡所依据的全剧源快照；与第三阶段现有“本集源＋上下文”的综合指纹不是同一概念。接入时显式映射globalSourceVersion、episodeSourceVersion和directionHash，不能因字段都叫sourceVersion就直接混比。

## 已实现与未实现

- 已实现：纯数据草稿/确认/修订/投影，版本与完整覆盖检查、不可变对象、确认hash绑定、600字符上限及离线反例。
- 未实现：全剧语义候选自动生产、可信DB确认存取、网页编辑/定稿动作、当前第三阶段适配。纯函数收到一份清单不等于证明AI真正理解了全剧。
- 示例采用合成题材，不代表已经给“灵气”贴上重生/暧昧等标签。本轮不跑真实70集分析或重写原剧本。

后续实质字段/行为调整另增V1.1/V2与迁移说明；旧文件保留，第三阶段影响写入追加台账。
