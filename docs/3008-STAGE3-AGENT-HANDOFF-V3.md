# 第三阶段上游消费补充 V3

2026-09-29。追加于V1、V2，不覆盖它们；本次仅本地3008，未来第三阶段新版仍以用户通知的仓库版本重新对齐。

## 本次变化与目的

1. 新稿的空白整行由共用接收程序删除，原附件、原始读取文本及UTF16删除范围保留。不让模型重抄正文，也不批量迁移旧库。
2. 新路径扩充明确说者头、编号群体、后置表演提示、OS/VO、人物表中的形态名、明确共同对白及括号内冒号。第三阶段继续直读标准包，不从显示文本重新猜说者。
3. 模型发送视图启用`production-context-v2`，去掉能由本次实际材料证明重复的内容。原包和旧任务回执保持本地可审计。

## 必须区分的三个层次

- **原件/来源证据**：全文、原行号、UTF16索引与回执。不得为了省Token改写或丢弃。
- **按集标准包**：正文、对白分型、辅助备注、相关事实/资产、必要前情、已确认全剧方向、有效采用设计。供程序验证，不整份照搬给模型。
- **单次模型视图**：当前工作包真正需要的源行、完整对白、情绪契约和有效辅助材料。只能在这一层删已证实的重复信息。

新导入使用`SCRIPT_BLANK_LINES_V1`清洗标记；旧未标记收据仍按旧规则验证。清洗后的行号不能冒充原件行号；两套坐标通过来源映射核对。

## 新模型投影的接收约定

规则快照`modelProjectionVersion=production-context-v2`仅用于新快照。`retrieval-facts-v1`及无标记旧快照仍走旧投影，固定请求hash回归保留。旧`legacy`/`standard-episode-v1`继续冻结旧语法；不能用当前标准化结果静默重算旧任务。

`retrievalFacts`可为原对象、旧的无损`STORYBOARD_FACT_TABLE_V1`，或更紧凑的`PRODUCTION_FACT_TABLE_V2`。表格必须按`columns`解释，不假定首列永远是id；`groups`仍按行索引引用，语义不因压缩而变。

允许省略：

- 本次实际发送的标准源行已完整覆盖的机械事实索引。仅“完整存档有这句”不够，局部主创未携带的原句对应索引仍保留。
- 背景`statement`：仅其`contextRef/contextRefs`全部存在且拼回文本逐字一致；引用缺失、冲突或不匹配时保留正文。
- 配音容量参照中的原句：仅与本次对白id、quote均相同；不同参照和额外表达信息保留。
- 无入口事实引用的空白行、对应空白引用、空列表和已知审计字段。不得删除正常原句、表演、声道、时间预算或情绪内容。

未知字段、未知嵌套证据、非常规有效期/坐标/版本数据走无损回退，保留原id及引用。不能把“字段名认识”当作内部数据形状也已知。

## 无Jev时的确定性工作仍然成立

明确对白识别、去空行、来源映射、完整覆盖/回读、编号与引用检查都由程序完成，不依赖Jev或生成模型。`P1Review.method=PROGRAM`如实表示程序验证，不显示为AI全文检查。

只有未解决的局部歧义进入已有辅助判断接口，且受明确调用、来源范围、权限、版本、费用未知及候选不自动采纳约束。接口见`3008-JUDGMENT-PROVIDER-INTERFACE-V2.md`，本轮未改接口或新增隐式回退。

## 留给新版第三阶段的核对清单

- 保留V2的全剧方向、采用设计、guidance与事实分层，不把主调强迫成每集同一情绪结构。
- 采用标准对白目录，不再把连续性备注、表演提示或台词内冒号识别成新说者。
- 支持按`columns`读取紧凑事实表；缺省机械索引回查已给源行，而非要求上游再次生成长资料。
- 对真实缺失只发坐标化、局部需求：身份/归属回第一阶段，视觉设计回第二阶段，创作表达留第三阶段。
- 新版更换协议/快照时另记实现事件，旧已付回包与恢复路径不能被新默认值覆盖。

工程证据、真实70集只读扫描边界及完整请求减负数据见[本轮报告V4](3008-UPSTREAM-CLEANUP-20260929-V4.md)。它们不代表真实模型创作质量或用户新稿验收。
