# 第一阶段完成状态收口

## 原因

旧逻辑即使 documentReady=true，仍因历史任务状态为 PARTIAL/STOPPED/WAITING_USER 而显示未完成。于是资料已满足交接条件、剩余事项为零，用户仍看到继续完成和P4待整理。

## 约定

P4属于第一阶段，负责按集交接，不等待第二阶段接入。当前交付是否完成应由内容、必要选择、当前版本资产登记及活动请求共同决定；历史任务记录仅保留执行事实，不能永久否决已经就绪的交付。

读取状态不修改历史记录、不提交任务、不触发AI。正常执行器在登记成功后按实际内容条件收口，不能依赖界面的运行中状态反过来判断是否完成。资料就绪但尚缺本地登记时不应重购已经完成的岗位。

## 验收要求

覆盖已就绪的历史暂停/停止/等待状态、真实未决、活动请求、未知调用、当前版本资产登记不完整，以及只需本地登记的零模型收口。界面P4和按钮使用相同完成状态。

## 本轮复检

主控复跑 verify:stage1-workflow 全部通过（含完成态隔离数据库测试、40项界面服务端渲染检查），verify-offline-final-gates 的 failures 为空，tsc --noEmit 通过。正式导入链路产生的资料仅执行本地登记便可收口，测试确认模型调用为零。

本轮没有操作用户测试项目、启动真实模型任务或重启服务；以上属于隔离回归与界面渲染验证，不代表对任意新剧本内容质量或实时浏览器状态的保证。
