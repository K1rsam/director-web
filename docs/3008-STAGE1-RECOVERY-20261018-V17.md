# 第一阶段同身份补充接收与已返回结果恢复 V17

## 目标与故障证据

本次补的是通用接收及恢复能力，不是为某个剧名、集数或资产写特判。第一阶段不应因为同一已登记资产的不同场次使用补充，把整批已付结果卡死；接收安全时直接继续原任务，不能靠第三方删记录、改状态或重买整批。

现场原任务的 109–136 批已经有完整返回，但因 `assets.key: 不得重复` 留在 108/150。70 条原声明中两条显式引用同一已登记群像 key，名称、类型及制作方式一致，场号和说明不同。直接删任一条会丢资料。旧精确记录去重没有误删，旧付费门也正确阻止了盲目重购；缺口在语义接收及网页恢复入口。

私人源文、提示词和原始回包只保留在忽略提交的本机证据目录，不附入工程文档。

## 通用行为

### F2 是追加使用，不是 Q1 替换

- 仅对模型 F2 的**显式已登记相同 key**进行归并。新候选仍按原行生成独立身份，不因同名、别名相似或关键词就认定同一实体。
- 每条原声明先独立校验来源范围。仅当名称、类型、角色及制作方式/来源一致时，合并使用集号、场号、别名和状态；关系说明、状态说明及制作说明全部保留。
- 不同身份事实或制作方式冲突仍拒绝，报后一个对象及具体字段坐标，交给既有有界局部修复，不做“保留第一条/最后一条”。未知 key、越界来源、子状态父范围问题继续保护。
- Q1 局部替换、可信 canonical 快照唯一性、源文、专业创作规则及质量核对不变。没有把所有重复输出当成安全，也没有静默认领未证实的新身份。

正常新任务收到这类安全补充后自动写入并继续，不需要用户逐批点击恢复。

### 原回包限定恢复

新增正式 `recoverSavedFoundationDelivery` 和鉴权网页操作“恢复已返回结果（零模型）”。它沿原任务、当前来源/上下文及语义指纹复验已确认返回，保存可接收内容；下一步没有现存回包就正常让出，**不创建下一条模型请求**，不以空回执冒充零费用。

服务端仍核项目权限、expectedState CAS、任务 lease、来源和上下文；运行中、未知结果、用户 STOPPED 或已完成任务不自动续启。重复操作不重复采用旧版本。原请求、原失败状态和模型返回不改写，新 FoundationDocument 追加引用原 run。

免费恢复与后续正常创作明确分开：恢复本身不花一次模型调用；未制作批次和最终资料核对仍是原任务正常调用，不能用“修复免费”掩盖生产用量。

## 实机验证

原项目在已登录的现有 Chrome 页面使用新增正式入口，从 108/150 恢复至 136/150。仍是同一任务，11 次原请求、0 修正调用不变；原 11 条 PipelineRun、所有原集源文及旧不可变快照 hash 保持一致。70 条原声明接收为 69 个身份，重复群像的 33 个场号引用及两段说明全部保留，没有删除原回包。

本轮修复没有新增生产测试调用、重启服务、取消模型或启动已完成项目。2274 份既有洪荒保护文件逐项 hash 不变。新增网页代码由现有 Next 开发服务 HMR 加载；新执行者使用当前源码，不能把 HMR 本身当作生产成功。

用户随后明确批准“继续原任务剩余部分”。原网页“继续完成”只接 137–150 及原 Q1 核对；这部分与免费恢复分列，后续真实结果见本机快照，不能提前宣称第一阶段或分镜质量验收完成。

## R1：最终核对暴露的普通源格式接收缺口

原 Q1 随后自然完成全 150 集核对和一次有界局部内容修正，因源语法诊断保护性暂停；不是又少生产一批。当前任务累计 18 次真实请求、其中修正 2 次；相对免费恢复时的 11 次，用户另行批准的剩余生产实际新增 7 次，包括 F2 一次未知 key 的局部格式修正及 Q1 一次原范围修正。没有把修正藏成免费调用，也没有重发 109–136 已付批次。

六类共用语法缺口已先 RED 后 GREEN：

- 士卒/军士/谋士/斥候/密探等职业、编号及群体说者保留完整源标签，不靠资产同名猜身份，不生成别名。

- 有独立人物依据、完整“听到/听见…，气得/气的又喷/吐出血”肢体结果的整行可分为动作；引用、疑问、否定和含混续句继续保护。
- 仅**紧邻、完全相同且第一头没有任何发言**的两次说者头可作重复版式；重复的说者/声道/提示全部原字节留在 layout，第二头仍完整校验。编译器和第三阶段独立接收器都核精确重复、源字段范围及全字符覆盖；不同人、不同声道、有前一句发言或隐藏正文不能借此放行。
