## 根因与修复

P1 按原文字数分批，最终发送预算计算的是系统提示、完整请求 JSON 和预计输出预留。二者并非相同口径：原文块不长，不代表携带的诊断信息也小。

第二批把相同的 `SCENE_BOUNDARY_UNCONFIRMED` 诊断按块重复发送；相同 `code/message` 被重复写入 1066 条 `issues`，成为请求膨胀的主要来源。

[`lib/fidelity-p1-review.ts`](../lib/fidelity-p1-review.ts) 在传输投影中合并相同 `code/message`，对其 `sectionKeys` 取并集。不同问题说明、不同代码、未定位的空范围以及未知附加字段均保留。原文块、块编号、分批边界和本地范围校验保持不变；不截断剧本，不调小全局批次，也不提高预算。

旧 `FULL_STRUCTURE_V1` 请求、旧 `FULL_STRUCTURE_BLOCKS_V1` 日志和新投影使用同一规范化规则计算付费工作指纹。传输变紧凑不会被当成一份新的已付费工作；第一批已保存的 checkpoint 保持有效。
