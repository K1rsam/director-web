# 给第三阶段优化Agent：上游供给与改进方向 V1

2026-09-28。可独立转交。用户正在另行优化第三阶段，**收到用户指定的新版仓库基线后再适配**，不要按本文件自动回退模型/输出格式、重跑旧任务或更新GitHub。

## 1. 目标与不可混淆的状态

整个链路应当是：第一阶段稳定洗本与有依据的理解 → 第二阶段实际采用的视觉设计 → 第三阶段在同一全剧定位下做单集创作。不是三个阶段各自重写一次剧本。

当前3008已拥有新版分镜内核与“情绪统筹→完整主创→统一整编”界面；旧1.5显示已改为第二阶段。下述标准化与全剧卡基础代码先作离线切片，并不表示生产网页已读到这些新输入。

| 内容 | 当前状态 | 接手时怎么判断 |
| --- | --- | --- |
| 原文、集场、目录、检索事实、决定、后续事项 | 现reader/adapter已有传递 | 以新版真实代码为准，不重复造摘要 |
| 标准稿目标协议DIRECTOR_STANDARD_SCRIPT_V1 | 规范与示例已写，完整生产接线未做 | 别把设计当已发布API |
| DIRECTOR_STANDARD_SCRIPT_SLICE_V1 | 首个编译器基础切片 | 只编译明确源片段计划；不含完整集场/实体树，semantic=NOT_RUN，不可直接派单 |
| 全剧创作方向卡 | 版本/确认/精简投影纯模块 | 自动全剧理解、DB/网页确认与第三阶段投递仍待接线 |
| Jev边界 | provider中立接口与有限调用适配 | 判断不是事实证明；真实剧本准确率未校准，不能直接全自动放行 |
| 第二阶段采用设计/真实图片 | 现有提示词/视觉事实可复用，但跨阶段采用投影未完整接通 | READY文字不等于图片已生成、已采用或视觉验收 |

## 2. 每一集应收到的最小完整资料

### A. 全剧公共方向（各集同版）

提供一张精简卡：背景标签、故事机制、身份/主线标签、主调/副调、一句观众回报、最多3条表达原则和3条偏离边界、单集弹性。

例如“都市／重生／逆袭”和“暧昧为主、轻喜剧为辅”属于不同维度，不能把重生等同搞笑，也不能因某集几场打斗改成战斗番。保持创作标准，不强制所有集使用相同起承转合或固定情绪比例。

目标约200–350中文字符，当前程序上限600 Unicode字符。模型只需brief；确认人、覆盖证据、hash及版本存服务端。全剧卡要基于完整来源范围并定稿，不靠抽看一集推断。卡片改变走新revision和重新确认；单集Agent不得写回全局方向。

当全剧卡与本集局部感受不同，先尊重本集真实情节，在全剧范围内安排局部起伏。若确有矛盾，报告冲突与源位置，不以情绪标签改变台词、胜负、身份或提前揭露。

### B. 本次制作正文

完整本集源文，稳定源位置，明确的场次及正文节点类型：对白、动作、声效、画面文字。对白另外有说者/原称谓、声道、cue与精确片段组装规则。

不要重新按冒号、空行、△判断已标准化节点。文本内部的双冒号、引号、真正换行与字面量反斜杠+n必须原样保存。当前编译切片不支持一条物理行拆多个独立节点，遇到该情况属于待扩展语义/计划能力，不能丢半句来换通过。

### C. 可引用的事实与上下文

必要的更早源片段、作者资料、持物/伤态/服装状态的起止依据、人物关系和知情范围、空间条件。每项有来源域、版本和位置；原文证据、人物主张、AI解释分别标记。

上下文不参与“必须拍出来”的本集覆盖；不能把前情又补拍一次。入口事实只能由真实证据支持，不用创作建议自证事实。旧实现中检索facts虽然可读，却未全部进入可校验contextRows，新版需核是否已补齐。

### D. 有价值的辅助意见

CONTINUITY、EMOTION_CLUE、RELATIONSHIP_CONTEXT、KNOWLEDGE_REVEAL、SPACE_CONSTRAINT、CREATIVE_GUIDANCE分别投递，明确scope、origin与authority。

“导演处理”“连续性备注”“情绪线索”是帮助理解与创作的内容，不因旧解析器不认识而删除，更不能被当成说话人。用户确认要求、来源事实、AI建议优先级不同。建议可采用/调整/说明不适用，不能为了消耗资料而把每条意见强塞进作品。

### E. 第二阶段实际采用的视觉依据

主体和变体ID、采用设计/参考版本、服装/外观/道具状态、场景母空间/必要视图/固定布局与光源、素材可用性。只给本集有关设计约束，不广播全部长生图提示词。

空缺如实标记。没有图片可以先做文字创作，但不得声称已绑定图片；素材图主视角也不是每镜唯一机位。第三阶段确需新视图、接触细节或道具状态时，输出局部素材需求回第二阶段，不擅自改源事实或触发全库重做。

### F. 接收门与版本

结构可解析、源覆盖/保真已核、证据可定位、当前范围必要事实无阻断；普通提醒/可选设计/暂未出图分别处理。服务不可读或模型不可用不能冒充空资料成功。包的“VALIDATED”字符串不是授权或证明，需由程序绑定真实来源、回执及对象版本验证。

## 3. 三个岗位如何使用同一资料

| 岗位 | 主要使用 | 不应做 |
| --- | --- | --- |
| 情绪统筹 | 全剧卡＋本集正文＋关系/知情/情绪与连续性证据，形成当前完整事件的观看回报 | 根据局部片段重定全剧类型、把题材标签当剧情事实 |
| 完整主创 | 同版全剧卡、事件方案、相关事实与采用美术，联合表演/摄影/光影/声音 | 再写全剧分析，改变原词或身份，按参考图机位僵化拍摄 |
| 统一整编 | 同版方向和输入，查情绪/信息/动作/素材衔接及整体可用性 | 机械统一镜数/时长，回抄全部上游，替用户宣布成片已验收 |

输入裁剪按实际工作包，但保留它的依赖证据与适用意见。缺重要材料由装配器补取，不能指望一个禁止工具的执行模型按文件路径自行回查。

## 4. 版本接入原则

- 当前V4输入适配、输出schema和规则快照是不同版本面；新标准输入不必强行改变新第三阶段已有输出设计。
- 显式区分全剧原稿版本、单集正文版本、资料包版本、全剧方向hash与采用设计版本，不按同名sourceVersion字段盲比。
- 全剧卡和语义意见有变化时新建可追溯输入快照，旧任务保持旧输入/规则/回执。新版上线不能把旧付费任务自动判失效重买。
- Jev只是上游可替换的判断提供者。第三阶段应依赖标准正文和证据含义，而不是依赖某个模型名称、概率数值或供应商。
- 旧内部owner=STAGE2曾表示分镜后续事项，不要因为现在资产阶段叫第二阶段就把这些旧记录误路由。

## 5. 优先改进与验收清单

1. 标准节点直读；对白目录的验证不再强依赖旧冒号正则重新抽取。
2. 本集覆盖、上下文证据与辅助建议分域；备注不变对白，未来信息不提前揭露。
3. 三岗共享同版全剧短卡与采用设计，投递ID/版本可核对。
4. 结构、机械保真、语义可用与素材状态分项验收，错误发生在付费派单前。
5. 同源跨写法、换行、双冒号、OS/VO、无△动作、群体、闪回/戏中戏、持物/伤态与缺素材回归。
6. 用少量同源对照比较错人、错状态、情绪偏移、重复信息、无效返修和实际可拍性；JSON正确、工程通过不等于好分镜。

不要求按本文件恢复旧E0–E5、特定多岗组织、固定镜数、情绪比例或上一轮被用户否定的样稿。用户最新第三阶段设计优先，只核交接语义和安全边界是否保留。
