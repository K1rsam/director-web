# 3008 岗位执行与交接重构

日期：2026-09-14。分支：handoff/3008-stage1-20260912。

## 交付目标

测试稿只用于复现流程缺陷、验证通用修复。发布验收对象是岗位输入、实际岗位规则、修改交付、程序合入及内部纠错链，不是某个业务项目显示 COMPLETE。此次不修改或恢复任何已有业务项目。

## 原因与改动

1. **本岗输出接收失败，后续修复根本进不去。** 旧接收器先拒绝整包；修复只接受缺少原文依据的机械叶字段，很多错误永久挡在工作流外。现在保留完整候选和原始响应，本岗继续携带相同规则，只接收程序定位的错误对象、相关原文、场次、原资料及决定。模型只返回允许路径的补丁，脚本合入已保存候选，再执行完整校验。正确字段不重写，下一岗接收修正后的成果。
2. **限制写入靠整包事后拒绝。** 明确用户决定的修改先按对象、字段、集场投影；无权普通字段恢复原值，无效空修改剔除，再完整验收。未知身份、删除归并、来源依赖不明不能借此越权。被裁掉全部实际修改的事项不能伪造完成；未受裁剪影响的既有无改动回执沿用原协议。
3. **岗位职责分散且与实际请求容易脱节。** 修改真实加载的 F2/Q1 岗位规则、P1 实际常量和任务说明，要求直接完成职责内修正，内部返修沿用本岗判断；技术错误不得变成用户选择题。增加经过实际规则加载器和 CLI/API 发送适配层的测试，证明不是只修改说明文档。
4. **重复记录与重复读取。** 完全相同的重复资产/场修改由程序消除；冲突内容不假合并。局部修复只发相关来源，不发整包结果、其它集原文或全剧历史。原始响应仍留存，补丁中断可本地恢复；完成项目不再请求模型。

## 执行责任

| 环节 | 责任与输出 |
| --- | --- |
| P1 | 阅读原文，交归属修正计划；程序复制原文物化，台词、剧情和动作不改写 |
| P2 | 程序物化集场和来源索引，不再次全文 AI 检查 |
| P3 的 F2 | 提取必要素材、定位证据、给制作依据，交可用目录 |
| P3 的 Q1 | 在目录上直接修改遗漏和错误，交增量修改；已满足可不改，不制造评审循环 |
| 同岗内部返修 | 原岗位规则 + 错误位置 + 必要证据，只交允许路径补丁 |
| P4 | 按实际集场分发原文、素材、决定和后续事项，不广播局部决定 |

程序保真、真实引用、用户授权仍为约束。岗位可以改善资料理解，不能修改不可变原剧本。范围不明时不能凭空扩大授权。

## 验收入口

- `npm run verify:stage1-workflow`：隔离数据库与故障注入，不读取业务样本，不调用模型。
- `node --env-file=.env --import tsx scripts/verify-stage1-roles-live.ts --review-source`：新建隔离库，用合成稿验证真实 GPT6-low 岗位链。
- 加 `--inject-fault`：在独立测试中向已返回 F2 数据注入非法类型，检查真实岗位能否只修该字段继续推进。真实模型原响应与故障注入证据分开保存。

真实验证脚本有总调用上限，日志和隔离数据库位于忽略的 runtime-3008/live-evidence。无业务数据库、账号凭据或实际剧本上传。Mac 重新安装依赖并配置 CLI；Windows 临时路径不作为部署依赖。

## 验收边界

隔离控制器用例覆盖不同换行及说话人格式、F2 类型/身份键错误、Q1 场次/字段错误、已付费补丁中断恢复、局部写入和原文保留、已完成不重复读取，以及越权补丁反例。调用层覆盖 UNKNOWN、预算、无改善、越权和证据版本变化；它们不应靠无限请求掩盖。

一次局部修复仍有持久预算；错误不可定位、输入损坏、网络结果未知或修复仍不成立时不假报完成。这是剩余技术故障，不转成创作选择。当前尚未对任意错误实现自动修复，不能把有限案例通过写成“所有剧本均可发布”。真实语义质量与规模性能必须持续用独立回归集评估。

## 本轮实际结果与发现

- 主控复跑：实际岗位加载/发送适配、局部纠错调用层12项、真实controller隔离6场景、字段投影、原调用层35项、旧轻量controller、旧交付controller、来源解析及类型检查通过。限定决定controller15项由low子代理复跑，主控另验投影与接收顺序。
- 真实GPT6-low正常链：新建两集合成稿，P1/F2/Q1各一次，共3次，COMPLETE，原文不变；这只证明实际岗位接通和短流程，不等于长篇质量验收。
- 真实故障注入：原F2响应另存后，测试适配器注入非法type。原岗收到3982字符请求（原F2请求7451字符），仅返回`assets.0.type = CH`，Q1继续。全部为GPT6-low，4次请求。
- 后一测试同时抓到程序误把“需实体形象；不据此降为纯声音”当作声音专用。已修声明判断，保留真正AUDIO/肯定声音专用的冲突反例；派生诊断读取时重新按当前原文和规则验证，不以历史错误阻断。使用同一隔离证据进行零新增调用回归后COMPLETE，原文和已有请求不变。没有为了让测试通过改动模型正确的原说明。
- 本机证据目录：`runtime-3008/live-evidence/2026-09-14T08-26-07-430Z`及`2026-09-14T08-28-16-090Z`，后者包含最初失败与post-rule-regression，二者都保留；不上传仓库。
- 本轮无业务项目修复，无服务重启，无main合并，无Sites发布。岗位规则更新会更新方法版本提示，已有成果不会仅因规则文字改变强制重跑。
