# P1编号接收、字段诊断与免费恢复 · 2026-10-21

本修复位于通用P1接收及已有资料恢复入口，不含项目名、集号映射表或指定回包补丁，不改变原文、分集事实、生产模型、预算或授权。仅格式接收通过不等于全剧结构、身份语义或作品验收。

## 统一编号契约

`baseline.episodeNumber`保留源集号标签及旧请求字节，模型说明明确它可能使用中文数字。输出优先JSON整数；接收器还允许规范十进制字符串和无歧义中文数字，派生归属统一为数字。数字规则同时适用于集号与场号，集号从0、场号从1开始。

- `十九`→19、`一百零二`→102、`二零二六`→2026；独立`两`及明确百/千位同义用法可接收。
- 不猜`一百二`、`一两/两三`、带标题的整句、空白、前导零、小数、指数、零场号或安全整数溢出。
- 不借兼容补造缺失集号、场界、原文块或身份。原有范围/源版本/场界校验仍执行，资料`context`的数字提示仍不成为正文路由。

旧V1/V2请求编码、原始baseline、已付工作指纹、原生响应与历史失败状态不变。新接收能力不是偷换旧源文本或把旧失败回执改成成功。

## 字段级诊断及收费边界

P1接收失败携带程序生成的具体坐标，例如`assignments.0.episodeNumber`、`reviewed.lastBlock`、`assignments.0.note`；不再把可定位错误一律压成`response`。未知字段、坏块范围及源版本漂移仍拒绝；无效别名候选继续隔离为原有候选警告，不提升为事实或结构阻断。

这类P1错误使用`LOCAL_ONLY`恢复策略。控制器保存策略，初次失败与后续恢复均不能据此购买格式补正；以后校验器变化也不得放宽已经保存的禁止收费策略。新校验器若能免费验证原回包，可直接接收。其他岗位已有的有限字段修复策略和限额不变。

## 已付结果的产品恢复

网页已有“恢复已返回结果（零模型）”按钮继续调用`recoverSavedFoundationDelivery`：核当前状态、来源与CAS后，重验原已付回包；仅增加`P1_ASSIGNMENT_TRANSPORT_V3`派生证明和进度检查点，保留原FAILED运行与回包全文。已完成批次不重读购买，重复免费恢复不重复采用；到首个没有可用回包的未完成批次即停止，不创建该批模型请求。

用户停止、运行中、未知结果、来源变化、过期状态、损坏请求编码和不能安全解释的值仍关门；没有弱化为“全部自动成功”。完成检查后继续未制作内容仍是正常模型调用，免费恢复不自动授予这部分费用。

## 集前元数据及旧检查点收敛（fidelity/6）

独立集头之后、正文或场头之前的明确“集名：标题”归为逐字保留的格式，不当人物、对白或画面字幕。场内同名对白、混合动作、空标题及用户明确采用的正文不适用。网站、独立下载包与P1物化使用同一规则；集号基础解析提取为浏览器安全的共享模块，含逐位中文数字，P1输出在此基础上维持更严格的无歧义拼写约束。

只有经接收验证、来源一致的P1归集建议，才能投影保留独立识别的同集场前格式；保留原提案、坐标、证明快照及修正原因。完整历史进度证明须同时匹配schema、原件/读取哈希、源版本、已完成范围与runIds；无证明、用户保护范围、显式场号、context和冲突归属均不放宽。不能仅看body字段或备注猜授权。

V5源码按旧版本逐字节冻结，V1–V5包先由对应旧校验器验真再升级；不改旧计划版本号、不删旧疑点以伪造通过。首个已付响应即使还没有完成检查点，也保持源输入和付费指纹，不因刷新而重买首批。

真实9批已付检查点在隔离SQLite副本中经产品免费入口验证：131项技术场界误报收敛为0，9/9完成范围与原runIds保留，19项P1格式投影留痕，5528行原场内正文不变。403条是投影后的派生归属，不是篡改原422条已付提案；原回包及旧快照全留。原始语义问题继续按自身依据处理，不把结构通过说成全剧语义或成片验收。

## 真实Word修订由用户确认，不由模型代选

来源页面新增“读取版本确认”：管理员或审阅者核对当前文本后，明确勾选采用。只生成独立`SOURCE_READING_CONFIRMATION_V1`记录，绑定当前导入ID、原件哈希、读取文本哈希与读取器指纹，不改原Word、修订标记、读取警告、P1检查点或源输入指纹，不启动worker或模型。

确认只解除`DOCX_REVISION_VIEW_UNRESOLVED`这一项读取选择。对象缺失、读取失败、真实归属冲突、UNKNOWN费用或用户暂停仍各自关门。来源、读取器、原件任一改变后旧确认失效；权限不足、过期页面或仍有在途任务拒绝保存。重复提交同一有效确认不增加记录。用户不认可当前文本时保留原件与门禁，不能自动接受/拒绝修订。

“技术接收可自动收敛”不等于“代用户裁决源文”。已知类错误在以后正常生产中走同一通用实现；历史故障可用现有零模型恢复入口，不需Codex逐批改状态；真正的读取版本选择可在网页直接确认。

新增回归包括：V6元数据/明确正文优先级、P1来源正反例、逐位编号、真实GET下载ZIP解包运行、首付无检查点保护、读取确认权限/哈希/在途/幂等/原件保留及表单身份绑定。对应入口为`verify:p1-reception-integrity`、`verify:source-reading`及`verify:stage1-recovery`。私人实际应用和保护对账另存本机证据，不随源码交付。
