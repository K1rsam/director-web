## 已确认的设计方向

“柔光鸢尾·浅”：以浅蓝紫环境光为主，少量暖色，玻璃面有边缘高光和柔影。避免纯白大块阅读面、深紫背景、石墨风格或过于冷淡的雾蓝。材质透明作用于背景，文字保持清晰。

用户的历次截图反馈已经形成 [DESIGN.md](../DESIGN.md)，继续工作时以它为准。关键要求：

- 页面顶部标题和主操作栏固定；正文独立滚动，顶部/底部自然渐隐。内容页签不吸顶。
- 侧栏适配浏览器可用高度，分集列表独立滚动；新建项目及 CLI 与 API 放在所有项目中。
- P0–P3 和 E0–E5 共用紧凑玻璃卡片；模型、耗时、编号不能抢占标题层级。
- 分镜表保持宽幅；Seedance 提示词也是主要工作区，不能左右留出大块空白。缩小无用间距，不删减真正提示词。
- 各类按钮有主次、统一触感；导航和页签使用连续选择反馈，页面切换有短过渡，也尊重减少动态效果设置。
- 浏览器默认 100% 缩放验收，不以整体放大掩盖字号和层级问题。

3180 是视觉/交互案例，不是真实生产后端。正式页面有真实长文本、全部镜头和操作，需要用真实内容验证。不要直接拿三行演示表替换生产分镜表。

- 未开始制作的剧集不再误报“已放行”；主操作说明与实际状态匹配。

- 抽屉独立滚动、背景锁定、Esc 关闭、关闭后焦点归还；不再用四条纯白按钮和整面白背景。

## 双端同步规则

`main` 是公共代码和本地版基线，`sites-online` 是 Sites 的平台适配分支。遵循 `.platform/platform-boundaries.json`：

- `common_once`：公共代码在 main 修改，生成 Sites 时带入。
- `dual_until_split`：同路径有平台差异，需要分别检查两端；不能整文件盲目覆盖。
- `sites_only`：云数据库、Runner 与平台配置，只在 Sites 适配层改。
- `local_only`：Prisma、本地流水线、本地工具和交接案例，不塞进云端运行包。

先阅读材料生成脚本与平台配置，再生成、验证并发布 Sites。新文件须分类，否则后续同步可能拒绝未分类文件。3180 案例在 main 保存一份，Sites 开发者同样从 GitHub main 查看，不依赖某台电脑端口。
