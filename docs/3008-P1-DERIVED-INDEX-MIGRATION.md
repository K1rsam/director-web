# P1 岗位结果交接：派生集索引迁移

## 缺陷与岗位责任

P1 可以纠正集场归属，接收层却把旧派生集数量减少一律当成删除业务资料。岗位输出虽已合法，保存时仍被拒绝并提示用户修改来源范围。这是 P1 岗位接收和保存契约不一致，不能通过让用户重做剧本或让 AI 重读全文解决。

上一轮只验证了合入后的内存结构，漏验旧数据库索引的迁移。本轮验收增加实际隔离数据库的保存与连续更新路径，不以任何业务样本完成作为交付目标。

## 通用机制

- 新结果必须逐字覆盖锁定原文，来源版本及决定版本在事务内复验。
- 只有能证明来自旧来源快照、未含人工或下游制作资料的旧集和场，才允许自动重建或退出当前索引。
- 变动前归档旧集、场、来源和凭据关联；程序生成的旧场历史保留原内容及标识。旧来源文件与凭据不覆盖。
- 已有人工作品、制作引用或其他无法证明为派生内容的资料继续保护，不能以“流程畅通”为由删除。
- 本地迁移不需要模型调用，也不改变已付费的 P1 请求指纹。不为此重新通读剧本。

## 状态显示

PARTIAL/error 不再显示首次使用的“待整理”。界面显示具体暂停岗位及系统处理说明。后端允许恢复时保留恢复入口；真正禁止恢复及结果未知分别沿用对应状态，不靠错误中文内容判断是否暂停。

## 验收边界

回归覆盖合并、拆分、正文转资料、连续更新、程序历史保留、原文保真及已有制作资料的拒绝覆盖；另有状态渲染和旧协议回归。具体执行结果由本轮主控复检记录补充。

没有重启或完成用户的测试项目，也没有用其完成率充当岗位验收。已有下游制作资料的跨版本自动迁移仍不是本次实现范围。

### 主控复检结果

- `npm run verify:stage1-workflow` 全部通过，包含新增迁移、P1 当前协议及 40 项界面 SSR 检查。
- 新增组合测试从已付费 P1 检查点进入真实 `prepareFidelitySourceAssisted`，验证集数变更保存、P1 完成、下一岗位输入加载和重复执行幂等；模型调用为零。
- `verify-fidelity-p1-upgrade-guard` 与 TypeScript 类型检查通过。
- 所有本轮自动化结论针对离线适配器、合成输入和隔离数据库；没有将 SSR 描述为真实浏览器验收，也没有将测试入口完成描述为任意新剧本的端到端成功保证。
