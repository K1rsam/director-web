# P1 精简来源快照兼容修复

2026-09-14。

## 根因及验收遗漏

正式 importParsedProject 写入 SOURCE_IMPORT 时仅保存 sourceText、sourceStructure、读取信息和原文件，不重复保存 episodes。P1 派生集迁移却将其强制视为完整 ImportedScript，直接调用 original.episodes.some，因字段不存在抛出 TypeError。模型已成功返回，错误发生在程序保存环节。

上一轮隔离测试手工写入完整 ImportedScript，虽然测试了 P1 接收与迁移，却没有使用正式导入写入器，因此未覆盖产品实际存储格式。这是实现和验收双方的问题，不能要求用户重做原稿。

## 修复机制

通过统一的旧来源投影读取器，从锁定的来源分区和保真凭据恢复内存中的分集视图。完整快照与精简快照都接受同一原文、分区、集号、标题和正文一致性验证。不得把缺失字段当空数组，不按最新解析规则重写旧凭据，也不增加模型请求或重复正文输入。

旧来源、付费批次及原始返回保持不变；证据损坏明确拒绝，不以跳过保护换取通过。

## 新验收入口

verify-p1-production-import.ts 直接调用正式 importParsedProject 创建隔离项目，确认实际保存的是精简快照，再从已保存 P1 批次经迁移进入下一岗位读取。覆盖合并、资料重新归类和结构不变；验证原文、旧快照和已付费记录不变、零新增模型调用及重复执行无新增快照。

投影读取器另覆盖精简、完整、旧版及损坏数据；既有派生迁移和工作流回归继续保留。所有测试使用隔离数据，本轮没有重启或替用户测试项目收尾。

主控复检：整套 verify:stage1-workflow 通过；补齐空元素检查及旧版导出类型声明后，重新运行投影正反例、正式导入三例和 TypeScript 检查，均通过。旧版实现没有修改。
