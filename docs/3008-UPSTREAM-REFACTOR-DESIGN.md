# 从第三阶段反推第一、第二阶段：重构分析

本次范围：用户明确要求开始上游重构，参考 `/Users/yue/Downloads/wash-script/`，并将原1.5改称第二阶段。本文是设计建议与代码核查，不把设计稿写成已实现或艺术质量已验收。网页命名另行做最小修改；同事文件夹只读，没有执行、安装或改写其生产脚本，没有调用真实生成模型。

## 核心判断

**第一阶段提供“可信且可引用的剧本事实”，第二阶段提供“已采用、可复用的视觉资产”，第三阶段负责“如何把这场戏拍得好”。**

不要把洗剧本的五段完整流程套到网页上，再让第三阶段重新导演一遍。借鉴它的固定格式、来源映射、事实/设计分离、资产闭合和定向修复；保留当前V4的情绪统筹→完整主创→统一整编。现有输入保护、局部修复、暂停恢复、未知费用保护及毛玻璃交互不推倒重来。

## 维度一：第三阶段实际需要什么

| 第三阶段需要 | 第一阶段负责 | 第二阶段负责 | 对分镜的直接价值 |
| --- | --- | --- | --- |
| 完整原文、正确集场、逐句说者/声道/语气 | 原文只读、来源定位、稳定的本版行/段ID、正文类型与对白归属 | 不重抄或润色对白 | 防漏台词、错说话人、把备注当对白 |
| 本场正在发生什么，哪些不能改 | 源中成立的事件、因果、关系、信息揭示顺序；人物自述与客观事实区分 | 设计不改变事件或身份 | 防提前剧透、凭空补动机、为画面改剧情 |
| 进入本场前已经成立的状态 | 持物、伤态、服装、进出场、知情等证据，发生/解除时点与时间层；未知如实标记 | 对应可用造型、道具状态及版本 | 防伤势自动消失、物品换手无过程、闪回串状态 |
| 当前可见角色与真正要备图的人 | 全部出场、提及、画外音、屏幕内人物、群体/成员关系与人数口径 | 独立参考、派生、随场呈现、仅声音的实际素材方案 | 防全员入镜、群演重复计数、错脸和不必要出图 |
| 角色/道具的稳定外观与必要变体 | 原文明示外观、用途、变体成立依据及适用集场 | 采用的外观设计、基础/变体差异、参考素材及制作状态 | 分镜能写与实际造型一致的动作，而非只笼统说“保持一致” |
| 可供动作发生的空间 | 源明确门窗、障碍、通路、空间边界、日夜内外及时间层 | 场景母空间、稳定布局、兄弟视图、固定光源/材质；设计与源事实分开 | 走位、交接、遮挡和反打有共同空间依据 |
| 哪些已确认、哪些还缺 | 决定及生效集场/字段；来源歧义、事实矛盾与后续设计待办分流 | 未采用设计、缺图、缺视图、受影响素材范围 | 真正缺关键事实才停；不因可选图片未制作阻断文字创作 |
| 当前用的是哪版材料 | 原稿、集场、证据与确认项版本 | 实际采用的设计/图片版本 | 避免旧稿覆盖新资料，只让受影响结果待复核 |

具体情绪落点、事件工作包、镜头时长、表演策略、机位运镜、逐镜光影/声音和幻想表达，仍由第三阶段决定。上游可提供全剧叙事依据与已确认风格，不预写一套分镜或把自己的推测冻结成事实。

### 当前实现不是从零，但存在四个真实断点

1. **对白被重复解析。** 第一阶段已有来源与集场，第三阶段仍对 `episode.content` 重新做规则解析；并未直接消费明确的逐句类型/说者目录。见 [input.mjs](../runtime/storyboard-v4/input.mjs#L24)、[source.mjs](../runtime/storyboard-v4/core/source.mjs#L59)。
2. **检索证据“看得到，但不都能规范引用”。** `facts/decisions/scenes/materialDependencies` 确实被传入模型，并非丢失；但普通 `contextRows` 仅来自前集末场，作者资料和更早历史没有转成V4可解析的证据行。入口事实的引用闭合集合只有 `sourceRows/contextRows`。见 [input.mjs](../runtime/storyboard-v4/input.mjs#L17)、[output-schema.mjs](../runtime/storyboard-v4/core/output-schema.mjs#L17)。
3. **第二阶段成果没有接通。** 原1.5已能整理 `visualFacts`、提示词记录与图片选项；第三阶段reader/adapter不读取这些成果，因此美术做得更细，也不会自动改善分镜。见 [asset-prompt-service.ts](../lib/asset-prompt-service.ts#L44)、[storyboard-service.ts](../lib/storyboard-service.ts#L27)。图片选项不等于已生成或已验收的图片。
4. **接收门过于笼统。** reader的 `PARTIAL/reasons` 混合事实/资料/资产问题，adapter转为警告；`prepare.ready`表示转换可读，不等于可安全制作。需要把真正阻断当前正文判断的问题，与未出图、可选设计、普通提示分开，而不是把所有PARTIAL都强拦。见 [light-foundation-reader.ts](../lib/light-foundation-reader.ts#L31)、[storyboard-service.ts](../lib/storyboard-service.ts#L37)。

另外，author/finish目前只裁剪正文和入口事实，仍携带整集context与assets；可以后续按工作包裁剪，不能先压缩掉关键证据。全局documentRevision还会让无关修改牵动本集版本，后续宜绑定实际消费材料。模型调用明确不使用工具，不能指望它临时按文件路径或sectionKey自行查漏。[core.mjs](../runtime/storyboard-v4/core/core.mjs#L81)

## 维度二：wash-script为什么值得学，又为什么不能整包照搬

### 值得保留的六项机制

| 机制 | 建议在网页中的落点 |
| --- | --- |
| 固定集/场/时空/人物/道具/正文结构 | 第一阶段统一阅读格式；机器数据不再依赖字符串位置猜类型 |
| 源ID、原位置、版本与逐处变更记录 | 原稿不覆盖；修订与显示整理分别留痕，新增版本不能冒用旧审核 |
| 角色、场景、道具与使用位置双向对账 | 检查未知引用、孤立资产、重复键、缺档；同时从原文反查遗漏 |
| 出场集合与备图集合分开 | 第一阶段记全出场；第二阶段只准备实际需要的参考，保留群体成员与身份对应 |
| opening→events→ending与mother-space布局 | 前者是有证据的事实连续性，后者是已采用美术设计；两者不混成逐镜调度 |
| 确定性组装、回读、同版局部复审 | 网页/导出共用一个序列化器；程序管编号、字段、保真，模型只做必要语义判断 |

代码依据：`wash-script/scripts/runtime.py` 89–237、254–301、368–489、492–590；`delivery.py` 224起；业务依据为 `references/fact-ledger.md`、`scene-continuity.md`、`character-routing.md`。

### 不能照搬的职责与偏好

- 五段中的“导演化正文”会先写观看中心、动作、声画组织，甚至补D段。整段放在第一阶段会与现第三阶段重复创作。可借鉴F原事实/D设计/Q未决的分离和设计补丁留痕，但导演设计仍在第三阶段。
- 不将“黑神话/写实”固定画风、某种群像人数、固定镜头/素材画幅、年龄或标识禁词直接提升为全项目规则。真实年龄、身份、剧情文字和物证在源事实层保留；平台安全/素材可执行性在对应适配层判断，不能通过隐瞒或改词绕过限制。
- 不把角色名加“默认状态”回写为所有原说话人名称。保留原称谓，通过主体ID、呈现身份ID、服化状态ID映射；戏中戏同脸不同角色也能表达，且不破坏原台词。
- 不把每个场景都填满姿态/坐标/镜头方案，不为表格完整制造事实；不强制增加多轮全剧审核和重复长文输出。

### 静态审查发现的实现风险

这些是本文件夹当前代码的风险，不是对同事实际成品效果的否定；目录没有真实生产输入—输出—审核成套样本，暂不能独立验证其“普遍稳定”。

1. **文档与检查器的版本分叉。** 新人物规则允许J＋functional C＋ambient visual C进入人物行/角色库，`runtime.py:482–488`仍只认J，`delivery.md:9`仍写角色区只收J。格式示例还有数字年龄和未入角色库的发言工作人员，与新规则不一致。
2. **人物名称替换会触及台词。** `apply_person_row_policy.py:13–18`对场内整行替换，不限冒号前称谓；`person_policy_replay_check.py:18–24`又先替换源文再比较台词，可能把已改台词判为unchanged。必须改成位置精确、带before断言的授权补丁，原稿永远只读。
3. **重放门禁有缺口。** `director_diff_check.py:46`首次ID未加入seen，重复D ID不能正确检出；标准补丁按source_id压成字典且只读after，insert和场notes不完整。借鉴思想，不直接复用实现。
4. **并非一个完整的五段放行器。** `runtime.py:593–627`只汇总facts/assets审核；导演交接、人物policy、actor-role与各check的结果未全部纳入。连续性文件的hash绑定也不等于内部状态链被校验。
5. **专案与关键词检查不能作为通用裁决。** 名称检查含“小午→烬午”特例；导演处理长度/关键词、服装禁用词、五官词齐全只能提示风险，不能证明情绪、空间或设计成立。

### 已做的零模型兼容探针

只读取格式示例的第一集，在内存调用当前 `parseScript`，没有运行wash脚本、写DB或发起模型：

- `导演处理`、`连续性备注`被识别成说话人。
- `日 内`和三条不带△的正常动作被报“无法安全识别为对白”。
- 这证明“适合人阅读的稳定格式”不自动等于“现有解析器无误接收”，不证明同事成品本身有错。

**结论：原稿仍是事实权威；内部以带原文映射的结构化字段作为机读交接契约，阅读/导出由程序生成。不要把装饰性格式和导演备注再次拼进待识别对白的原稿。** 用户仍可上传常见剧本写法，兼容责任在接收器，不让用户删除合法标题/动作来迁就程序。

## 推荐重构形态

### 第一阶段：剧本整理与事实底座

保留当前源稿物化、来源索引、局部决定与F2/Q1可修部分，不另建一套重复全剧总结。

1. **原文接入**：原文件/有效正文/版本、背景与正剧范围、表格等漏读风险。
2. **标准化索引**：集场、正文单位类型、原始说话人、声道、cue与原位置。显示可紧凑，原文不重写。
3. **事实与连续性**：主体/别名/关系、出场方式、物品流转、状态起止、时间层与揭示边界；每项可回到源证据，角色主张和推断分开。优先补反复导致分镜错误的几类，不先追求全语义知识图。
4. **按集交接**：把本集、必要历史与作者资料放进统一可引用目录；输出当前范围的阻断/待设计/提示，不广播全剧待办。

网页保留已确认毛玻璃步骤。正文区分“原文/标准阅读”，旁边可查证据和连续性；真正待确认事项独立呈现，技术格式错误不交用户当导演题回答。

### 第二阶段：资产形象设计与采用

1. 消费第一阶段同版事实，避免再从零抽一套互相冲突的人物身份。
2. 角色/非人/群体、场景、道具分别维护基础设计、必要变体、素材来源与使用范围。
3. 将“已有提示词”“已生成图”“已采用参考”“需要更新”分开；现有READY提示词不得冒充已采用图片。
4. 场景维护共同母空间/固定结构/必要兄弟视图，不把素材图相机冻结成成片机位。
5. 输出给第三阶段的是**实际采用设计的简短结构化约束与版本**，不是把整套长生图提示词反复塞给主创。

保持现有资产列表＋编辑区布局。事实、设计补足、参考素材与采用状态可清楚区分；不新造“事实→提示词→图片”已全自动的假流水线。

### 两条交接线＋一条回流线

第一→第三：完整正文/对白目录＋必要事实证据＋连续性/决定/缺口。

第二→第三：已采用外观/空间/道具约束＋参考版本＋实际可用性。

第三→第二：确实需要的新视图、接触细节、道具状态等**局部素材需求**；不直接改原事实、不让全库自动重做。第一阶段关键事实未明才回第一阶段，镜头偏好不回上游当错误。

这与已保存CTO经验一致：先明确共享材料，再决定岗位；概念分镜允许标缺素材，正式依赖引用才需要相应素材；机械搬运交程序，创作判断留给模型。历史资料只是参考，不恢复旧团队、旧E0–E5或固定镜数/全员入镜等规则。参见 `docs/cto-handoff/creative-reasoning.md:121–196`、`experience-review.md`、`3008-ROLE-WORKFLOW-REFACTOR.md`。

## 建议实施顺序与验收

**第一刀：统一接收与证据契约，而不是先改长提示词。**

1. 共用正文类型/说者目录；补必要证据到V4可引用目录；把阻断与提示分型。这一步同时修第一→第三真实断点，保留旧任务快照。
2. 补高价值连续性与主体/状态映射：换装、持物转移、伤态、闪回/戏中戏、知情边界；允许未知，不造全量伪快照。
3. 接通第二阶段实际采用设计及版本，先复用已有visualFacts/PromptRecord，再补采用语义与场景布局；图片能力未接通的部分如实保留。
4. 最后精简按工作包重复输入，增加从第三阶段回流的局部素材需求；只使所消费材料发生变化的结果待复核。

回归样本至少覆盖：同事格式、无△动作、中文/全角/带副题集名、多说者与OS/VO、群体个体混合、动作交接、跨集伤态解除、闪回/戏中戏、仅声音角色、素材未生成与源证据矛盾。检查不能只用“灵气”一稿。

分开验收：结构可解析；原文/引用无损；语义事实正确；真实分镜更可用；用户认可/实际媒体质量。格式通过不是精品证明。先用极少量同源场景对照新旧供给，比较错人、错状态、空间矛盾、无效返修和输入重复；真实模型或视频试产须另获授权，不能用静态测试冒充。
