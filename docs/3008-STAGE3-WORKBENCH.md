## 日常操作

- **创建任务**：新建区选15/30秒档、四种幻想策略；可选创作要求与调用/Token停止线。这里的修改只影响下一次新建。
- **开始情绪分析**：调用本机CLI进行整集情绪统筹。当前模型为GPT-6 Sol、中档，不采用第一阶段CLI/API模式设置。
- **情绪与幻想**：看完整事件的主体、变化和落点，按源位置选择表达。选择和确认只是保存；不会暗中开始正文生成。已有稿更改选择会先明确提示保留历史并重新创作。
- **继续完成本集**：主创一次负责完整事件的表演、摄影、光影、声音和所选幻想；整编联修完整关联范围。最多两路独立模型作业。
- **完整分镜**：单元阅读、横向分镜表和原始完整稿共用实际采用成果。复制与Markdown使用未删改的完整字符串；过期结果标为历史，JSON仍可导出。
- **执行记录**：显示实际阶段/范围、已结束记录、回执结果与已知用量，可按具体范围提交付费返修；来源、结构或依赖无法确认时不自动重发。

## 状态是事实，不是动画进度

顶部同时呈现当前阶段、执行状态、等待原因和安全下一步；三个阶段卡显示真实的工作包采纳/整编数量。幻想选择是统筹后的用户动作，不是第四个AI岗。

没有模型流式百分比或预计完成时间。作业历时包括排队、执行和回包处理，不等于模型纯计算时间。记录结束也可能是未发送失败；未知用量不计作0，停止线不是账单硬封顶。

- 暂停：不再派新请求，等待在途回包保存。
- 立即中断：独立风险确认，可能没有完整结果或用量。
- 检查已有回包/重新核查候选：不调用模型，仍须通过来源、epoch及关联范围校验。
- 确认未知费用风险：只解除指定阻塞，不撤销计费，也不自动继续。
- 文字稿待审看：程序核对与整编完成，不代表配音/视频或用户质量验收通过。

刷新和切换恢复所选任务的保存设置；轮询不覆盖新建草稿或未保存停止线。旧GET/POST不能覆盖换集后的任务，切页签保留返修草稿。同集有已知未结请求时不鼓励另建任务绕过恢复。

## 毛玻璃步骤与真实状态

本次将第一阶段 P1–P4、第三阶段三步接入同一套 Soft Iris 蓝紫毛玻璃：边缘柔和扩散，以低透明内反光形成厚度，文字保持清晰，不使用生硬白框。详细材质参数见 [设计规范](../DESIGN.md#3008-步骤卡soft-iris-毛玻璃2026-09-27)。

斜扫光是所有步骤都可出现的装饰；只有真实运行中的步骤有底部活动条。排队、等待确认、暂停、完成和异常仍以各自文字状态显示，不根据扫光推断进度。“减少动效”及系统减少动态效果设置只改变显示，不影响后台任务。

毛玻璃落地时没有给正文、分镜表或每项资产加循环发光。后续用户已明确要求将1.5改称第二阶段，现已统一网页命名，但没有改成 facts → prompts → images 连续自动流水线。第二阶段顶部真实状态摘要、错误恢复的玻璃层级、折叠执行记录和按钮短时反馈仍为适配建议，不冒充新增成果。

## 分阶段超时与执行诊断

以下时限用于**新发出的单次第三阶段 CLI 请求**，不是整集总工时，也不是“多久没有文字输出就停止”：

| 阶段 | 默认时限 | 可选环境变量 |
| --- | --- | --- |
| 情绪统筹 `plan` | 15 分钟（900000 ms） | `DIRECTOR_STORYBOARD_PLAN_TIMEOUT_MS` |
| 完整主创 `author` | 30 分钟（1800000 ms） | `DIRECTOR_STORYBOARD_AUTHOR_TIMEOUT_MS` |
| 统一整编 `finish` | 20 分钟（1200000 ms） | `DIRECTOR_STORYBOARD_FINISH_TIMEOUT_MS` |

未设置时使用默认值；设置后必须是 1–3600000 ms 的整数，单次最多 60 分钟，空值、非整数、非正数或超限配置均无效。无效配置阻止新生成请求，历史任务与成果仍可读取，不静默退回默认值。示例位于 `.env.3008.example`；修改配置不重写旧时限、旧回执，也不会自动继续任务。此策略不改变第一阶段的 CLI 时限。

每次请求在本机 attempt 下保存有限诊断：实际配置时限、开始 / 结束时间、最后 CLI 活动时间、标准输出 / 错误输出字节数、事件类型计数与结束分类；事件尾部最多 32 条，仅含时间和类型，读取上限 16 KiB。诊断不保存完整思考、逐 Token 内容、凭据或 stderr 原文，也不复制完整输出；模型最终回包仍按既有成果保存规则保留。

网页执行记录只取上述元数据摘要。CLI 最后活动不是模型创作进度：有事件不等于已有可用分镜，长时间无事件也不能单独证明任务卡死。没有诊断文件的旧任务显示“未记录”，读不到或损坏的诊断显示不可用；不能补写推测时间或把缺失字节数 / 用量当作 0。

### 无回包 TIMEOUT：核对、确认风险、单独继续

1. 先“检查并恢复已有回包”。此操作不调用模型；如果有原始正文、事件最终正文或候选成果，必须先恢复 / 核对，不能用风险确认跳过。
2. 只有安全核验通过才允许确认：本地与同集没有活跃 / 排队请求、同集执行锁可用；请求已有原因一致的 `FINAL / UNKNOWN / TIMEOUT` 回执；本地进程结束证据可核验；没有保存正文或候选。旧记录缺少进程回执时须通过本机进程检查，无法核验就继续阻止确认。普通 `UNKNOWN` 不能一概解除；原有用户主动中断 `ABORTED` 入口仍须满足其安全条件。
3. 用户主动点击超时费用风险确认并接受提示：费用仍未知，可能已经消耗额度；之后重新调用可能重复消耗。确认仅记录对指定请求的风险接受，保留原 `TIMEOUT / UNKNOWN`、未知用量、请求和历史成果，不撤销计费、不自动重跑，也不把费用变成 0。重复确认不新增调用。
4. 无其他阻塞时任务转为待继续的暂停态。用户**另行点击继续**才会发出新请求；原文版本、前置依赖、停止线和同集互斥仍须满足，确认不是绕过这些检查的通行证。

本次功能接入没有代用户确认真实第一集的超时风险，也没有继续或重跑该真实任务；原任务与超时回执保留。提高新请求时限不能追溯修复旧超时结果。

## 验证入口

### 阅读空行与接收标准（2026-09-27核对）

原文索引、交接预览和分镜源行阅读默认收起纯空白行；不合并动作/对白行，不改变行内文字及原始行号。原始证据页、数据库、交接数据和下载继续保留原稿。不要拿显示层清理后的字符串重算来源坐标或覆盖sourceText。

推荐作者格式如下，已用当前源解析器做内存验证；这是兼容写法，不表示每个栏目都是程序强制项：

```text
第1集：集名
1-1 客厅 夜 内
出场人物：甲、乙
△甲推门进来，乙转身。
甲（低声）：你还没走？
乙（OS）：他终于回来了。
```

每行只放一个说话者，完整对白不要人为硬断行（网页自动折行不算）；动作用△/▲，声道明确区分现场、OS、VO、系统音。背景资料独立，不冒充生产集。实际给下游的是程序生成的LIGHT_EPISODE_SUPPLY_V2按集包，不是截图或作者手写JSON：完整本集源文、集场归属、稳定证据、有关资产及素材依赖、前情、确认决定、缺项和版本绑定一并提供。

建议后续以“正文无漏改、集场归属正确、对白说者/声道明确、证据可回查、必要缺项无未解决阻塞、版本一致”作为合格标准；格式可读不等于素材齐备，更不等于成片质量。图片尚未生成必须如实标TEXT_ONLY，不能伪称已有素材。

当前仍有接收边界，**尚未统一为上述完整验收门**：prepareStoryboardView的ready只证明读取转换成功，真正创建才检查source.diagnostics；同一行多角色对白及仅标题无实质剧情尚缺可靠拦截；上游PARTIAL/reasons（包括部分严重资料问题）只转为警告。带括注的中文集标题和“【全剧终】”会被现解析器误报为无法识别对白。这些需要后续改接收校验，不能要求用户删除有效原文来换取通过。
