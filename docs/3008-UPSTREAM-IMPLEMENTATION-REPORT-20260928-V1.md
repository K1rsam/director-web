## 测试过程与结果

- 标准编译：先确认模块缺失的RED，再实现GREEN；复审发现并修正“将正文标点藏到layout”和“稀疏数组空槽破坏JSON往返”。最终正例及39类拒绝反例通过。
- 全剧方向：先RED→GREEN；修正字面量类型推断与运行时空参数分类，补总预算、来源清单变化、确认人变化和稀疏数组。最终12组通过。
- 判断边界：先离线假传输验证，复审补上UNKNOWN高概率不放行、异常model保留已知usage、Score等级绑定、动态模型别名拒缓存、2MiB响应限制、公开指纹及稀疏级别；随后修复在途配置轮换的凭据消毒竞态。最终44项离线测试通过。
- 规格与代码质量分开复审；已发现的重要问题均经过反例及修复复验，不以作者自报替代。
- `npm run verify:upstream-foundation`为新增离线统一入口；三模块均不读业务数据库、不在测试中访问真实模型。严格类型检查、项目typecheck及diff检查通过。

### 单次真实Jev合成接通

脚本：`scripts/verify-semantic-judgment-live.ts`。默认SKIP，只有显式`--synthetic-once`才允许一次请求；未加入普通离线测试入口。

- 请求内容：两行人工合成短句，角色甲与嵌套冒号；2个独立问题（类型Choice、续接说者Noul）。无真实项目/剧本输入。
- 实际模型：jev-1.13.0。
- 返回：Choice=dialogue，confidence=0.99；Noul=0.9。
- 计数：输入564、输出72 Token，单次请求；工具记录耗时781ms。
- 结果仍为review/uncalibrated，acceptedForProduction=false。

该结果只验证本次真实传输与两类响应可解析，不是准确率、节省比例、可靠延迟或完整生产验收。Score只作离线协议测试；未测试真实图片/视频，未发送“灵气”剧本。

## 文件交付与使用

1. `3008-STAGE3-AGENT-HANDOFF-V1.md`可单独给第三阶段优化agent：材料、职责、全剧卡、接收/版本/验收边界与改进顺序。
2. `3008-JUDGMENT-PROVIDER-INTERFACE-V1.md`说明实际接口和停用Jev后的程序/既有P1-Q1/普通模型路径；替代模型不得伪造Jev概率。
3. `3008-SERIES-DIRECTION-CONTRACT-V1.md`说明全剧卡如何定稿与保持跨集一致，不把局部情绪当整剧定位。

文件描述的是当前能力与下一接线要求，不指示其它agent自动修改旧任务或执行模型。第三阶段生产适配仍等待用户指定新版基线。

## 历史与数据保护

- 旧标准V1、旧反推/Jev分析保留；本次第三阶段影响只追加台账事件。
- 现第三阶段input/source生产文件hash保持本轮前基线，未接入或改写它们。
- 本轮只读核对发现第一集原run已在此前续作后形成文字稿（旧TIMEOUT记录保留）；这不是本轮新调用。没有回滚或篡改用户已有续作。旧TIMEOUT receipt仍与原hash一致。
- 没有向生产DB、源稿、既有任务写入本轮测试数据；未改变模型配置、登录或代理。

## 下一切片的完成标准

把明确的分类/片段计划真正从第一阶段来源流程产出，形成完整场次/主体树；把全剧方向候选/确认接到受信存储和界面；按需要做有标注的语义判断对照。之后再对齐用户新版第三阶段，不能跳过这些步骤把SLICE或高置信度答复当正式标准包。

实质接口、策略或验收结论变化新增版本/事件，写清目的、处理过程、影响范围和证据。普通无行为排版修正不再生成冗余报告。
