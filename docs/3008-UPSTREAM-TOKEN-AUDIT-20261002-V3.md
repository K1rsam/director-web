# 第一阶段无损减负与重复调用复核 V3

2026-10-02。追加V1/V2，不覆盖旧记录。本轮依据“无损、不降低质量”要求，先核对现有控制器，再修复免费回归查实的历史传输膨胀问题。没有真实模型调用、剧本外发、方向确认、设计生成或Git提交/推送。

## 1. 修正此前建议的边界

V1把Q1再次读全剧列为优化候选，但本轮确认：当前《神君》的这一笔是首次语义终编，并非反复点击导致的重复终编。原回包确实修正了4项资产、2个场景和1处拆场；不能仅凭改动数量少，就判定其完整源文核对没有价值。

程序检查可以验证格式、编号、引用、权限与容量，但不能证明角色/道具没有遗漏、同名身份没有混淆、悬念时点没有提前。故**保留首次必要的源文—目录双向语义核对**；不实施“没有程序诊断就取消首次Q1”。未来若要合并阅读岗位，须先有同稿质量对照，不能靠结构通过推定无损。

现有控制器已经实现而非本轮新增的保护：

- 已完整整理时，重复排队被拒绝，不新建模型派单；修改显示标题不使资料失效。
- 采用局部决定只发送受影响集/场或长集片段；不重新购买基础目录。
- 中断后复用有效的已付回包，保留原模型归属，不因换模型策略或传输视图重新计费。
- 局部返修无进展时持久停止；反复继续、重建任务或未知重发选项不清空原停止依据及预算。
- 真正的源文、全局条件或重要决定变化仍重新校验对应范围，不能为了少调用而假装资料有效。

本轮只增强这些边界的回归，不新建AI判断岗位、审批层或重复缓存机制。局部返修中的完整相关原文、最低全局身份索引和未证实可删的资产细节仍保留。

## 2. 查实并修复的问题

现有长短集混合回归复现：长第2集完成目录后，第3集请求达到665364字符，加24000字符输出预留超过200000字符的原请求预算，发送前被拦截。没有提高预算，也没有截断原文绕过。

历史检索含3303条独立证据，仅2种原句；但相同句子出现于不同坐标，不能合并为一条事实。旧历史V1传输仍有601734字符，主要重复负担为机器ID、分类、来源域与自锚点。

修改 `lib/foundation-model-input.ts`，新增自包含的 `HISTORICAL_EVIDENCE_TABLE_V2`：

1. 原行形状、字段、枚举、引用闭合及已知根协议严格校验。未知字段/引用完整回退；未知根元数据、缺推导版本、任一ID不匹配时，继续保留V1全ID表示。
2. 只有**每条**ID均等于当前来源版本、背景版本和完整源坐标的SHA256时，才用明确的确定性公式替代重复机器ID。独立解码器恢复所有原ID；模型无需计算hash，也不拿机器ID交回执。
3. 常量字段共享；重复值采用带字段名的零起始字典索引。原句逐字保留，不同源坐标、人物、主张、有效期和行顺序仍独立存在。
4. `evidenceShared.domain=EPISODE`是逐行验证后的恒定值，不是补猜。集号及字符起止原样传输。
5. `retrieval=null`只表示明确的“SUBJECT_MENTION且仅自锚点”；邻句、多锚点和其他检索边均保留完整数组，解码后与原图一致。
6. 仅实际更短才使用V2。已保存V1/V2传输视图再次投影保持原样；工作指纹、接收版本、岗位规则、输出要求不变。原件、数据库、标准包、历史回包和第三阶段接收材料不改。

合成探针旧历史V1 601734→94795字符；3303条证据全字段/ID/引用精确还原。首次失败专项转绿后，原长短集端到端回归恢复通过：源顺序、长集分片、后集伤势依据、前接原文、付费片段免费恢复、局部决定仅重核对应片段都保留。
