# 3008：岗位交接与内部自动修复

日期：2026-09-14。适用分支：`handoff/3008-stage1-20260912`。

本轮处理的是工作流的交接缺口：程序发现结构问题后，不能只把错误展示给用户；可定位、可验证的问题应在系统内完成局部修复并继续。无法完成的内部故障必须保留证据并明确暂停，不能伪装成用户的创作选择，也不能假报完成。

## 接收不同写法的剧本

原稿先保留不可变原文。P1 通读时同时接收程序已有的结构疑点，输出原文块归属计划，不重新生成剧情、动作、台词或说话人文本。程序按原文位置物化规范结构并验收；全文检查遗漏的结构缺口进入有界局部补漏，已读全文和已付费响应保留。

已清洗稿直接接收，不重复调用全文 AI。外部清洗推荐使用配对协议：`FIDELITY-TEXT/1` 返回归属计划，`FIDELITY-DRAFT/1` 返回标记全文；程序从原稿复制或逐字核对。仅有清洗稿无法证明外部是否改过台词。自由写法可以作为原稿进入 P1，不要求用户手写 JSON、计算哈希或修内部字段。

## 自动修复的边界

1. 程序执行可确定的解析、原文覆盖验证和输出契约检查。
2. 需要阅读判断的可定位拆场待办，自动交给有权输出拆场计划的编辑岗位；程序验证原文锚点并执行拆场。仅删除待办文字不能算修复。
3. 素材和引用问题按问题所属集、对象收窄。明确的场级目标限制场字段修改；未知范围不能当作全剧授权。
4. 同范围问题合并处理；成功结果持久保存，下一步复用。修复失败不回滚正确结果，不整岗重做，不重发整剧历史记录。
5. 无实质进展、修复预算耗尽、响应结果未知或无法可靠定位时停止自动重试，保留诊断给维护方。UNKNOWN 仍需要重复计费确认，不能悄悄购买第二次。

跨集待办需要完整结案时保留原子范围，不拆成无法独立结案的付费请求；超出容量时保留后台诊断。此处尚未实现任意跨集问题的分段结案证明，不能宣称所有长篇结构缺口均能自动消除。局部 P1 补漏的正文上限为 12,000 字符，完整传输 JSON 上限为 24,000 字符；连续缺口共用邻接上下文。

这套机制不承诺任意剧本都无需作者判断。原稿缺失的创作事实不能由系统编造；只有确实影响制作的取舍才进入用户决定，按实际集场提供给后续阶段。

## 维护入口与验收方法

- `lib/fidelity-p1-review.ts`、`lib/fidelity-source-assist.ts`：全文检查、残余结构验收、局部补漏与恢复。
- `lib/foundation-issue-dispatch.ts`：问题定位与修复目标，不用未知范围广播全剧。
- `lib/foundation-delivery.ts`：自动调用、局部写入约束、费用证据、复验与继续。
- `app/projects/[projectId]/foundation-delivery-panel.tsx`：真实阶段、技术暂停与费用确认。

重点回归：`verify-fidelity-p1-review.ts`、`verify-workflow-auto-repair.ts`、`verify-unactionable-repairs.ts`、`verify-foundation-repair-crash-runtime.ts`。这些使用隔离数据库和模拟模型响应，验证实际调度、持久化、原文不变及费用护栏；不能替代真实模型的语义质量验收。

## 本轮实际验收

- 主控复测发现并修复队列数组与任务 `scope` 共用引用：队列消费会污染内存 CAS 比较值，导致单线程也报“任务状态已变化”。改为独立数组，保留严格 CAS，并增加真实数据库比较断言；不是放宽并发保护或归因用户刷新。
- 隔离真实 controller：自动局部拆场、完成交付、原文逐字相同；拒绝改同集无关场和关闭无关待办；未知范围不广播。主控最终复跑通过。
- P1：多种标题/资料/正文写法、遗漏首段补漏、直接导入零模型、已付费检查点复用、结构疑点不假成功、语义候选不阻断；主控复跑通过。
- 35 项模型接收/付费恢复检查、28 项保真解析检查、35 项界面 SSR 检查通过；持久修复预算、无进展停止、响应保存故障恢复、长集分片、场级交接回归通过。
- 浏览器隔离 3018：登录、生成外部材料、粘贴计划并配对原稿、创建项目、下载原文逐字一致、Skill 下载和刷新通过，页面错误为零；没有把浏览器用例当成真实 AI 质量证明。
