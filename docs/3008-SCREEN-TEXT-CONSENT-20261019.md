# 第一阶段额外叠字确认

## 本轮要求

时间跳转字卡、姓名/身份/等级介绍及其它额外叠字，即使剧本写了“后期添加”，也不是用户已经同意加入生成画面。第一阶段沿既有必要确认卡询问加入/不加入；已确认的同类、同范围答案不重复问。幻想推荐不是这项确认。

墙上文字、牌匾、书信、系统面板及剧情内屏幕等有实际载体的文字依源保留，不因出现“等级”二字就要求确认或删除。按语义和载体区分，不添加关键词扫描或自动删改源文。

## 实现与权限

- `foundation-choice-change-targets.ts` 增加可选 `presentationFields`：`timeCards`、`identityCaptions`、`otherOverlays`。纯呈现题的资产/资产字段/场次字段数组为空，不可混入资料修改权限。
- 使用既有 `humanChoiceRegistry`、必要确认卡、源版本、范围、CAS 保存与 `APPLY_DECISION` 回执。只有呈现交接时可提交 `changes:{}`；实际确认后仍须完成采用回执，推荐、待确认与保存答案本身不冒充已采用。
- 确认答案按集/场进入后续 `context.confirmedDecisions`。不加入只省略额外叠字呈现，原时间跨度、身份等级事实、原对白及源目录不变，也不自动改为旁白。
- 加入时，统筹/主创/整编须交实际显示文字、位置、占幅或字号、有用样式、入场/驻留/出场与画面衔接。不将“后期统一制作”等流程备注写入执行正文。

示例仅供已确认后的具体设计：添加字卡“十余年后。”，画面正中、宽约50%，白色细衬线字，无底板，黑场渐显、短暂驻留后渐隐。居中、50%与渐隐不是所有字卡的强制模板。

## 冻结兼容

新 `rulesSnapshot.screenTextConsentVersion=screen-text-consent-v1` 将 `onscreenTexts` 明确为源证据，取消“一律上屏”指令。独审发现这条旧硬指令会与用户拒绝冲突，已有离线 RED→GREEN 请求构建回归。未知版本拒绝，不静默回退；旧快照未带标记仍使用旧输出提示，不偷换旧合同。

省略 `presentationFields` 的旧权限规范化字节及身份不变。第一阶段方法身份随新 schema 改变，不自动重跑或迁移旧项目。已完成150集、旧源文、采用稿、原生 request/receipt/FINAL 和正式导出不改写。

## 验证边界

`scripts/verify-screen-overlay-consent.ts` 使用隔离 SQLite、真实确认/采用/交接控制器及注入的离线响应，覆盖加入/不加入、待确认阻断、旧修订拒绝、范围隔离、禁止资产/场/源修改，以及统筹/作者/全量和差量整编的新旧请求提示。未调用生产模型。

相关权限/保存/交接回归与类型检查另行记录在本轮私有工程证据。测试证明程序链和指令合同，不证明模型一定正确判断所有文字载体，也不代表视频成品或用户验收；本轮不以新增付费调用验证语义，不重跑已完成集。
