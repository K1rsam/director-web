# 判断接口与无Jev路径 V3

2026-10-01。追加V1/V2，不改写旧测试结论。此次整合**不要求Jev在线，不向Jev发送真实剧本**。

## 更新目的

稳定格式交给程序，创造性交付归原岗位。避免把明确的对白、表演括号、空行、坐标和版本问题交给另一个模型；也避免每集增加独立付费裁判。

## 本轮路由

| 工作 | 首选 | Jev不可用时 |
| --- | --- | --- |
| 空白整行、明确说者/声道/cue、唯一坐标/别名、版本/覆盖检查 | 原文保真解析与编译 | 完全不受影响 |
| 合法格式尚有局部归属歧义 | 既有局部候选接口；提供源片段、有限类别及UNKNOWN | 现有CLI/API同形候选或只修对应解释，不重写整篇 |
| 全剧方向、情绪、主创、整编 | 已有负责岗位 | 不另开Jev评分器/长摘要生成器 |
| 跨集已选版本、原文hash、同值状态、采用分组和依赖 | 程序核对 | 完全不受影响 |
| 自由设计差异与真实源冲突 | 原整编局部修正/真正冲突交用户 | 不用概率高低覆盖源文或锁定约定 |

Jev可继续用V1 provider/Choice/UNKNOWN接口做合成资料实验。若将来允许真实材料外发，必须另得用户明确授权，记录最小源范围、问题版本、模型、原生用量和用途；不能因环境已有Key就默认为获准。

## 可替换边界保持不变

- provider只给有限判断，标准稿、productionFeedback、资产候选和第三阶段不依赖供应商格式。
- 返回`review/complete/unavailable/failed`、原始置信类型与已知usage或null；普通LLM自报概率不当校准值。
- 非关键且来源明确的程序整理可自动完成；**不能用“候选全部人工确认”恢复旧的无意义关口**。源冲突、关键方向/设计仍需要真实选择。
- 生产预算上下文为统一账本；任何新增的真实Jev实验必须以`provider=JEV`先预约再结算，和其它调用共用批准的40/200万边界。禁止新建隐藏预算来绕过停止线。
- 关闭/NOT_SENT不制造调用成功；UNKNOWN暂停新付费并保留回包。更换供应商不抹除旧证据，不自动再付一次。

当前实现入口仍是`lib/semantic-judgment.ts`、`lib/script-resolution-judgment.ts`和`lib/script-resolution-service.ts`。本轮新闭环没有注册自动Jev生成动作；所有回退都能在无Jev条件下保存原稿、准备标准包、读取历史和继续独立创作链。
