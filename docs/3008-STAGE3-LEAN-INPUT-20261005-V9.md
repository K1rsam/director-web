# 第三阶段 V9：删重复输入，不再增加生产流程

2026-10-05。追加于 V8，保留旧报告和已付稿。本轮不增加岗位、确认步骤、AI 调用或预算，不提交或推送 GitHub。

## 修改目的

原稿约 1,741 字符，而一次统筹提示词为 74,399 字符，另带 10,800 字符输出协议。创作规则不是全部负担：资产卡反复附带已经实际可读的原句索引；没有前集的开场又带一次完整原文与节点。旧 v3 只共享完全相同的整数组，无法解决部分重叠的索引。

本轮只调整实际发送读包，不删有效创作方法，不继续堆叠规则或付费审查。

## 已落地

新任务冻结 `productionTransportVersion: production-lean-v4`，统筹、主创与整编统一消费精简读包。

- 只有当前标准稿已证明来源、权限、精确坐标，且本次模型可读原句完全覆盖的 `ASSET_NAME/SCENE_ACTION` 机械引用索引才省略。独立事实、设计功能、历史/未来证据、角色说法权限、未知扩展及被其他资料/正文引用的索引保留。
- 没有前集、没有采用尾态或共享约定，且本次完整可读开场及场景元数据时，省略重复 `currentOpening`；同步去掉输出协议中不再提供的边界坐标。真实前集材料、采用结尾、制作约定、关系策略及未知说明不删。局部请求未覆盖开场时保留原包。
- 分行对白精确装配后可证明覆盖多个物理来源行，不因逻辑行和物理行数量不同而误判缺料。
- 字符串精确拼接支持空分隔符，解决原文行本身含换行、原压缩器再次插入换行而不能复用的问题；不改原话或原换行字节。
- 原始 `source`、`productionSnapshot`、材料 ID/版本、历史请求和回包都不变。省略只发生在新版本模型输入中；旧 v1–v3 冻结请求仍按原字节恢复。
- Web 内核版本检查增加读包版本，避免热更新页面配上旧驻留引擎。没有静默升级旧任务或自动重跑。
