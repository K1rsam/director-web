# 《神君》隔离同稿对照驱动

## 计划与安全边界

本驱动只为已批准的30集上游、EP1再EP2对照准备。当前只允许 `prepare-only`，不得因此文档执行真实模型。源3007固定 `daad694d2027ad1aa4821ae4ab309d53fb1dbd0d`，原数据库只用只读连接查询明确的 Project、Episode、SOURCE_IMPORT 快照；不读取用户、凭据或配置表。

1. 先用零模型测试锁定默认模式、共享预算未知阻断、单动作范围、首集双侧质量门和输入统计。
2. 从源快照保留DOCX原字节、读取文本与30集旧正文/hash；迁移新隔离SQLite，正常保真导入全部原件，不假造P1、方向或设计确认。
3. 两侧共用第一阶段处理后的相同本集raw和必要上一集raw。3007使用固定源码原生makeEpisodeInput/parse，不接入3008标准包、方向卡或资产卡；3008通过统一workflow及现有角色服务。
4. 全部上游、两侧、失败与返修使用同一个40次／2,000,000已知Token账本。未知用量不填0、不自动重试；在途回包可能越过Token停止线，此值不是账单硬上限。
5. 默认仅准备和只读状态。显式 `--live-step` 每次最多推进一个持久工作流动作；不循环推进下一动作。EP2必须两侧EP1机械成稿，且代理复核记录绑定当前双侧稿件指纹。
6. 保存真实请求、最终正文、原生usage摘要与耗时；不另存模型reasoning事件。原生runModel的attempt/request/receipt目录保持原样。

共享创作设置：gpt-6.1-sol／medium、maxUnitSeconds=30、maxUnits=null、fantasyMode=recommended、源项目3D国漫／16:9。前置角色仍按现有role-runner配置，逐次记录实际模型，不静默改成第三阶段模型。关键设计默认NOT_SPECIFIED，候选确认门必须真实停下。

## 交付文件与证据口径

- `source/`：原DOCX、原读取文、原30集、原导入快照、保真receipt和hash清单。
- `comparison.json`：同参、固定基线、唯一预算/工作流、活动动作和历史journal；`shenjun-campaign.json`锁定同一campaign。
- `shared-raw/`：一侧第一次生产时冻结的双侧同稿及上集raw哈希，另一侧必须严格相同。
- `requests/`、`responses/`：上游实际发送prompt与最终岗位JSON、原生usage摘要、ledger attempt关联；不另存stdout reasoning事件。
- `3007-storyboards/`、`3008-storyboards/`：各自原生request/receipt/raw与运行档案。不会用3008新内核代替3007对照。
- `snapshots/`：每次状态快照、双侧最终正文、输入差异、真实请求比重/重复位置和统计；`latest-summary.json`为最新入口。

字符比重明确标为UTF-16字符，不冒充Token节省；父子字段统计可能重叠，重复字段也不自动等于可删。耗时仅累计已取得的原生receipt/角色计时，未知保留；完整费用以原生回执和账本为准。真实剧本/数据库只留在忽略提交的本地隔离目录，勿提交或外发。
