# 四路模型选择、统一暂停与安全重连 V18

## 用户操作

- 四路面板可选新分镜模型及推理档位，默认 **GPT-6.1 Sol / medium / 普通速度**，Fast 默认关闭。当前分镜内核支持 6.1 Sol、6 Sol、6 Astra；账号实际可用性仍由本机 CLI 决定，不静默换模型。
- 设置在保存四路安排或明确启动时保存；只有新创建任务采用。已创建的计划、主创、整编和原请求继续原冻结档位，选模型不重做旧稿、不调整预算。
- “统一暂停 · 保留在途回包”关闭整条原队列的后续派单，包含当前集的下一次模型请求；不取消已发请求。仍在途时显示收尾，归零后显示已暂停。**建议等在途归零再合盖**；合盖可能中断仍未返回的请求，不能承诺远端会保存结果。
- 人工暂停后点“继续原四路制作”，沿原选版、链和账本接续。复用已有制作许可，不重复要求逐集确认；不重发已完成步骤。原准备动作若因本次暂停得到严格 NOT_SENT，自动免费闭合外层记录，不要求手工改 JSON。
- 未主动暂停的已授权队列，页面重新可见、恢复网络或重新打开等待连接的页面时，核对原授权并重新接上服务端 worker。不会建立新工作流、解除人工暂停、扩大预算或同意未知费用。

## 通用实现与边界

`production-policy` 是浏览器与服务端共用的模型/推理允许列表及默认值。带版本的新任务选择经过完整对象校验，沿 workflow → 新任务 binding/settings → runner 参数传递，原生 request 记录执行选择。没有 opt-in 标记的旧非默认任务仍受原模型政策保护；既有 FINAL 正文恢复不受新选择影响。

四路暂停不再调用单集 `onPause`；后端已存在的每次真实调用前授权门负责阻止下一请求。在途回包正常保存。单集手动流程的暂停语义不变。暂停使用同一授权的 CAS，可容忍 worker 普通 revision 更新，但旧授权页面不能暂停后来的新授权。服务端 worker 停止可立即应答，等当前免费准备动作结束再释放原租约；不杀进程组或删锁。

临时只读故障仍只有原最多两次自动恢复。新 wake-reconnect 策略在耗尽后保存 `WAIT_CONNECTION`，停止轮询重试并释放本地 worker，保留原授权，等待网络/可见性事件或明确重连。重连不是绕过原上限：没有进展时不清零计数；一次成功 pump 才复位。源码、写入冲突、权限失败、未证明的技术错误仍停止，不能一律当断网。

`reconnect-parallel` 是经鉴权、同源且绑定原 `authorizedAt` 的 POST；GET、未配置、未授权和人工暂停均不能开始制作。人工暂停优先，晚到重连结果不能复活旧状态。跨窗口/重复事件复用同一执行者和租约；执行仍保持最多四集、同集一个请求。服务启动只恢复原已启用授权，权限撤销仍阻断。

保存正文先走原生 FINAL/退出证据恢复。未知费用、活进程、源漂移和真实承接冲突继续保护，**不能靠开盖或有网自动补发 UNKNOWN**。没有新收费中控、裁判或创作调用；未改创作 Skill、源文忠实度、幻想/表演规则或停止线。

## 验证范围

- 新模型选择、四路暂停不取消、wake 原授权重连、有界连接等待、准备动作即时暂停应答及 NOT_SENT 外层续接均先 RED 后 GREEN。
- 186 项相关 Node 回归通过，覆盖真实队列/临时账本的 80 集四路补位、共享停止线、同集互斥、UNKNOWN 不重发、旧冻结请求字节保全、原生保存正文恢复、导出对账及单集暂停旧行为。
- 真实适配器、临时 SQLite/鉴权 API、隔离浏览器真实组件、TypeScript 和差异检查通过。浏览器检查默认档位、切换模型、Fast 关闭、暂停/继续、online 事件及 390px 窄窗；HTTP 全部拦截，不调用模型。
- 当前原网页只验证模型切换并恢复默认，没有勾选制作授权或启动项目。部署只在无在途、无启用队列且 PID/cwd/owner/内核租约核实后进行；私人证据在 `runtime-3008/four-lane-controls-20261018/`。首探测因旧 owner 记录零动作退出，不把文件存在当活锁或删锁，确认死 owner 与本机身份并取得原内核租约后才允许冷加载。

上述是本机工程和合成断线/恢复验证，**没有主动合盖或进行新的真实模型生产测试**，不能据此承诺任意项目、任意断线时点或 Windows 已验收。新功能已补通正常用户入口；仍需人类决定的新未知费用和真实源文裁决会明确停下。未提交、推送或发布。
