# 第二集：回执分类卡住与定向恢复 V1

日期：2026-10-02。追加三阶段闭环修改记录，不替换旧结论。本轮不提交或推送 GitHub。

## 问题证据

第二集任务 `386cb58c-6f57-4181-9121-229011dbb40e` 的情绪方案已经返回，免费检查确认正文可形成 3 个工作包、3 个幻想候选。阻止采用的是生产回执，不是情绪方案本身。

- `productionFeedback.sharedChoices[0]` 将“本集沿用街头离场后的服装状态”这一条写成了 `INTERPRETATION`。
- 接收校验要求 `sharedChoices` 只能存放 `DESIGN` 制作约定，但原输出 schema 允许包括解释推断在内的四种等级，提示也未明确此限制。
- 校验只返回根坐标 `productionFeedback` 和“字段或类型不完整”。回执局部修复因缺乏准确原因，保留了同一条错误分类。
- 防重复派单规则发现问题没有变化，正确停止继续扣费；页面仍显示“定向修复并继续”，让用户误以为再次点击能推进。

本轮开始时只有两次真实调用：初次统筹 61,726 已知 Token，回执修复 28,644 已知 Token，共 90,370。重复点击没有新增调用；这不是累计多轮模型生成，也不是浏览器超时。

## 修改与安全边界

1. 错误精确定位到 `productionFeedback.sharedChoices[0].authority`，并说明制作约定与解释推断的区别。
2. 新任务冻结 `production-feedback-design-v2`：`sharedChoices` 的输出 schema 只接受 `DESIGN`。事实、角色说法及解释仍按各自证据等级进入入口/出口状态；没有共用选择时用空数组。不把设计自动提升为原文事实，也不为通过校验把推断自动改成设计。
3. 新定向回执修复使用 `production-feedback-repair-v2`，明确上述分类限制。只允许修改报错字段；其他回执值、消费记录、需求及全部创作正文保持不变。
4. 旧 `v1` 修复请求、旧输出提示和未启用新标识的 schema 保持原样，按原冻结版本重建请求。新版本不能改变历史请求的输入指纹。
5. 旧笼统回执错误先免费重校，生成新的诊断候选，不改旧回包。普通统筹、主创、整编都可使用这条局部恢复路径。
6. 原每任务两次自动返修上限、重复问题停止、预算及未知费用拦截保留，不重置次数或扩大额度。准确定位后的局部修复若仍无进展，继续停止，不升级为整套重写。
7. 工作台显示修复准入状态：旧诊断或已停止重复修复时，主入口改为免费核查已有回包；重校后仍是同一准确问题或已耗尽返修次数，不重新开放无效付费入口。
