# 3008 第三阶段：快速显示保存稿与连续完成 V1

日期：2026-10-02。对应用户授权：修复打开任务慢，以及新任务不能一次连续完成。本记录追加既有结论，不替换三阶段闭环框架。

## 1. 问题与原因

- 原前端先等待完整索引，再等待完整任务详情；资料准备和稿件显示绑在同一条等待链上。
- 原普通详情 GET 每次核对整个项目的任务，再为当前任务重复构建来源。此前实测完整索引约 2.1–2.6 秒、详情约 3.9–4.6 秒；不是读取几个保存文件本身耗时。
- 原主按钮在没有情绪方案时提交 `mode: next`。后端本来支持从新任务直接 `mode: all`，是网页入口将它拆成了两次操作。

## 2. 修改

### 先阅读，再核对

1. 新增已保存索引及详情视图 `view=saved`，不等待资料、CLI 登录与执行诊断读取。
2. 页面先显示真实保存稿及状态，同时标明“核对资料更新”。快照只是阅读，不是来源有效、预算可用或正式交付的批准。
3. 后台按当前所选任务进行来源与依赖核对，复用同一次当前输入；普通轮询不再刷新其他任务。
4. 依赖上下文完全不变时不重复改写、核对同一份付费稿。材料、前集实际尾态、选定版本或制作约定真正变化时仍进入核对。
5. 同一任务、同一选择代次的在途详情读取合并；请求结束即删除，不引入可能掩盖原文变化的时间缓存。
6. 核对失败保留已显示稿件，不放行生成或正式 Markdown 导出；切换任务、旧响应、卸载及未提交配置保护仍保留。
7. 读取选定前集实际结尾时使用前集自己的冻结接收协议和表演语法，不能用新任务的默认语法把历史稿错误判为过期。

完整项目核对仍在服务恢复、作业结束和正式 Markdown 交付的必要位置保留。原文及真正关键约束的变化、共享未知费用和费用停止线仍严格拦截。

### 连续制作是默认主入口

- 新任务主按钮为“连续完成本集”，提交 `mode: all`，依次推进情绪统筹、源顺序主创、统一整编。
- 次按钮“只做情绪分析”保留 `mode: next`，便于先审看方案。
- 创建仍不派单。等待幻想确认、缺材料、超时或费用风险时仍停止；连续执行不等于绕过这些条件。
- 已完成任务不提供重复付费的继续入口；旧版只读及导出策略不变。没有改并发、模型、输入内容、创作规则或预算额度。
- 沿用 3008 现有毛玻璃控件，不引入新视觉体系。
