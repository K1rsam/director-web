## 先说结论

我建议新的核心不是再发明一套更长的 P/E 岗位表，而是建立一个清楚的创作顺序：

**守住原稿与授权 → 决定观众如何理解和感受这段戏 → 找到人物当下的行动策略 → 联合设计表演、声音与观看方式 → 按模型能力组织生成 → 检查实际交付与成片。**

这些是判断的依赖关系，不代表必须六次模型调用、六个岗位或六张表。

“情绪先行”也需要分成两件事：

- 导演先决定**观众的体验**：先误会、再怀疑、最后意识到真相；或先压迫、后惊喜、再余味。
- 人物表演不能只照着情绪标签演。要知道**人物此刻想从谁那里得到什么，受什么阻力，何时换策略**。情绪从这场努力中产生。

这比“本段愤怒8分，所以加特写、吞咽、手抖”更接近你要的活人感。

两个模式可以成立：**Seedance 2.0 常规叙事 ≤15秒；Seedance 2.5 长叙事 ≤30秒**。这是已核对的模型能力方向，不是每段必须填满的时长，更不是15秒只能简单、30秒必须复杂。[Seedance 2.0 官方发布](https://seed.bytedance.com/en/blog/seedance-2-0-%E6%AD%A3%E5%BC%8F%E5%8F%91%E5%B8%83)、[Seedance 2.5 官方主页](https://seed.bytedance.com/zh/seedance2_5)。

## 2. 各家真正值得吸收的是什么

### 飞书：最有价值的是“理解意图再安排具体表现”

**活人感**：心理动机、眼神语气、身体联动、接触关系、环境反馈与拍摄条件要相互一致。人物不是独立贴在背景上的脸，手碰物体也必须有先后与受力。但“手机夜间口述感”只是那篇示例的场景，不是所有短剧都必须加噪点、晃动或拒绝电影布光。[活人感原文](https://mcn1eoufbabt.feishu.cn/wiki/Oskywwhoxi0YF7kkzEMcTs85nQe)

**空间与参考分工**：场景图负责空间，人物图负责身份，站位图负责相对位置，箭头负责路径。比反复写“保持一致”更有信息。我们已看标注图和入人结果；但是由一张图推导出的背面房间仍是设计假设，不能冒充实测空间。[站位与走位](https://mcn1eoufbabt.feishu.cn/wiki/Ve41wqNDVi7zh8kEGqRcCKo1nTh)

**色彩有功能**：区分主环境色、光照、阴影、材质和强调色，比只喊“电影感”有用；不必强制13色或把估算HEX当精确测色。[色板方法](https://mcn1eoufbabt.feishu.cn/wiki/FpzSwtgGqiFtDUkddK3cG6SMnah)

**商业目标和验收先说明白**：品牌叙事、投流转化、剧情短片不是同一个目标。先用小样校准，再扩量；连续失败要改变假设或制作方法，而不是只加提示词。不能把电商测试素材的瑕疵容忍度直接当你的精品短剧标准。[ToB经验](https://mcn1eoufbabt.feishu.cn/docx/FnvDdSQfGoLeo2xJptIcbyLdnvd)

需要排除的不是“长提示词”，而是**互相冲突、没有适用条件的指令**：固定12/15秒、三镜/五镜配额、每句最多10字、禁止停顿却又要求情绪发酵、所有对手戏持续对视。五份模板已找到具体冲突与示例漏改，见[模板比较](source-index.md#s045)及[手册与生产经验](source-index.md#s105)。

### Higgsfield：补上“人物怎样活着”和“当前镜头怎样独立成立”

三份文档各有作用，不应揉成一份巨型总提示词。

| 文档 | 最值得留下的机制 | 需要改成条件化选项的部分 |
|---|---|---|
| ACTING | 目标、阻力、策略变化、潜台词；倾听中的反应；动作突然停止成为重音；表面态度与真实需求的张力；上一场的状态继续影响下一场 | 每场2–4次变化、每人必有小动作、强者总安静、每场必须有人失败、所有角色都双重情绪 |
| CINEDANCE | 只装入当前段真正需要的引用；明确首帧；世界位置与画面位置分开；身体朝向与眼神分开；场景参考不擅自覆盖构图；把光学效果写成可见结果 | 默认禁止空镜/叠化、固定FOV档、长焦必须堆四条效果、把全部精确数字当确定控制 |
| LIRA | 先区分已有与缺失；身份由实际参考承载；局部修改说明改什么、保留什么；不同入口有不同表达方式 | 永远三分法、固定60/30/10配色、某模型永远优先、所有动作只写状态不写过程 |

这里最重要的取舍：

1. **动作与停顿都有理由。** 停住原本在做的事，可能比新增三个动作更有力量；没有物件也不必凭空加杯子。
2. **性格不是重复动作。** 同一习惯在不同处境可能变化、被压抑或不出现。不能让人物每一镜都执行固定眨眼程序。
3. **身份稳定，状态演进。** 音色可以保持，气息、语速和音量应随处境改变；伤势、疲惫、认知也不能切镜重置。
4. **起止状态帮助控制，关键过程不能省。** 取物、接触、转交等决定剧情结果的过程仍要说清；“只写状态”不是删除因果链的许可。
5. **不写未来结果的表演。** 主控可以知道结局，人物只能根据他当下知道的信息行动。

原文件：[ACTING](source-index.md#s106)、[CINEDANCE](source-index.md#s107)、[LIRA](source-index.md#s108)。

官方Zephyr案例还提示：人物可通过处境反差、身体承受的后果被介绍；舞蹈段先有音乐再生成动作。作者披露了大量未入选生成，所以优片案例不能被解释成“一次提示词就稳出精品”。[官方拆解](https://higgsfield.ai/blog/guide-youtube-seedance2.0)

### 漫剧老李：借资料组织与专项经验，不照搬它的最高原则

有用的部分包括：台词原句—建议—理由对照；按复用价值准备资产；区分文戏、写实动作与玄幻表现；保留动作起点、路径、终点与后果；投喂正文与质检附件分开；记录失败经验的来历。

但有四个关键问题会影响我们：

- **模型能力表有错。** 它将2.5最大时长写成15秒、把2.0参考能力写成单图，不能作为新的适配依据。[仓库能力表](https://github.com/lixiaoxiao9888-create/manju-laoli-skill/blob/aa20fb60054ae52553a4b13f8810ed2fcd89ba70/short-drama-director/references/model-adapters.md#L31)
- **创作判断被模板预设。** 固定12节拍、第9拍反杀、禁止静止、强制11环与密集切换，可能把你的关系戏、喜剧和克制段落全推向高燃武打。
- **锁稿保护不完整。** 一边保护核心台词，一边要求删场、重构台词；拆镜范例还新增一个“我”。不能让“优化”成为默认改甲方稿的权限。
- **实现与宣传要分开。** 包检查脚本只查入口/name并列数量；情绪脚本默认画12点，不从剧本计算情绪；多平台和批量流程主要是文字提案，不是已连接的后端系统。

它还在新规则旁保留旧范例，构成“禁止静止”与“定镜收尾”等冲突。这是我们重做时必须防止的：**经验更新后，旧模板、检查器和最终交付也必须同步，而不是只在总纲顶上再贴一条最高优先级。**

完整证据、38文件分工阅读清单与源码坐标见[仓库研究稿](manju-review.md)。本轮主任务另读根README与SKILL，共覆盖40文件；源码未修改。

### 外部实践：把“会写提示词”扩展成“会判断画面”

- 剪辑者要判断一段表演是否符合人物意图、关系与整体发展；声音、倾听反应和适量停顿同样塑造表演。不是每次换说话人就必须切镜。[Frame.io：表演与剪辑](https://blog.frame.io/2022/11/21/editing-vs-performance-what-can-editors-learn-from-actors/)
- 动作戏的反应镜能让观众感到代价；打得多并不等于观众更在乎。威胁、目标和观看位置必须清楚。[Frame.io：动作剪辑](https://blog.frame.io/2019/01/31/editing-action-scenes/)
- 首帧与文字分工、从必要动作开始逐项增补，有助于定位失败原因；明确的顺序比僵硬的统一公式更重要。[Runway官方图生视频指南](https://help.runwayml.com/hc/en-us/articles/48324313115155-Image-to-Video-Prompting-Guide)
- 参考素材、声画要求与时间段可以显式组织，但不能因为Veo示例用了某格式，就当成Seedance的专用参数。[Google官方Veo指导](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-veo-3-1)

以上是可迁移的判断方法，尚不是本项目的对照实验结论。

## 3. 新逻辑必须先分清四种“单位”

| 单位 | 回答的问题 | 不应被什么决定 |
|---|---|---|
| 戏剧节拍 | 人物策略、关系、信息或观众预期有什么变化？ | 不是每句话、每三秒一拍 |
| 剪辑镜头 | 观众从哪里看、看谁、何时改看别处？ | 不是每个动作必换镜 |
| 生成片段 | 这一批输入与时长能可靠承载哪些连续内容？ | 不是天然等于一镜或一场 |
| 故事板画格 | 需要哪些关键画面帮助设计、沟通或控制？ | 不是九格就必须拍九镜 |

一个镜头可承载几个节拍，一个节拍也可能跨镜。一次生成可含内部剪辑；分镜板的某格可能只是控制动作起点，不必在成片里单独停留。

这是新推理逻辑与旧 Web 最需要拉开的距离。

## 4. 新方案的三条路线

| 路线 | 优势 | 代价 | 建议 |
|---|---|---|---|
| **共享导演决策稿＋按需要调用专项能力** | 保持整段意图完整；复杂动作、表演、空间、声音按风险深入；可针对问题返修 | 需要明确输入版本和局部修改边界 | **推荐** |
| 固定多岗位逐列加工 | 批量格式容易统一，职责表面清晰 | 意图易在交接中丢失，声音/摄影/表演互相迁就；调用和审查负担大 | 不作为默认 |
| 整集一次性直出 | 启动快，适合快速看方向 | 长上下文遗漏、难定位返修，首稿好坏波动难解释 | 用于短小草案，不当长篇生产底座 |

推荐路线不是让一个模型一次吞整部剧、所有素材和所有规则。每次工作围绕当前完整片段；共享简短已确认的导演判断和相关事实，专家只拿需要解决的问题。**先定什么信息必须共享，再决定是否需要多个岗位。**

## 5. 推荐路线：如何真的推理

### 5.1 原稿与授权先分开

入口可以只有两个清楚选项：

- **锁稿转译**：保留原词、归属、事件、因果、人物关系和明确结果。错字、矛盾、合规问题先报告，不自动改。允许不改变这些事实的视听设计；会增加明显动机、关键行动或新事实的内容单列待确认。
- **允许改编**：明确可以压缩、重排或新增什么。先形成修改对照，批准后才成为新基线，旧稿保留。

同一项目可以局部授权，而不是非黑即白。甲方允许修错字，不等于允许改台词意思；允许改表现强度，不等于允许把“死亡”改成“受伤”。

### 5.2 先写一小段导演判断，不急着列机位

每个有意义的段落，只确定必要内容：

- 哪些原文事实必须到达观众；
- 观众此时知道什么、人物分别知道什么；
- 观众的体验从哪里走向哪里；
- 人物各自的目标、阻力与策略，何事使策略发生变化；
- 哪个可见/可听瞬间是这一段的核心。

没有人物的环境段无需硬填人物目标。镜头也不必每次制造新变化：建立空间、维持压力、给理解留时间，都可能有价值。

这段判断是后续方案是否合适的依据，不是给模型表演“内心独白”的指令。

### 5.3 表演、声音、调度一起设计

先排一条发生顺序：事件或声音 → 人物注意到 → 评估/掩饰 → 行动或回应 → 后果。

这不是五步必填模板。很多过程可同时发生，也可能故意省略。只保留使观众理解成立的部分。

- 台词有稳定原文ID与说话人，画面可以看说者，也可以看听者。
- 一段话跨镜不等于拆成几句，也不自动变成内心OS。
- 声音要写谁发出、是否画外、对行动有何触发；声纹身份与情绪演绎分开。
- 动作从处境里来；关键接触与结果写清，非关键生理细节留自然空间。
- 停顿期间可以发生犹豫、拒绝或重新判断；没有意义的停顿才压缩。
- 时间初估考虑动作与说话是否同时发生，不能把所有秒数机械相加，也不能只算字数。

语速数字只作报警参考；最终要用所选声线/实际口述与画面节奏验证。锁稿超容量时先调整切点和制作方式，不先删词。

### 5.4 再决定观看方式和需要什么素材

对核心时刻比较少量可行方案：

- 留在同镜，让变化自己发生；
- 切到对方，让观众看到这句话造成什么；
- 改变距离、遮挡、构图或焦点，让信息被发现；
- 必要时用声音、环境或物件承载，而不直接演在脸上。

不是每镜都提供三套方案；只对真正影响风格或理解的选择比较。

素材与分镜应有反馈关系：已有图限制哪些细节？这个动作是否需要补接触关键帧？是否必须有另一侧空间？普通短对话可能只需现有角色和场景，复杂调度才值得补站位图/白模。

**概念分镜可以先做并标缺图；正式引用生成前才必须解决所需素材。** 这样保留资产可靠性，又不把“全部资产先画完”变成开始思考的门槛。

### 5.5 最后组织生成，不让排版器重新导演

同一份源文和导演判断，可以输出15秒或30秒方案。分段时优先看行动闭合、信息转折、声音连续与可恢复状态，再看容量。

最终投喂内容保留：

- 本次真实使用的参考与用途；
- 开始时谁在何处、正在做什么；
- 必要事件、表演、台词和镜头/声音变化；
- 结束时需要留下的状态；
- 少量针对已知风险的限制。

项目背景、评分表、问题卡和长推理不混进去。参数由真实入口处理，不写未验证的伪API开关。

### 5.6 检查分成两个层次

**是否可生成/可交付**：原文覆盖、台词归属、引用存在、时间顺序、容量、状态连续、输入版本、最终导出内容一致。

**是否值得拍/值得留下**：目标体验是否清楚，人物是否在回应处境，镜头是否帮助观看，声画是否有层次，风格是否符合已经与你确认的样片标准。

“结构没错”不能冒充“创作已认可”；“我更喜欢另一个角度”也不能自动触发整集无限返工。创作问题要指出具体位置、损失了什么效果、改哪个变量，并限定重做范围。

## 6. 2.0与2.5：同一个导演逻辑，两种制作配置

### 已核对的能力

| 项目 | 2.0常规模式 | 2.5长叙事模式 |
|---|---|---|
| 单次时长目标边界 | ≤15秒 | ≤30秒 |
| 官方发布所列参考数量 | 最多9图、3视频、3音频 | 最多30图、10视频、10音频 |
| 应用重点 | 可独立承接的片段，控制单次负荷 | 较完整的连续事件、关系变化和跨空间调度 |
| 生成组织 | 可单镜、也可多镜 | 同样可单镜/多镜；长叙事不等于一镜到底 |
| 跨段 | 明确状态与实际参考 | 同样需要；官网另列两次延长能力 |

参考数量是公开模型上限描述，不代表所有入口允许同一组合、也不是应尽量用满。[2.0发布文](https://seed.bytedance.com/en/blog/seedance-2-0-%E6%AD%A3%E5%BC%8F%E5%8F%91%E5%B8%83)、[2.5发布文，2026-07-31](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)、[2.5主页](https://seed.bytedance.com/zh/seedance2_5)。

2.5额外值得研究的是白模/创意参考和时间戳局部编辑、绿幕/视角编辑。这意味着可尝试把难用文字说清的调度交给视觉预演，把局部失败交给定向修补；**不是官方承诺像素不变、帧级必准或零穿帮**。[2.5发布说明](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)

Higgsfield当前产品页明确列30秒、50多模态参考、native 1080p；页面标题里的4K不宜被我们直接当成模型原生输出规格。[Higgsfield产品页](https://higgsfield.ai/seedance/2.5)

BytePlus LAS官方文档索引已列 `dreamina-seedance-2-5-260628` 与4–30秒；说明不能继续用7月发布时“API即将上线”断言现在没有API。这是LAS入口的信息，不自动等于国内火山方舟或你的实际账号契约。本轮未发起API调用。[官方LAS文档](https://docs.byteplus.com/en/docs/Byteplus_LAS/video_gen_enhanced)

仍需后续入口验证：首尾帧与其它参考能否并用、各类素材时长/大小限制、音频控制、实际编辑边界。BytePlus的8月31日[提示词指南](https://docs.byteplus.com/en/docs/ModelArk/2607689)和[教程](https://docs.byteplus.com/en/docs/ModelArk/2607688)当前要求登录，正文未读，不据标题编写规则。

### 对写法的实际影响——以下是我们的设计推论

- **15秒不是压缩版的30秒。** 先找自然可承接边界；长对白不能为了省一个片段被改短或加速。
- **30秒不是双倍密度。** 更长容量可给误会、试探、领会、回应足够时间，也可以承载更长运动；不强制加入第二个反转。
- **参考增多后更要分清用途。** 身份、场景、路径、表演、声音各取什么；不要把30张图全部当首帧或所有人物都强行入镜。
- **局部编辑不会取消连续性检查。** 修完仍要看目标外是否变化、前后动作和声音能否接上。
- **镜头时长与生成最低时长分开。** 成片中可以有短插入镜，不意味着平台必须接受同样短的一次生成。
- **2.0也有叙事与音频能力。** 不能把它降格成只会单图动一下的旧模型。

## 7. 第一次预演：同一段戏，两种生成组织

以下是自拟的校准微场景，不修改你的任何剧本；不是已验证可直接投喂的成品。

### 固定剧本文字

夜，玄关。林岚拎着行李箱，把钥匙放在柜上。

林岚：“钥匙放这儿了。”

陈默：“这么晚了，明天再走。”

林岚：“你是怕我走，还是怕没人替你关灯？”

陈默伸向钥匙的手停住。林岚拉箱出门，陈默没有追。

### 导演判断候选

观众先以为这是一次普通赌气，听到反问后意识到长期关系的问题，最后从“没有追”感到这次不同。

人物读法暂选：林岚要一个真诚的挽留理由；陈默先用时间借口拖延。这是**根据文本提出的解释**，不是唯一正确内心，更不能直接替甲方锁稿加进既成事实。

关键不是哭脸，而是：钥匙成为关系即将结束的可见事实；伸手动作没能完成；行李声走远，人没有追出去。

### 大致时间与观看设计

| 预估区间 | 发生的事 | 为什么这样看 |
|---|---|---|
| 0–4秒 | 放钥匙、第一句原台词 | 让离开的决定具有具体行动，不先讲背景 |
| 4–8秒 | 陈默说“明天再走” | 可留在林岚的反应上，不因换说话人强制反打 |
| 8–11秒 | 她看向他，判断是否还会说别的 | 停顿里有判断；若实演空了就缩短，不硬保三秒 |
| 11–18秒 | 完整反问，陈默听到关键处手停住 | 语言、倾听与动作在同一过程中变化；不拆成零碎短句 |
| 18–26秒 | 她拉箱离开，陈默没有追 | 行李声与没有完成的追赶承载余味，不擅自加拥抱或回头 |

时间只是预演估值，需读台词/实际样片再调。可以用两镜完成：前段较近地看她，后段同轴侧向双人构图，让伸手、离开和留在原地都可读。也可比较更克制的单镜，但不预设单镜一定高级。

**2.5方案**：尝试一次约26秒、含明确内部切点的完整段落。段内情绪不中断，参考只绑定实际需要的人物、玄关和关键物。

**2.0方案**：可在反问前的自然转折处分成约11秒与15秒两次生成。第二段明确“钥匙已在柜上、林岚仍握箱、陈默未碰到钥匙、对话尚未回答”的起始状态；若复用上一段尾帧，必须使用真实取得的尾帧，不能只写“承接上段”。

二者保留同样的原文与戏剧判断。差异主要在生成边界、参考组织和衔接成本，**不是30秒版加戏、15秒版删台词**。

检验这个预演时，先问：观众能否感到话中的试探与失望？人物是否像在听而不是等轮到自己？不是问用了几个特写、有没有吞咽、是否达到9.5分。

## 8. 对未来 Web 的直接含义

以下是架构建议，不是本轮实现。

| 旧问题 | 新逻辑应保证什么 |
|---|---|
| 拆场后漏掉原文前缀 | 原文完整保留，未分配内容可见；场景/对白/事件映射可追溯 |
| 资产重跑删除重建、同名混用 | 稳定身份与状态变体分开；更新不靠名字猜、不无声清库 |
| 后端按字数改句、按时空重排镜序 | 程序检查与报错，创作模型或人裁定语义变化；不能偷偷重新导演 |
| 表演、声音、光线逐列补丁失去原意 | 各专项共享当前导演判断、当前稿和真实邻接状态 |
| 返修看不到自己正在修的现状 | 明确底稿、目标片段、不可动内容；只重算实际受影响范围 |
| 审查的稿与导出的稿不同 | 生成/编译后审查同一份可交付内容；审后任何语义改动使旧通过状态失效 |
| 结构通过就叫精品 | “可生成”“创作待确认”“样片已验收”分开显示 |
| 停止、重试、成本记录不可靠 | 状态可终止、可恢复；不重放已成功环节；每次尝试都有成本记录 |

这些判断来自此前已做的[后端诊断](source-index.md#s053)，不是把他人模板换成新名字。未重新声称修复或测试通过。

## 9. 如何越学越像你，而不越学越臃肿

以后每吸收一条方法，保留六样东西就够：**适用情境、想达到的效果、具体选择、对应输入/版本、结果与失败点、你的判断**。

分成四类保存：

1. **你已确认的偏好**：比如某部戏要克制、某类爽点要迅速、某种镜头你不喜欢；标明项目/题材范围。
2. **稳定的制作底线**：原稿授权、身份引用、状态连续、交付保真。
3. **可选择的创作方法**：长镜、反应镜、声音先行、白模、图形转场等，没有无条件优先级。
4. **待验证的模型经验**：版本、入口和测试材料写清，不能因一次失败就变成永久禁令。

同一条内容不会同时复制到总纲、每岗提示词、模板和程序常量中反复维护。真实失败应能指出哪条经验需要收窄或撤回。

首轮试验建议小而有区分度：锁稿关系戏、喜剧误会、写实动作、玄幻/MG各选一小段；先在同模型内比较旧/新组织，再比较2.0与2.5，避免把模型升级误认成工作流进步。看原文保真、人物/声音自然度、情绪是否到达、空间动作、可用片段比例与人工修正成本，不用自评分代替你的选择。

这些都还是研究候选，没有写入全局记忆、AGENTS或技能。

## 下一步讨论点

建议先选一段你最能判断好坏的甲方锁稿，比较两三种导演处理方式。我们先对齐“你会选哪一个、为什么”，再决定新工作流需要哪些能力与协作边界，最后才写新的AGENTS和Skill。

**本轮得到的是有来源、可回查的学习底稿和第一版推理预演；不是已经证明达到精品质量的新系统。**
