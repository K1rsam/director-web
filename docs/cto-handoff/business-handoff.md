## 1. 用户究竟要什么：优先级不能再倒置

### 1.1 核心业务不是写分析报告，而是交付能制作的分镜

用户最初描述的实际工作是：接甲方剧本，理解全剧、组织人物/场景/素材，再按集场转成Seedance可用的分镜组提示词，生成后选片剪辑。图片和视频由对应软件完成，当时最需要的是快速、稳定、一致地生产分镜提示词。[最早工作描述][H5]

因此当前第一业务应是**剧本到有导演内容、清楚可用的Seedance分镜脚本**。全剧前置、数据库、岗位树、JSON、网站和管理制度都服务它。用户不是只要一份“剧情没漏”的谨慎说明，也不是先拿一个规模很大的组织图再等待内容成熟。

“通用”不能解释为粗糙兜底：普通对白、一般行动、常规打斗、人物出场、爱情互动都应有合格的基础导演处理；未来打戏/POSE/爱情专项负责进一步提升，不是等专项开发后才弥补主线无表现力。这是CTO在第一版公开建议中已经说过、后来没有充分兑现的承诺。[当时建议][C1460]

## 2. 15/30秒：必须补全我此前交接丢失的一半

### 2.1 历史确实有演变，不能删证据来制造“一直完全相同”

- **7月13日00:06：** 用户已经在同一条反馈中批评“14s的小分镜完全不变化镜头”和“6秒的分镜单元”，随后提出分阶段处理框架/时长、镜头逻辑，再细化动作/光影/前景/镜头语言。这直接支持“生成段要合理连续，但内部镜头不能呆滞”，两者不矛盾。[H1701]
- **9月5日17:25：** 用户给出的母版优化文本确实包含“取消15秒必须塞满”“15秒是最大容器，不是目标时长”，同时取消对白SC≤3秒，要求完整表达。不能假装这段历史不存在，也不能只截取它作为以后不追求长连续的永久授权。[WEB82]
- **9月6日10:21：** 用户明确提出2.5的30秒内长叙事与2.0的15秒内常规叙事两个选项。[C843] 随后的学习综合、CTO回复和任务包反复保留“不是必须填满”，却没有同等保留长连续的选择偏好。[学习综合第20行][NEW20]、[51包装任务第15行][PKTASK51]
- **本轮明确：** 两模式预先选择；合理、可生成且不改稿时默认尽量接近上限，短单元要具体理由。它是当前应遵循的完整口径，不需要用户再证明一次。旧记录中“默认近30秒”的同样完整措辞，本轮未找到更早直接原话，不编造日期或批准链。

**我的传递失真：** 把防止“硬塞满、拖时、加戏”的纠偏单向压成了“上限并非目标”，后续再把这种简写写进任务与验收，没有表达“优先长连续、短段举证”。主审稿第82行若仍只保留前半句，会延续同一遗漏。

### 2.2 现行完整原则

1. **先选模式，再做情绪与分段设计。** 模式不是末尾排版参数，要提前影响对白/动作容量、段落接续与候选切点。
2. **在合理方案中优先较长连续单元。** 尽量接近15或30秒，是减少独立生成接缝、降低跨段不一致风险的生产偏好；不是已证明任何模型都必然更稳。
3. **短单元允许，但理由具体。** 如真实换场/时间跳转、戏剧落点、与前后重组更合理、复杂动作或实际入口容量限制。只说“不必填满”不构成理由；大量常规低于10秒、长模式低于20秒，不能未经解释成为默认。这里也不是新增绝对10/20秒硬下限。
4. **不得靠水时长达标。** 不新增无用空镜、不延长无意义停顿、不把动作放慢、不删词或强压语速。应先比较合并与边界重排是否更好，不能先切碎再补水。
5. **五种对象分开：** 戏剧段落/信息变化、剪辑镜头、一次生成单元、故事板画格、实际世界经过的时间。一个近30秒单元可有多次快速切镜；一个很短的反应镜也可以只是长单元内部片段，不必单独发起生成；一个画格也不自动等于一个镜头或一次生成。
6. **对白连续不等于画面不换。** 原句和声源可以连续跨镜承载，听者反应可压在话中或余音上；不能切一镜重说一次，也不能把现场画外声改成OS。跨生成单元确有必要时要处理语义、声音与状态接缝，不把51“每U只属一个单元”的本例选择升级为所有模式的铁律。

51的30秒组织中已有16、19.6、13.2秒等单元；这是可检查的排布事实。[PKTASK51] 本报告不据时长单独宣判每段都错，也不另产一套51分组；关键缺口是，任务先锁定7组，却没有把用户的长连续偏好、全段重组比较和短单元理由作为交付要求。

## 3. 用户认可了哪些观点：按公开讨论还原，不扩大批准

本节C链接均指CTO原记录的物理行。重要区别是：有些是用户赞同CTO，有些是用户自己提出、CTO表示赞同，还有些是用户质疑而不是认可。

### 3.1 “不错，不过”——肯定部分价值，同时否定仍沿旧地基

**问题：** 前置P0–P3产出大量后面不消费的信息，专业修改相互牵连，未来业务难增加。[C1383]

**当时公开依据/比较：** 我比较固定逐列流水线、整集直出及共享导演判断，提出“事实底座＋段落意图＋专业分工＋受控修改”，说明只限制列不够，还要知道修改的依赖和影响。[C1460]

**用户回应及范围：** 11:40说“你说的很不错，不过……你还是再沿用我web的旧基础框架进行的升级改造”，要求真正推倒比较。[C1469] 这是部分肯定加明确纠偏，不是批准七种职责、所有修改规则或我在回复末尾提出的默认创作权限。

**后来：** 我在11:53承认前版主要回答员工怎样交接，转而讨论公司以什么组织生产。前版可留专业边界和必要上下文思想，不能作为已经获准的最终流程。

### 3.3 CTO与CHO——职责授权及下一阶段启动，不是永久代工

**问题/观点：** 架构负责人应总控、纠偏、安排员工，以真实成果验收，不把员工说完成当通过；下一阶段先定核心成果与业务边界。[C1616]

## 4. 创作业务全貌：分工要细，但共享的是一场完整的戏

下面是历史有价值的依赖关系和待主审讨论的工作地图，**不是把旧七职责、M1十节点或58六稿宣布为新定稿顺序**。原构想本来就区分业务能力、员工实例、模型调用次数，不能用“能力不等人数”取消专业分工，也不能反过来每列都开一个模型任务。[C1460]、[FRAME]

### 4.1 全剧前置为何做：每项都要能说明下游用途

| 前置资料 | 解决什么 | 实际消费者/携带方式 |
|---|---|---|
| 完整原文、集场/段落/发言定位 | 防漏前缀、漏动作、漏词；知道正在改哪版 | 所有创作拿当前完整因果片段；检索和核对可回原文，不要求每岗重读80集 |
| 项目约束 | 锁稿/可改范围、3D风格、画幅、15/30模式、成品结构、主体控制与参考条件 | 作为每次任务必要共用短约束，不能只存在总报告中 |
| 人物身份/关系/别名与阶段状态 | 防同名串人、造型不符、把未来关系提前带入 | 表演、分镜、资产引用与连续性；按本集时点给，不把完整人物传记交每岗 |
| 知情时间与信息来源 | 全剧知道不等于人物此刻知道，OS/系统VO不自动广播 | 情绪/表演/声音/信息揭示；给实际进入、听见、看见及尚未知的依据 |
| 场景、关键物、状态变化 | 持物、接触、出入口、方向与前后状态可接 | 表演/空间/摄影/单元起止；给相关局部事实及必要相邻片段 |
| 原文疑点与权限 | 区分源缺口、解释候选、导演发挥，避免把问题当改稿授权 | 只限制受影响的判断，确需改关键事实再交用户；不全链停等无关问题 |
| 类型与难点地图 | 选有区分度的试例，识别普通主线或专项需要 | 调度/研发与专业路由；不把类型统计或长“基调库”默认灌入制作正文 |

前置不传给当前员工，不等于删除资料。原始资料保全，供给按实际消费者反推；保存和投喂是两件事。导演决定也不是原稿事实：角色估计“全无珠”可被后续证据推翻；未来小传不是当集已实现；故事内有一个小时省略，不需要强补未写的全部搬运/铺布前史。

已有捕鱼[全剧知识地图][GLOBAL]、[集数类型地图][TYPES]、[原文索引][INDEX]可以避免新主审再做整本机械盘点，但其具体事实应按当前要写的段落核必要出处，不整包背书。

### 4.2 从情绪意图到成品的专业职责与真实依赖

| 专业环节 | 必须解决的创作问题 | 必要输入、输出与衔接 |
|---|---|---|
| 当集/段落叙事与情绪设计 | 本段让观众期待什么、何时吃惊/受压/释放？人物此刻向谁争取什么，阻力和策略怎样变化？ | 读原文、必要前情、模式与主体/资产条件；输出可观察的体验变化、信息cue、重点及保留项，不先填固定镜数 |
| 表演与行动调度 | 情绪怎样变成有目的的行动、倾听、反应、接触、起势/峰值/回收？哪些可夸张？ | 消费导演意图和源时点，与空间/声音共享实际触发；输出动作/表演方案及状态，不替相机决定所有镜头 |
| 空间与主体组织 | 谁必须在本镜被辨认/表演？世界位置、朝向、视线、动作路径和物件关系怎样成立？ | 与表演共同确定场面；输出少而充分的空间关系和人物负荷，不把七人名单自动变成七人同镜 |
| 声音与对白 | 谁发声、谁能听到、语气/节奏/停顿怎样作用于情绪？声音怎样跨镜连续？ | 原句与通道保真，结合人物策略/事件cue；输出声轨与可校准时间需要，不靠删词或改变OS解决容量 |
| 镜头/剪辑与摄影光影 | 观众此刻看谁/什么，为何切、怎样运镜和布光，是否真正放大重点？ | 在已有场面上比较必要观看方案；情绪目标贯穿，机位不偷改站位。光影可以共用策略＋镜级变化，但不能被简化消失 |
| 单元编排 | 在已选15/30模式下，怎样长连续、内部明快，又有可接续起止？ | 在创作早期就参与预算/候选切点，后期据真实声画定组；短单元给理由，不能只按场标、句数或已有表格机械打包 |
| 最终表达/导出 | 如何把同一已选稿变成用户看得懂、Seedance实际能执行的完整内容？ | 不重新导演；必要条件留在本单元，内部定位/验证资料另层展示；不能在“压缩”中删掉情绪或空间判别信息 |
| 独立专业判断 | 文本是否已有足够创作内容、主体可控、节奏有效、可读可用？哪些必须实听/实生才知道？ | 审实际最终表达，不只审表格；问题回真实源头，修后查受影响连接。不能把本来可判断的苍白表达全部放进“真实观感未测” |

**先后关系不等于一条只能等到底的长队：** 在共用原文、情绪意图和初始场面条件下，表演、空间、声音的一部分可并行提出；脚步声决定转头时点、动作需要门边距离等是真依赖，要协调选定。摄影可早提观看想法，但落到可采用稿时必须与实际动作/空间相容。编排若发现容量或衔接不成立，应有范围地返回有权调整的创作步骤，而不是包装器暗改。

### 4.3 情绪必须贯穿，而不是前置文件里写过就算完成

早期公开建议已经把“观众体验”与“人物目标/阻力/策略”分开；后者不是给视频模型生成内心OS的命令。[NEWLOGIC] Higgsfield相关ACTING资料提供目标动词、策略变化、倾听与回应的具体方法。[ACTING]

应一直能追到这条链：**本段希望观众感到什么 → 哪个信息/事件触发 → 人物如何行动/回应 → 观众通过哪张脸、哪个动作、何种声音/切点感到升级 → 最终单元是否完整保留。** 它不是每镜都要填一套新表，也不是固定情绪分数、每人吞咽或人均微动作。

用户举的群像例子已经说明稳定性与高张力可以一起设计：一句关键信息到达后，选择少量不同角色的差异化反应，借甩镜/切换串接，声音可保持连续；同一生成单元内先后看见多人，不等于同一帧同时控制多人。不要让镜头扫到某人时，他才像刚听见同一句话；注意世界中的反应同时性与剪辑观看的先后。

“保护原文”是保护事实和意思，不是只准照抄原动作；“稳定”是控制同时负荷和承接，不是让人始终平静；“快”是单位时间有效叙事/情绪密度，不是单元越短越好。极短蓄势或克制反应可以是具体方案，但必须服务用户要的增强效果，不能作为把3D漫重新拍成平淡说明的借口。

### 4.4 每个Skill至少要明确，但不必堆出巨大管理封套

一个专业Skill需交代：专业目标、适用/不适用场景、所需原文与当前稿、可改/不可改范围、具体判断方法、产出形态、关键正反例、验收与返修去向。实际输入必须带必要正文，而非只说“请看某目录”。其任务规模要适合实际执行模型/工具条件。

固定专业知识与当前项目事实分开。一般岗位不必反复拿全剧、所有其它Skill、所有旧失败报告；但省掉这些不等于省掉它完成任务所必需的整段戏、现稿和邻接状态。58一名执行员工串行六阶段、共享代理上下文，只能证明该执行条件下的开发表现，不能自动证明每个Skill在独立短上下文或目标API里同样能做。[58实际任务][TASK58]

### 4.5 未来支线如何利用主线，而不是推翻主线

旧讨论已给过同一种接入思路：拿指定原文范围、当前已选分镜/版本、创作约束、起止状态和可改区，交回局部专业候选、影响范围与新增素材需求，再走相同的衔接和交付检查。[C1460]

| 未来能力 | 可消费的主线成果 | 应返回什么，而不是做什么 |
|---|---|---|
| 角色/场景/道具资产生成 | 稳定身份、状态变体、已定风格及当前镜头需要 | 美术方案/实际素材及版本、缺口与绑定；不重新决定剧情有哪些人或把场景道具永久画进角色基础图 |
| 打斗专业拓展 | 原冲突/胜负边界、当前段落意图与动作骨架 | 更专业的攻防、受力/接触、反应和镜头建议，联动时长/空间复核；不擅改结果或整集其它段落 |
| 首次出场POSE、爱情错位表演 | 当前角色/关系、出场或情感目的、场面与参考条件 | 指定范围的姿态/表演/观看强化及关联变更；不把专项风格全局套到普通对白 |
| 白模参考视频 | 已选场面/镜头/时间组织及必要空间参数 | 可核的动作/相机预演参考及适配信息；不是在提示词末尾加“白模”二字即完成 |

这些只是应预留的业务边界，当前不要求生成全部资产、建设白模系统或开发支线。通用主线先能稳产合格内容，专项再提高专业深度。

## 5. JSON分区还是全文改写：已经讨论过什么，什么仍待定

用户7月解释过Excel的真正目的：只看/改相关单元格，减少重复通用段，不动正确部分，把可脚本化的搬运交给脚本；结果不满意不代表这个目标失效。[H2741] 9月又明确保留“专业Skill只改自己专业部分”的优点。[C1383]

**被认可/反复要求的是可控修改，不是Excel、JSON或某个schema本身。** 目前没有用户批准某套JSON字段树、所有节点数量或任意JSON自动合并的证据。

| 方式 | 可取处 | 对本项目的主要风险 |
|---|---|---|
| 每岗拿整稿自由重写 | 起步快，适合短草案、解释或受控探索 | 很容易改坏非本岗内容，反复转写原句；来源/版本与责任难定位，不适合作为默认稳定生产方式 |
| 严格分列/分区，岗位只看自己的小格 | 写域清楚，程序易比较差异 | 若读域也切得太窄，会不懂整段戏；时长、表演、摄影、声音并不语义独立，只锁列仍会互相打架 |
| 结构化单一底稿＋专业自由内容＋受控局部修改 | 保留专业表达，同时可定位、保护原句与无关部分、产生一致的多视图 | 需要先定最小业务字段、跨域变更规则与实际执行能力；不能直接堆完整平台封套给模型 |

第三种是**值得继续讨论的候选方向，不是本轮替用户定下JSON实现**：内部可用JSON或等价结构承载稳定身份、原句归属、镜/单元、当前创作内容与依赖；专业表演/摄影/光影等字段仍能写完整自然语言。外部给用户/Seedance的表示，不必是JSON。

防“拆东墙补西墙”的重点有五个：

1. 读到明确底稿与必要上下文，输出明确改区，程序拒绝越界；不是每个模型重写所有控制字段。
2. 源文、原句/归属和批准边界受保护；改解释候选不偷偷改原文。
3. 一次修改可能影响别的专业，需提出关联变更而不是暗改。公开旧例中“坐着回答→走到窗前回答”会影响摄影、时长、下一段起点，不应重做无关人物身份和其它集。[C1460]
4. 跨域冲突在共享意图下作明确选择；没有被选的两份合法方案不能同时拼入，也不自动各算一个Skill错误。
5. 最终采用同一确切版本组合，局部修改后复核受影响语义和连接；hash/字段差异负责保护，不负责判断作品好不好。

控制ID、权限、费用、调度与恢复应由程序或执行框架保证，不要求较弱模型自己抄写并担保。已有[模型输出/控制封套分离代码][CODE-CONTRACT]、[节点输入及模板拼接][CODE-INPUT]可作为后续技术参考；它们不证明创作工作流或目标执行器已达标，更不是现在重开网站工程的理由。

## 6. 最终输出、人物与俯视图：给主审的可讨论边界

### 6.1 用户本轮提出的栏目仍是候选，不是已批准母版

`[通用提示词][人物][场景][参考站位/俯视图][分镜]` 是用户正在问“哪种框架更好”，不能写成已全部定稿。可以围绕下面的职责讨论精确栏目与格式：

| 用户/Seedance看到的部分 | 应保留什么 | 不应混进什么 |
|---|---|---|
| 单元标识/模式/时长 | 所选15/30模式、本单元实际时段与总长，必要的生成边界信息 | 内部工单状态、审批编号、长预算说明 |
| 通用提示词 | 本项目3D画风、画幅、整体视觉/连续性要求及少量关键生成约束 | 全套Skill规则、评分方法、工作流程、无关题材预设 |
| 本单元人物与真实参考 | 实际需要的人物身份/造型状态、真实可用的参考及用途；各镜实际露脸/动作主体进一步明确 | 整场全名单自动绑定、虚构图片编号、未出现人物和每人完整传记 |
| 场景与必要站位 | 当前实际地点/时态、关键地标、关系和开场状态；复杂时使用真实参考站位图 | 每单元复制全场全部坐标、未验证的三维精度、把待发生动作写成已发生 |
| 分镜 | 具体时间、画面与动作/表演、观看/机位/运镜、光影必要变化、对白/声态/声音、有效衔接 | 只有“情绪强/光照自然”的空标签；大量审查式禁止句替代正向画面设计 |
| 必要结束状态/衔接 | 给下一次生成确实需要的角色/物件/行动后态 | 虚构下一集剧情；用“同上/延续上一单元”让执行器猜未提供内容 |

镜头视图和单元视图应来自同一已选稿：前者方便检查/局改，后者方便整体复制生成。内部源文索引、版本、映射、证据卡、费用、失败记录保留在独立工作视图，不删除，也不让用户从一大份技术账本里自己找成品。[当时双视图建议][C1460]、[旧通用段边界][WEB465]

具体用表格、分镜分行还是短段落，需要拿可读结构和用户共同定；本报告不新做51/58或另造一份母版。可以确定的是：**少废话不等于少内容；字段齐全也不等于人看得懂。**

### 6.2 同镜人物控制不是只数资产标签

至少区分：本场有哪些人、本单元先后涉及哪些人、本镜实际可见谁、谁需要清晰脸/口型/主动动作、哪些只是背景存在。旧项目1–2主动主体的规则有用户来源，不是毫无依据的过时禁令。[H386] 新方案不应未经讨论把它整条撤掉；若确需放宽，必须说明具体必要性和实际验证条件，不能因“允许群像”默认全员成为同镜清晰主动主体。

另一方面，控制主体不等于删掉群体戏：可把信息、对白与反应分配到同一长单元中的不同镜头，保留群体事件的完整性和反应差异。不能把“源动作完整”误写成“全部人物必须在同一个画面一起完成”。

### 6.3 参考站位与俯视图是空间工具，不是装饰或万能药

- 分清世界位置、摄影机位置/朝向、画面左右、身体朝向和视线。反打可能改变画面左右，不应无原因交换世界关系。
- 内部地图服务行动路径、接触关系、视线、镜头侧和连续性；静态顶视图本身不证明动态不跳轴、手能碰到或模型必定照做。
- 能用简洁明确的相对关系说明的，不必强迫每段写整组小数坐标；需要坐标时必须有坐标系、尺度及实际用途。现有材料未证明这些文字坐标是Seedance的官方可执行控制参数，不能把模型可能理解位置描述当成已验证的精确控制。
- 参考图若用于地理/材质/地标，不代表它的拍摄角度也必须继承；摄影仍要服务此段情绪与观看目的。[CINEDANCE空间规则][CINE304]
- 内部一次锁定世界关系后，每个独立执行单元只带它真正需要的空间锚点。可用实际上传的站位/多视图参考帮助表达，但没有该图就不能捏造引用。
- 白模视频是未来的新成果：需要空间尺寸、动作、时间与相机预演及验证，不能把七人坐标表叫作已经可用的白模功能。[白模扩展边界][FRAME170]
