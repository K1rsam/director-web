# 标准洗剧本与123阶段交接框架 V1

日期：2026-09-28。状态：**设计基线／待接入生产**。依据用户本轮明确要求新增；不覆盖上一轮分析。对应第三阶段改动独立登记在 [追加式修改台账](3008-STAGE3-CHANGELOG.md)。

## 1. 本轮明确的方向

第一阶段必须有独立、可验收的“洗剧本标准化”步骤。目标是吸收不同编剧、不同文件及AI候选的格式差异，让第二、第三阶段收到同一协议，不让下游反复猜原稿排版。

**不是删掉旧解析器不认识的信息，而是保留有价值资料、标明用途，并升级第三阶段接收方式。** 连续性备注、情绪线索、导演处理及上下文都可以传入；它们不因带冒号就成为对白，也不因未成为对白就被丢弃。

一个标准对象产生两份同源输出：

1. **统一标准稿**：给人阅读、编辑、导出的明确集场格式。
2. **标准制作资料包**：给程序和第三阶段消费的带类型字段、原文映射及版本的对象。

二者都由程序从同一已校验对象输出，不由AI分别重写。原文件与有效正文仍是事实权威，标准化不得覆盖原件或擅改台词。

## 2. 第一阶段内部步骤与职责

接入原稿 → 洗剧本标准化 → 事实／连续性／情绪理解资料 → 交接验收。

- **AI负责**：识别集场归属、说者和内容类型、必要语义歧义、有关事实与情绪线索；结果优先返回源单位ID及分类/关联，不重抄全本。
- **程序负责**：源单位分配、引用复制、字段校验、转义、编号和排版、版本记录、完整性及回读对账；输出新版本，不覆写原稿。
- **仅有歧义才局部处理**：单处断行或双冒号不能引发整本重洗。技术字段错误回责任岗按坐标修；源文确实无法裁定的说者/剧情矛盾才需要用户决定。
- **事实与建议分开**：上游可以提供观看中心、情绪理解、导演建议和已确认创作要求。不是禁止创作辅助，而是不把建议写成已经发生的剧情，不用上游镜头方案锁死第三阶段。

## 3. 人可读的统一格式

以下是网页阅读与导出的排版约定，不是让第三阶段按这些汉字标签重新解析的传输协议。场次间一空行，正文块之间由渲染器统一间距；原对白内的标点、引用及有语义的换行不做全局清洗。

```text
【标准化剧本】
第1集 · 回信

1-1
夜 内
场景：客厅
在场人物：甲
道具：未拆封的信封

【剧情正文】
△甲握着尚未拆封的信封。
甲（低声）：他说：“别拆：等我回来。”
甲：我等了这么久，
还要再等吗？

【本场辅助资料】
连续性备注〔源事实〕：开场信封尚未拆封。
情绪线索〔理解候选〕：等待带来的委屈与克制，可作为理解线索。
导演建议〔可选〕：可先关注握信封的手，再进入对白。
```

这是虚构格式示例，不是“灵气”改稿或已生成分镜。无本场辅助项时显示“未提供辅助资料”，包内仍为明确空数组；缺失、未知与已经核对为空须区别显示。人物的实体在场、画外声音、屏幕呈现、回忆、仅被提及分别记录，不把人物清单等同每镜都要入画。

洗本阅读可借鉴同事包的固定场头和三库组织；字段值不能被强行限制成某个示例的时代、画风、正整数起集或演员人数。集名、真实第0集、跳号等有源依据的信息保留。显示名不兼任稳定ID，角色和资产状态通过引用关联。

## 4. 机读接收框架：DIRECTOR_STANDARD_SCRIPT_V1

传输为严格JSON对象，由标准序列化器写出；不是Markdown代码块，也不是冒号分隔的自由长文。输入协议版本独立于现有performance-core-v4输出协议。下表为V1字段约定；[示例包](3008-STANDARD-SCRIPT-V1.example.json)展示实际结构，生产消费者尚未接入。

| 顶层字段 | 必填／类型 | 内容与边界 |
| --- | --- | --- |
| schemaVersion | 必填，固定字符串 | `DIRECTOR_STANDARD_SCRIPT_V1`；未知版本明确报不支持，不静默回退旧文本解析 |
| packageId | 必填，字符串 | 该冻结包的唯一标识；修订生成新包 |
| binding | 必填，对象 | projectId、episodeId、sourceVersion、revision、assemblerVersion；关联的是实际源和组装规则，不是示例假hash |
| script | 必填，对象 | number、title、scenes；仅本次制作的正文与结构 |
| entities | 必填，数组 | 稳定主体ID、原名/别名、主体类型；与衣发状态、戏中角色呈现分开 |
| evidence | 必填，数组 | 真实原文片段、来源域、源版本和可定位位置；不是AI意见 |
| annotations | 必填，数组 | 连续性、情绪、关系、信息揭示、空间、导演建议等辅助内容，详见第5节 |
| assetDesigns | 必填，数组 | 第二阶段实际采用的设计/参考投影及版本；尚未制作可为空，不伪造图片 |
| decisions | 必填，数组 | 已确认要求、适用范围与版本；推荐选项不能冒充确认 |
| fidelity | 必填，对象 | 冻结源单位清单的版本引用、全部单位去向/排除理由、授权补丁及程序保真回执；详见4.4 |
| issues | 必填，数组 | 有坐标的格式/事实/素材问题，严重程度及责任范围 |
| readiness | 必填，对象 | 结构、证据、当前阻断项、非阻断提示及素材可用性；由程序计算，不信AI自报PASS |

### 4.1 场次与正文节点

`script.scenes[]`包含稳定 `id`、原场号 `sourceLabel`、地点、时段、内外、时间层，以及 `presence[]`、`props[]`、`body[]`、`annotationIds[]`。未知地点/时间可为null并带问题，不能为了格式完整补造；是否阻断取决于它是否影响当前制作判断。

正文节点基本字段：`id`、`kind`、`text`、`sourceRefs[]`。kind只允许 `DIALOGUE / ACTION / SFX / ONSCREEN_TEXT`；对白额外提供 `speakerId`、`sourceSpeaker`、`channel`、`cue`。旁白仍属于需保留的发声内容，以专门主体和NARRATION声道表达，不凭画外呈现偷改成OS。其它声道约定为SPEECH、OS、VO、SYSTEM。

- `text`是正文值，内部可以合法含冒号、双冒号、引号、真换行、字面量反斜杠+n；均不能用于重新判定字段/段落类型。
- `sourceRefs`指向对应源片段；`textAssembly.parts[]`给出唯一组装顺序，SOURCE_SLICE引用正文片段，SOURCE_SEPARATOR引用原文中实际存在的空格/换行。按parts逐段原样连接，禁止自行统一加换行或去换行。获准结构性拼接变化必须有独立patchRef及before/after依据。精确偏移注明UTF-16或原文件段落定位，不能混用Python字符下标。
- AI尽量只返回引用、说者、声道和分类；程序复制真实正文。若发生获准修订，单列 `patchId/before/after/authorizationRef`，普通格式清理无权改字。
- 原文单位必须有完整去向：正文、场头、辅助源资料或确认为空白/元信息。排除项有原文与理由；不能通过把对白错标为“备注”绕过保真。
- 两个角色同一行发言等语义歧义由局部标注解决；不允许简单用所有冒号切分，从而拆坏“他说：别走”。

### 4.2 证据区

每条evidence含 `id/domain/sourceVersion/location/text`。domain为CURRENT_SOURCE、PRIOR_SOURCE、AUTHOR_CONTEXT、USER_DECISION之一；对应文字/决定必须确实存在，位置可回读。

本集正文覆盖只能使用本集正文节点；前情资料不成为需要补拍的剧情。事实证据引用可以指向有关历史和作者资料；AI建议不能放进evidence，不能用“建议让他害怕”证明“原文里他已经害怕”。

### 4.3 第二阶段设计与采用

`assetDesigns[]`至少包含 `assetKey/entityId/designRevision/sourceVersion/applicableSceneIds/originFacts/designAdditions/adoptionStatus/materialStatus/referenceIds`。场景另有已采用布局与必要空间约束。引用的来源、采用和图片状态都是真实记录。

提示词READY、设计已采用、图片已生成、图片已采用是不同状态。没有图片不等于没有设计；设计可以辅助第三阶段文字创作，但不得声称图像一致性已验证。第一阶段的人物存在事实与第二阶段的素材准备集合分别保留。

### 4.4 全源去向与保真回执

`fidelity.sourceIndex`指向冻结的完整源单位清单及其sourceVersion；生产须另绑定原件/有效正文/清单的实际摘要，接收器向当前源存储核对，不接受仅自报hash。模型输入不用重复携带整本原件。示例另附小型[source index](3008-STANDARD-SCRIPT-V1.source-index.example.json)。

`assignments[]`将每个源unitId唯一分配到BODY、STRUCTURE或ANNOTATION，并给出目标字段路径；对白行的说者、cue与台词分别有去向。`exclusions[]`只接受确有依据的空白/源元信息，必须保存原文、类别和理由。两者覆盖全部源单位、不重叠、不遗漏，正文单位保持原序；仅集合相等还不足以证明分类语义正确。

程序`receipt`绑定源清单、标准对象、补丁和组装规则的实际版本，记录覆盖、顺序、内容重建、说者/cue边界、排除与授权差异检查结果。接收器核验回执绑定及结果，不相信AI自报或旧版本PASS。`readiness.fidelity`只有VERIFIED可放行；NOT_RUN/FAILED或receipt缺失必须阻断派单。示例不伪造生产回执，故保留NOT_RUN与acceptedForDispatch=false；它用于解释资料形状，不是可运行任务。

## 5. 辅助资料不是被忽略的“附录”

每条annotation固定字段：`id/kind/text/scope/origin/authority/sourceRefs/decisionRefs`。scope明确集场及适用时点；authority只允许FACT、CONFIRMED_REQUIREMENT、ADVISORY。事实需真实证据，已确认要求需有效决定，AI解释默认ADVISORY。

| kind | 含义 | 第三阶段用途 | 不允许发生的混淆 |
| --- | --- | --- | --- |
| CONTINUITY | 开场状态、状态变化、跨场承接 | 规划确定入口，主创接动作，整编查衔接 | 当成新对白或无依据永久状态 |
| EMOTION_CLUE | 人物处境、关系压力、情绪触发与理解候选 | 情绪统筹参考；主创设计反应；整编核对表达 | 将推断强制升级为原文动机 |
| RELATIONSHIP_CONTEXT | 身份/关系及本场适用情况 | 理解互动与表演分寸 | 人物主张自动成为客观关系 |
| KNOWLEDGE_REVEAL | 谁知道什么、观众何时应知、不能提前揭露 | 控制信息与幻想表达的时点 | 把未来事件提前写进当前剧情 |
| SPACE_CONSTRAINT | 明示或已采用的空间条件 | 走位、视线、遮挡、接触 | 把素材图机位固定成每镜机位 |
| CREATIVE_GUIDANCE | 来源中的导演处理、上游可选设计建议 | 可采用、调整或说明不适用；已确认要求另按决定处理 | 当作已经发生的动作/对白或强制复写模板 |

origin区分SOURCE、USER_CONFIRMED、INTERPRETATION、DESIGN_PROPOSAL。来源中的导演注记也要按其真实性质分类：来自作者不代表一定是已发生的故事事实；但其原始文字应被保留并传达。

**投递必须可核对：** 派单记录保留本包提供的annotation IDs及版本。统筹、主创和整编都收到其所需内容与依赖证据。确认要求/关键约束应有采用或冲突记录；可选建议可以不采用，不能为了“消费完资料”强塞进作品。任何暂缓项保留原因与范围，不静默丢掉。

“全部有效信息”指本集与当前事件有用的完整资料，不是将全剧历史导出重复塞给每岗。先装配本集所需资料，再按工作包裁剪；关键依据不足时装配器补取，不让禁止使用工具的模型凭路径自行查找。截断/省略须有清单，关键证据不能静默截掉。

## 6. 为什么换行与冒号不再击穿整个流程

| 输入现象 | 处理方式 |
| --- | --- |
| 字段之间空行多、缩进不同 | 由JSON解码，语义对象相同；渲染器固定输出结构空行 |
| BOM、CRLF/CR与LF | 在接入边界作已声明编码规范化，原件不变，位置映射保留 |
| 元数据的中英文冒号、日内/日 内等 | 只在明确字段边界用映射表归一；不对正文全局替换 |
| 台词内“他说：别拆”、有意“：：” | 作为字符串值原样保留，不按冒号数量判错 |
| 真换行与字面量 `\\n` | 严格序列化/解码一次，二者不同；禁止二次反转义 |
| AI额外加代码围栏或外围说明 | 只有唯一、完整可定位的对象时可去掉外包装，原始回包留存；多个候选不猜选 |
| 同名JSON键重复、值互相冲突 | 拒绝当前候选并定位局部返修，不能静默采用最后一个 |
| 断开的引号、非法转义或正文被AI拆字 | 不能猜正文修复；按源引用重新组装或定向返修该对象，不整本重写 |
| “导演处理：…”恰好出现在原台词里 | 以节点kind和源位置为准，不能按黑名单删词或改类型 |

重要区别：**格式可恢复不等于语义可以猜。** 合法排版差异内部消化；无法确定说者、漏段、换序、修改台词等不能伪装“清洗成功”。

格式失败只隔离当前候选/对象，不销毁已正确场次与已付费回包。返回 `sceneId + sourceUnitId + fieldPath + code + allowedPatchPaths`；沿用已有持久调用上限与无进展停止规则，不新增无限返修链。技术错误由系统处理，不包装成让用户选择剧情的问题。

## 7. 交接验收与123协作

第一阶段输出前：源覆盖/同序/无重复、正文保真、说者/声道类型、引用可回读、JSON无重复键、必需字段和唯一ID、标准化幂等、序列化回读一致。

第二阶段补充后：主体与资产键闭合、采用版本明确、造型/空间设计和源事实分开、素材状态真实、不会因同名而换脸或切错状态。

第三阶段接收前和实际派单前使用同一版本门：结构和证据有效、当前范围无必要事实阻断；普通备注、可选设计和未出图不一律阻断。来源服务失效不冒充空资料。未知输入协议版本返回明确错误。

第三阶段产出后：继续核源覆盖、逐字对白及声道、情绪表达与状态衔接、采用设计一致性；新增素材需求可定向回第二阶段，必要事实矛盾才回第一阶段。第三阶段的新创作不回写为上游原事实。

协同收益应以减少错人/错状态/提前揭露/重复读取/无效返修，并改善实际可拍性衡量；不是用更多字段、更多审核轮数或一个PASS代替成品质量。

## 8. 版本与历史保护

- 新洗本包、新接收器和对应规则按版本启用；已保存任务保留其旧输入快照、指纹和规则。
- 不升级现有V4输出版本，除非确有输出字段需要；届时单独登记变更。
- 语义指纹覆盖节点类型、说者/声道、证据域、辅助资料、决定和实际采用设计；版式指纹另算。合法结构排版改变不应让全部成果陈旧，正文值实际变化不能被误当纯版式。
- 新包出现不会自动重跑第一集或迁移所有旧任务。旧结果仍可查看、恢复、导出。
- 本规范V1保存为基线；后续不静默改写其含义，新增V1.1/V2及与V1的差异。第三阶段变更、实现、撤销与替代全部追加到独立台账。

本轮只完成准确框架、示例资料包和第三阶段追加修改说明；**没有把生产解析器改成已支持V1，也没有完成网页洗本编译器**。示例的JSON/引用检查不等于真实洗稿或生成质量验收。
