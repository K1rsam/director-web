## 2. 实际修改

按 systematic-debugging / receiving-code-review 核真实证据，以 writing-skills 做小范围规则替换；可执行的尾段定位先红后绿，最后依 verification-before-completion 分开报告工程与创作品质。

1. **语气先于字速。** 共同契约和声音方法明确：参考字速不是合格区间。温柔、迟疑、决断、压迫可以慢说或停顿；喝止和反问也不按标签一律加速。先守自然整句，再把声音分配到有效切点，不从剩余镜长倒推急读，不因换画面把已合适的原话摊慢。
2. **收尾只修重复。** 主创区分必要退形/落定与重复收手、站稳、再确认。范围内下一声或动作可接管普通恢复；源未覆盖下一包时不补演其台词，交覆盖双方的原有整编衔接。整编采用retainedUnitIds前仍核实际声画，不把格式齐全当创作完成。
3. **幻想重音留在真正揭示处。** 铺外观威势与揭开破绽分开，不能第一眼已亮答案，后面再以相同特写冒领新回报；源有戏剧反讽则保留提前知情。奖励/世界理解可与既有声音共时，关键差别读清接主动行为。不把空壳、巨物或本样稿变成新模板。
4. **状态必须落到声画。** 源与入口、主创、幻想和整编方法加强实际位移与时序锚；只有源允许的同期/主观展开才能使用，不能用一句“同期”掩盖人物停住或到场问题，也不强插行走镜、虚构阻碍或时间跳跃。
5. **新增软坐标而非硬裁判。** `screen-rhythm-v5`的`audit.speech.tailIntervals`提供已知连续范围内末句声止→末镜结束的坐标与秒数，不复制台词。范围末尾不证明片尾，声后时间不证明空白。未知时长/边界、坏发声或非口语发声使相应测量保守退出；不自动改时、判错、暂停或派单。
