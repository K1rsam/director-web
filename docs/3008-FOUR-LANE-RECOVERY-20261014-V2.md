## 底层修复

1. **只读准备不成为重复生产。** 同一项目、集号、链、任务和全部读取选项，只合并正在执行的整个双快照读取；调用者获得独立副本，成功或失败即移除，不设跨请求 TTL。仅明确 P1008／SQLite busy 最多额外重读两次，来源变化及权限错误不重试，写入和模型派发不包进重试。
2. **队列状态与付款前核对分开。** 队列 inspect复用一次当前项目输入和保存任务视图，明确 `DEFERRED / ready:false`，不是当前资料已经验证。实际继续、内核派发及正式导出保留严格来源、消费范围和预算核对。临时不可读标为待核对，不能凭此声称 `SOURCE_STALE`。
3. **定点传播。** 单集结算／选版只刷新本集及前后相邻集，包括组边界；无具体消费范围的资产补充仍全量检查。冻结的 evidenceVersion传到当前读取器，不因页面使用新默认版本使旧任务失效。
4. **免费技术恢复有上限。** 已结清、无未知用量、无硬源冲突且未完成的明确技术故障可内部继续，先持久记录恢复次数再读取。新增 `NOT_SENT` 或零 Token记录不能重置上限。只有新完成、已知原生用量的模型结果才视为不同制作步骤；原生回执从恢复候选读取，避免恢复成功又被旧 UNKNOWN记录误挡。两次无进展即停止空转，不反复重买规划。
5. **承接复核不靠模糊字符串规则。** 追加 `boundary-review-v1`，绑定边界签名、前集实际稿版本、双方源哈希及具体字段。等义复核不能跨签名复用；明确冲突和锁定约定仍拦截。已核 scene仅按同版本派生为可读 DESIGN状态。未来 `production-feedback-inheritance-v1` 在既有岗位中约束已知入口键复用准确值，真实矛盾通过 conflicts报告，不另加付费判断岗。
6. **旧任务也能安全减少后续输入。** `configureInputPolicy` 只对将来的调用保存版本策略及追加历史，不刷新创作 Skill，不修改已付计划、主创、候选、旧 operation或规则快照。旧请求恢复仍使用原 operation中的输入供给快照。
