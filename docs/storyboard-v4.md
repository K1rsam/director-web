# 3007情绪分镜：使用与发布边界

本入口沿用项目分集原文与第一阶段资料，生成可评审的文字分镜，不自动生成图片或视频。旧E0—E5逐栏接力未重新启用。

## 使用

完成README中的依赖、数据库和本机账号准备后，先 `npm run build`，再 `npm run start:3007`。开发模式为 `npm run dev:3007`。只监听本机 `127.0.0.1:3007`；已有服务时不要重复启动。

进入项目的“情绪分镜”，选择分集：

1. 选择15/30秒单元容量和幻想模式，点“新建任务（仅准备）”。此步准备原文和本机平读参考，不调用生产模型。
2. “先分析”只推进情绪统筹，返回连续事件、工作包、粗单元和幻想候选。
3. 选择不加、全部加入、只加推荐或逐项确认。“全部加入”采用已有全部幻想候选（含未推荐但已设计的候选），尊重逐项取消；没有方案的片段默认跳过额外幻想，照常保留表演、摄影和源要求的表现，不要求逐片段覆盖，也不因此打断“连续完成”。只有主动勾选了尚无方案的片段，才需要补设计或取消该明确请求；主动补充规划会调用模型。逐项确认模式仍等待用户确认。
4. 点“连续完成”或“推进一步”。分镜生产全局最多4路请求、单集串行1路；不同集共享空位，优先照顾少占位的集、同级先来先执行。同集按源顺序等前包完成采用，再建立后包请求；相邻短包仍可一次完整创作。整编等待本集关联主创结清，复核全文并差量替换完整受影响单元。不会另加收费调度或创作判断岗位。旧计划若让前包依赖后包，会明确停下等核对，不跳序或自动重规划。
5. 完成后人工评审、复制或导出。局部问题按完整工作包提交返修，不重买正确段落。

网页区分本任务占位与排队：占位是本机已放行的请求，不是服务商正在推理的证明，排队也不算模型实际并行。回到页面会读取最新任务状态，不覆盖正在编辑的幻想选择。4路是本机上限，服务商排队、网络和限流仍可能使实际吞吐低于上限；不承诺耗时减半。

新任务的模型输入只省去纯空行及其可选引用枚举，不删原文、台词、声道、有效前情或专业规则；原始行号与ID保留。快照记录展示版本，旧任务缺少该版本时沿用旧展示，不使已付费回包指纹失效。整行`【音效：…】`、`【字幕：…】`、`【画面：…】`、`【特写】`归制作动作，不误建为说话人；人物明确说出的字面内容仍完整保留。已有任务和成稿不追溯改写。

新建参数与当前任务已保存配置分开显示。首次读取/切换任务会恢复其保存的幻想模式、秒数；自动轮询不覆盖用户正在编辑的新建参数。仅编辑上方参数不会改变现有任务。新规则只进入新任务快照，不回填旧任务冒充当时已生效。

新任务的后包还会获得源顺序紧邻前包的已采用末单元，用于承接动作相位、观看方向与出口状态；只交这一段，不重发整集历史。它是已作创作决定而非源事实，不重演前文，也不跨真实时空变化硬接动作。已存在的长包分批优先沿用其前批交接；旧任务/旧操作保持原请求版本。仍使用独立CLI调用，不引入隐藏续聊历史。

创作判断纳入现有独立整编：先找实际情绪回报，再对薄弱处比较演法，直接联修正文并记录实改；不另跑一遍全稿，不把自评分当放行。长段核中段发展，多层幻想核观看主次，修错误时保住身体峰值与运镜收益；有效静镜不强改。幻想推荐以充分强表演为对照判断净增益，关闭额外幻想不降低情绪/动作强度。现有超时预算暂不下调，下一轮串行实耗积累后再校准，不把旧并发样本当串行保证。

## 完整通用提示词与表现恢复

新任务使用“项目视觉基座＋本单元演出总指令＋相容的幻想说明”。`3D国漫`标签会选择完整三渲二、赛璐璐/PBR等项目基座，不再取代它；2D、真人和自定义风格保留各自介质与实际画幅。基座统一身份/造型、材质与层次、人物联动/惯性、声音口型和输出边界，具体场景光源仍由单元头与逐镜光影落实。

主创与整编在新协议中填写`unitDirection`，直接进入最终`[通用提示词]`，明确本段的表演调性、摄影节奏、声光重音与必要幻想边界；不能只有它写得精彩而正文平淡，也不能两处相互矛盾。项目基座、单元头和六栏不是互相替代。希区柯克变焦、子弹时间/速度坡度、甩镜、透视和破框等已纳入常用摄影方法，由情绪和动作选择，不设次数或运动镜头占比。

额外幻想关闭不关闭基础演出和摄影语法；正常比例人物仍可有强烈五官表演、身体动作与夸张取景。新增Q版、漫画替脸、字效、幻想场景或非现实意象仍受用户选择控制，不能借“表演/摄影”之名绕过off。源明确要求的Q版等照常保留。

程序合并单元时以现有segments保存各段指令，并在导出中转换成实际分镜范围，后段基调不倒灌前段。差量保留块原样保留；完整替换允许重新排镜，不强迫返回程序内部segments，但须将旧段有效的指令、光影和状态差异承接到新unitDirection及镜头正文，不能只保最前一段。

规则快照以`unitDirectionVersion: unit-direction-v1`区分新协议。旧快照无此标记时，仍沿用原提示/输出形状，不因新版缺字段被拒绝；已有规划不能通过刷新规则静默换协议。试用新版请新建任务，旧稿、原始回包与回执保留。

防退化检查按功能而非字数：风格/造型、源事实与情绪、表演动力、摄影与主视觉、具体光影、声音口型与气口、幻想递进/边界、单元独立可用、保存/导出不丢。自动检查只证明结构和传递；艺术强度、自然配音、视频生成和用户认可仍需分别评审。不会为补规范恢复旧的禁止Q版、固定脸数、40%幻想或单一高风险镜头配额。

当前分镜制作阶段（用户现称第三阶段）新任务默认 GPT-6.1 Sol、中档思考（`gpt-6.1-sol` / `medium`）、本机Codex CLI；需自行安装和登录，并确认账号支持该模型。中档显式传入，不依赖模型自身默认档位。可用 `DIRECTOR_CODEX_CLI` 指定可执行文件，否则从用户目录的 `.local/bin/codex` 读取。前置阶段CLI/API设置不等于本阶段执行配置。旧任务沿用保存的模型与档位，历史回执和测试证据不追溯改写；不支持的模型或档位报错，不自动换回旧模型。

## 创作与Q版

源事实、原话、声道、数字与知情 → 当前情绪和人物策略 → 可见表演与真实作用 → 同一声画时间线 → 幻想增益。

- Q版归幻想表达方法，不独立设岗；原文未点名也可按情绪选择，不自动等于搞笑、幼儿化或卖萌。
- 不设逐镜、逐单元或整集的固定幻想比例门槛。坏打算OS若二十秒全段适合Q版，就可持续二十秒，并可跨镜或跨单元续接；退出由情绪、语义与现实刺激决定，不由额度决定。
- 从整集保持主次，避免大半篇幅持续留在幻想层，以剧情与人物关系为主体；不能逐段说合适就忽略整体取舍。若铺得过满，先调整重复或抢读的片段，保住有作用的完整幻想，不硬插现实镜头凑比例。只有局部原文时不能假称已审整集。
- 画幅同样不设比例限额，适合时人物、形变或场景可占满画幅。长段需要表演和信息推进，不是长时间静态陪读；普通强表演、正常摄影与源真实法术不能被误判为装饰性幻想。
- 按同拍情绪判断严肃、压迫、痛快与反差，不以整场标签禁止后续反转，也不把尚未解除的伤痛一律演成喜剧。
- 30秒是容量上限，常规单元尽量接近，不是强制填满。单元、情绪拍、作者工作包不是一一对应；收的是无信息空等，不是原话或有效表演。

幻想时长记录用于真实声画衔接，不是比例配额；所选15/30秒单元总容量仍需遵守。工程通过、专业文字判断、实际配音/视频与用户认可分开报告。

## 运行与恢复

- 高级设置默认收起。调用次数与Token停止线仍由程序执行，不是账单硬封顶；在途及未知用量可能未完全计入。设0可禁止后续模型派发。
- 暂停停止后续派单，等待在途回包保存；继续仅推进未完成步骤。立即中断另有风险确认，费用未知不能当作零。
- 已保存回包优先免费恢复或复核；真有内容/格式问题才按额度有限返修。未知回执、仍运行的进程或源版本改变不能靠换任务ID绕过。
- CLI异常退出或超时且没有保存正文时，只有对应最终回执、本机进程及进程组均已退出等证据齐全，才显示“确认失败风险，允许继续”或“确认超时风险，允许继续”。用户确认保留未知用量和原调用记录，只解除该请求阻塞；另点“从已保存步骤继续”才重新调用未完成步骤，已采用的规划与正文不重跑。提交中、异地主机或进程状态不明不能放行；发送停止信号本身不等于进程已经退出。
- 启动、等待响应、生成进展、正文接收分别显示。仅新增内容算生成进展，报错、心跳和重复事件不延长空等时间；默认启动预算3分钟，总预算按岗位、请求字符量与单元数估算、最高30分钟，另有无进展预算。预算不是模型耗时或费用保证，页面也不把“已启动”当成远端已受理。
- 大型连续事件的主创按安全源文边界顺序分批（软目标5个粗单元或150秒），完整原话、粗单元和已选幻想跨度不从中切断。各批保留整场情绪与规则，承接前批末态；批次不是剧情事件或成片单元，最终整编仍可跨批合并，30秒及最终数量要求不变。未全部返回前保留分批正文，暂停后只继续未完成部分。
- CLI已保存完整正文却异常退出时，先免费核对原回包；输出文件残缺但最终事件正文完整时，读取完整事件正文，原始文件和回执不改写。归档、重复停止与免费重核不得把旧回包重复采用为新版本。
- 新CLI回执保留脱敏、限长的错误事件与标准错误摘要，网页显示可用的具体失败原因；不保存整条事件流或推理过程。此前被丢弃的底层错误无法凭退出码补造，确认风险也不等于故障原因已解决。
- 原文或前情更新时旧任务可能过期，旧结果仍保留；用最新资料须新建任务。规则也按任务创建时快照固定。
- 同集互斥、跨集并发、回执和本地文件写入由程序守住。`supervisor-design/`仅为设计，不在生产岗位扫描目录内。

## 来源与输入

源行及坐标不改。支持常见`△/▲`动作标记、独立/分行场记、点号场记、人物/道具字段与明确的VO画面标注续行。`【搭配画面：…】`保留给画面，但不念入对白；续行不能越过真实动作、空表演提示、场记或新说者。真正无归属的文本仍需核对，不靠把未知句一律归为动作来放行。

前情仅取有出处的前场原文，保持持物、能力、伤势与知情边界；未定位或尚未准备的资料不假称完备。没有图像素材不代表不能写文字，但不能声称图片已经绑定或生成稳定。

## 验证

```sh
npm run verify:storyboard-v4
npm run verify:storyboard-settings
npm run build
```

第一条包含内核/调度/回执/来源回归、工作台检查和设置浏览器回归。第二条可单独检查刷新、切换、轮询、新建参数和无候选选择。浏览器检查需已安装的Playwright浏览器；本机macOS还可使用已安装Chrome，不会自动下载浏览器。

需要更完整的隔离网页/接口联调时，在构建后运行：

```sh
npx tsx scripts/verify-storyboard-web.ts
```

该检查使用临时数据库、预置规划与本地假CLI回包，不调用真实生产模型；它不能证明新稿艺术质量、真实配音或视频生成效果。

## 数据与同步

任务、回包、回执和平读缓存默认位于 `.storyboard-v4/`，可用 `DIRECTOR_STORYBOARD_DATA_DIR` 指定本机目录。数据库、`.env`、CLI登录信息、本机运行记录和完整测试剧本不进入GitHub。源码包含验证所需的最小测试夹具。

固定私人项目的一次性灌样、清理、恢复脚本及其专属测试留在本机，不是通用发布工具。同步GitHub不迁移数据库，不修改CLI账号，不自动运行生产任务，也不合并到其他部署分支。
