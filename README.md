# Director Web · 本机3007资料与情绪分镜

本分支汇总第一阶段从导入、拆集分场、资产编目，到增量完善、失败恢复和按集交接的后端实现。它基于当前已验证的第一阶段工作副本，保留必要的操作页面，**不合并到 `main`，也不自动同步 `main` 后来的界面改动**。

第一阶段完成对象是可继续创作的**原文、场次、资产与状态资料**。本分支现另含第二阶段的本机情绪分镜测试入口：情绪统筹、完整主创、统一整编，输出文字分镜，不生成图片或视频。使用方法与边界见[3007情绪分镜说明](docs/storyboard-v4.md)。旧 P1/P2、E0–E5 代码、知识库和兼容测试仍保留，但旧后续生产入口未恢复；代码和工程检查通过不等于新稿艺术质量已验收。

## CTO业务交接与经验入口

本分支另收录[CTO业务交接与长期经验](docs/cto-handoff/README.md)：说明用户与CTO怎样从长期反馈、外部资料和实际失败中总结业务要求，哪些观点获认可、哪些仍待议，以及哪些历史成果可再用。由web-CTO于2026-09-12整理上传，含六份历史分析/交接的可移植副本与来源说明。

这些文档不覆盖下述现行第一阶段实现，也不表示新版第二阶段、51集成品或全部旧Skill已经通过验收。原始聊天、真实剧本、凭据和私有模型日志不随包上传；本机引用已转换为仓库内文档或来源说明。

按用户追加要求，另收录[外部Skill与平台经验参考库](docs/external-references/README.md)：灵墨六阶段八份编辑框提示词历史快照、保留MIT许可的同事规则包、用户提供的Higgsfield相关三文档，以及飞书资料的自有比较分析。均为私有研究参考，不自动安装/运行；来源、许可与缺口见各目录说明。

## 1. 第一阶段做什么

```text
TXT / MD / DOCX
  → 原件、读取文本与来源分区
  → P0 固定程序拆集 / 分场 / 提取明确字段
      ↳ 来源边界不明时，才由 F1 提交辅助计划
  → F2 资产与必要变体
  → Q1 对当前资料直接交增量修改
      ↳ 已有响应本地复验 / 有限局部修正 / 必要人工确认
  → 持续工作稿逐段保存
  → 单集交接包 + 只读预览 + 完整历史导出
```

| 环节 | 当前职责 | 不做什么 |
| --- | --- | --- |
| P0 | 固定 Python 解析、来源分区、场次边界和明确字段 | 不调用模型编写剧情 |
| F1 | 仅对程序无法确定的来源边界提供计划，由程序验证执行 | 正常稿不另生成全剧概述、逐集摘要 |
| F2 | 必要实体、基础身份、变体、适用集/场、素材准备方式 | 不登记万物，不把每个动作或特效变成图片 |
| Q1 | 对照本批原文与必要承接，直接修订资产和场次 | 不评分代替修正，不因局部错误重写整剧 |

用户通常只需“整理资料 / 继续完成”，不必逐个调度岗位。新作品仍需内容质量验证；结构检查通过不等于模型理解准确或用户认可。

## 2. 已确定的后端原则

### 原文是事实来源

- 原文件、读取文本、来源分区与分集正文分开保存。处理资料不能覆盖原剧本。
- 卷首人物设定、背景等不强塞进第一集；连续重复标题与重号异文分开处理，不用去重直接丢弃正文。
- 模型使用 `NUMBERED_SOURCE_V1`：每行是行号与原行文本，保留原换行，可以拼回原文；不重复发送另一份全文。
- 场次使用真实 `sourceRange` / `sceneRefs`。缺失、越界或来源不一致不能通过截断、补猜位置放行。
- DOCX 读取视图不等于完整复刻排版、图片或图片内文字；读取警告必须保留。

### 资产服务于实际制作

基础类型为 `CH / GROUP / BEAST / LOC / PROP`。基础身份与同一对象的必要服装、形态或持续状态分开；人物角色定位与素材准备方式是不同字段。

| `preparation.mode` | 含义 |
| --- | --- |
| `REFERENCE` | 需要稳定的独立参考 |
| `DERIVE` | 从明确的既有素材派生，`fromKey` 是素材来源 |
| `INLINE` | 保留必要引用或状态选择，随场表现，不单独制图 |
| `AUDIO` | 仅作为声音使用，不因此安排实体入镜 |
| `UNRESOLVED` | 仍有影响当前准备的真实缺口，不能假装就绪 |

- 尺度、姿态、透明度、普通日夜和瞬时破坏不自动产生派生图；必要服装、独特图面、关键物和连续可辨外观不能为减数量而删除。
- 普通物件是否独立准备取决于实际辨认和交互连续性；只有已确认可由角色/场景素材一致承载时才合入配套。
- 伤势、服装、残损要有起点与解除/覆盖边界：不能每集重置，也不能永久继承。状态解除本身不新增“恢复形象”。
- `fromKey` 不是剧情归属：召唤、觉醒或绑定不等于同一身份或图片派生。
- 已有对象沿稳定 `key`；同名不自动合并。显式归并和移出当前用途仍保留旧身份、素材及历史，不凭名称转移图片。
- 子状态范围冲突保留原声明并列为待核项；暂存范围不等于程序证实新增入镜。
- 某批只有画外音，不能覆盖该对象在其他集已经需要的可见基线。

### 持续工作稿，而非互相覆盖的结果

`FoundationDocument` 是当前事实入口，按修订保存；`PipelineRun` 是原始执行证据。正常第一阶段允许 `f1: null`，不为满足旧结构虚构摘要。

历史批准链另行保留；当前工作稿的 `COMPLETE` 不等于生成 `FOUNDATION_APPROVED` 批准包。

有效片段及时保存，后片失败不清空前片；只修改实际影响的集、对象和字段。读旧响应、重新校验旧响应、发新请求是三种不同操作。新接收程序或方法不能把旧运行记录改签成新模型结果。

| 版本边界 | 用途 |
| --- | --- |
| 来源版本与分集内容指纹 | 判断原文是否仍一致、哪些集真的变化 |
| 来源背景/风格等条件指纹 | 判断已用资料是否需按新条件调整 |
| 资产方法版本 | 区分目录采用的方法；更新提示不等于自动重跑 |
| 接收契约版本 | 按当前程序复验已返回内容，记录真实协议变化 |
| 工作稿修订 / 任务租约 | 阻止旧页面、旧工作器或并发操作覆盖新结果 |

人工选择使用稳定议题键与版本，按实际范围记录采用情况。收到答案不等于已应用；原文可解释、程序可处理或可留到后续表现设计的问题，不应机械变成用户问卷。

## 3. 停止、恢复与调用边界

核心控制器为 `lib/foundation-delivery.ts`。主要任务状态包括 `QUEUED`、`RUNNING`、`PARTIAL`、`WAITING_USER`、`INTERRUPTED`、`STOPPED`、`COMPLETE`。

- 完成且没有新输入时停止，没有无目标的“再次优化”。
- 同一工作输入最多一次格式修正；自动修正默认累计上限3次、最多2轮，无进展则停止。普通继续、删除/重建任务、换提示说法不能刷新旧失败的权限。
- 与当前范围无关的源文、决定或身份索引变化，不能让旧失败获得新调用额度。真正相关的新来源、决定或接收契约变化按对应工作范围处理。
- 历史请求/修正计数与当前预算域计数分开；预算域变化不是旧费用清零。上限不意味着所有异常都能自动修好。
- 停止保留已保存资料与原响应。写入时复核任务、工作器标识、来源和修订，不能让迟到结果污染新任务。

| 调用结果 | 后续处理 |
| --- | --- |
| `NOT_SENT` | 已知未发送，不计新模型请求 |
| `RESPONDED` | 保留完整原响应；先按当前接收器本地复验 |
| `UNKNOWN` | 未返回不等于未收费；不自动重发，须明确接受可能重复计费 |

原响应保存故障也不能直接重买；有效保存内容先复验。未知请求的确认要求保存在运行证据中，不依赖任务行是否还存在；程序维护入口也受此保护。

CLI token统计取自已保存的完成事件，缺失即未知。缓存包含在输入中，推理包含在输出中，不重复相加；日志统计不是账户账单，也不保证所有底层 HTTP 行为都已记录。

## 4. 场次兼容与安全拆场

- 新解析支持明确的连字符/点号/全宽点号场标题及逗号分隔字段；小数数量不能仅因后面有时间词就误切场。
- `SCENE_PARSER_V1 / V2` 按集随 `FOUNDATION_SOURCE` 保存。未改的旧原文保持既有场次解释，新或实际变化的原文采用新解析；已有工作器的不带版本请求仍按旧语义处理。
- Q1锚点最多去掉一个末尾行分隔符，剩余内容必须逐字匹配指定原行。不能整体 `.trim()`、删除内部换行或补造行号。
- `cuts` 表示已有场次内部的新边界。若返回把真实首段起点也列了进来，只能将其明确元数据搬回原场次；冲突仍拒绝，不能丢字段或造一个新首段身份。
- 拆场方案绑定源文版本并保存旧场次证据；场次变更与对应工作稿引用在事务中验证。原键留给首段，新片段使用原键加行号后缀。
- 完全相同的旧方案可按原基场复验；新编辑不能借旧方案扩大范围。人工字段、已有补丁与下游内容有保护检查。

## 5. 单集交接与导出

`readLightEpisodeFoundation` 是共享只读入口。预览页使用这一数据链；后续消费者可复用该入口，目前尚未接入新版第二阶段。读取不重新生成摘要或调模型。

`LIGHT_EPISODE_SUPPLY_V2` 提供：

- 本集原文一次、修订及来源版本；精确场次范围。
- 本集基础资产与匹配变体键；同场有变体时同时给出基础身份。
- 必要素材来源依赖闭包，单列为 `MATERIAL_SOURCE_ONLY`，不冒充本集出场。
- 必要前场原文末段和相关状态，带截取/缺口说明；它们是证据，不是永久继承命令。
- 本集后续表现提醒、读取警告和仍待解决的问题。

无效引用、准备方式未定、来源缺口、未完成编辑或未采用的相关决定影响对应范围的就绪度。多个状态是按原文选择的候选，不表示必须同时叠加。资料就绪不等于图片已生成、后续生产许可或成片验收。

项目导出保留当前工作稿、导入来源、历史版本与原始调用证据。**导出包含项目私有内容，不应直接提交到 GitHub。**

## 7. 从干净检出运行

这是完整源码、本地执行的应用，不是已经验收的无状态云服务或独立打包执行器。

要求：

- Node.js满足所锁定Next版本要求（至少20.9）；本次完整离线回归使用Node 24。
- Python 3，解析器只用标准库；本次完整回归使用Python 3.12。
- npm与本机可写SQLite存储。CLI模式另需已安装、已登录、可在本机运行的Codex CLI；应用不会代为安装或登录。

从仓库根目录执行：

```bash
npm ci
cp .env.example .env
npm run prisma:generate
npm run database:migrate
```

本分支不开放自行注册。先在本机设置 `TEST_ACCOUNT_INITIAL_PASSWORD` 为自行生成的强密码，再运行：

```bash
npm run accounts:seed
npm run dev:stage1
```

默认地址为 `http://127.0.0.1:3007`。初始化器创建 `tester01`–`tester05`；不要把密码或真实 `.env` 写进仓库。迁移已有库前先停止对应服务并确认备份；迁移脚本检查旧结构，并对已存在且含应用数据的数据库创建一致性备份。不要对重要数据库直接使用 `prisma db push`。

必须安装完整依赖：后台工作器依赖 `tsx`，不能将 `npm ci --omit=dev` 当成本分支已支持的部署方式。生产模式先运行 `npm run build`，再运行 `npm run start:3007`；开发模式也可用 `npm run dev:3007`。构建通过不代表模型内容或成片验收。不要省略 `scripts/`、`prompts/`、`runtime/` 和仓库知识库。

### 配置边界

以 `.env.example` 和代码配置为准：

- `DATABASE_URL` 指向本机库。示例相对SQLite路径按Prisma schema位置解析。
- `DIRECTOR_SESSION_COOKIE_NAME` 用于同主机多实例隔离。Cookie不按端口隔离，不同数据库的实例应使用不同名称。
- `PYTHON` 可指定Python可执行文件；否则查找 `python3`。
- CLI模型/推理强度按岗位覆盖优先，其次通用变量，最后代码默认。默认值见 `PROJECT_FOUNDATION_STAGES`；模型须以账户可用性和运行记录为准。
- API模式使用自行配置的 `DEEPSEEK_API_KEY`。第一阶段采用显式岗位正文：API系统消息与CLI内嵌指令不是完全相同的传输层级。
- 第一阶段角色使用临时、自包含请求，不依赖用户另装旧岗位Skill，也不默认携带旧角色会话。

## 8. 验证与本地恢复

主要离线检查：

```bash
npm run typecheck
npm run verify:light-stage1
npm run verify:release
npm run verify:storyboard-v4
npm run build
```

`verify:light-stage1` 覆盖固定解析、拆场/版本、精确锚点、旧响应复验、持续工作稿、停止/未知结果、费用边界、资产/导出、只读交接与鉴权。运行检查使用合成输入或临时数据库，不运行真实模型。`verify:foundation-delivery` 可单独检查通用交付链；旧协议回归另保留在 `verify:foundation*` 中，不等同于当前唯一入口。

选择性工具：

- `scripts/recover-foundation-locally.ts`：默认复制指定数据库预演；明确 `--apply`、当前修订且任务闲置无未知请求才写回。始终拒绝新模型请求；只恢复已有且校验有效的结果，不把未执行范围标为完成。
- `scripts/apply-foundation-program-repair.ts`：默认共享只读预览；显式、已核对的来源修正可用 `--apply` 执行，不购买Q1或伪造编辑覆盖。
- 历史复验/校准工具须显式指定输入；用到SQLite备份/读取的工具还需本机 `sqlite3` 命令。
- 浏览器端到端检查另需Playwright对应浏览器。真实CLI/API验证为显式opt-in，可能产生费用，不属于上述离线测试；不得自动运行 `*:live` 或真实API检查来证明安装成功。

本分支对持续任务和若干真实输入边界进行过验证，包括相邻集状态、尺度变化、点号场次和原响应恢复。私有样本及日志不随源码发布。测试、本地复验、模型内容准确性、图片/成片质量和用户认可应分别记录。

已观察到默认Node 26/系统Python组合在部分检查中偶发等待输入，未稳定复现根因；配套运行时完整检查通过不代表该现象已修复。遇到类似情况先检查进程与输入管道，不重复触发业务模型请求。
