# 主控决策场景

例子用于识别机制，不是固定镜长、固定特效或一律退回的模板。

| 现场证据 | 主控判断与动作 | 不应采取的做法 |
| --- | --- | --- |
| 源中已收盾，现稿为展示压制又让盾从头亮到尾；格式检查全过 | 向整编发源状态问题，联修画面/光影/幻想入口，保留角色抵抗 | 补源中没有的新开盾动作，或把“护罩被压制”的原话删掉 |
| 灭门后的不甘被画成Q版跳脚、爱心和弹簧眼 | 修情绪错调；可以大幅度咬牙、前压、握拳，不必减成微表情 | 认为有漫画特效就达标；或以“稳”为由去掉张力 |
| 英雄救场镜很炫，主角却始终被火遮住 | 指出人物承担的关键动作没被看见，交统一整编联修现稿 | 继续叠特效；让主控自己再写一个平行版本 |
| 两句对话间空等3秒，画面没有变化 | 收紧气口；若这3秒有咬下食物、刺激对方恼怒等因果，不机械删除 | 所有停顿一律删；加快整段语速或塞进无来由的路人反应 |
| 开口前0.8秒要退两步、吐血、看掌、抬头 | 留足必要动作，减少重复看掌，调自然镜界/单元边界，再验台词与表演共时 | 先要求真实演员/视频拍出来才肯改文字；或把吐血删掉省时 |
| 画外转画内是合理可见性变化，检查器却当成OS | 请求程序有依据地重校，保留原现场声道；无需再买整份稿 | 改原话/改声道来迎合错误校验 |
| 已存raw但包装JSON损坏 | 程序先尝试允许的解析归一；失败才给同范围整编修格式与缺失，保留raw | 删除原响应、清费用后整集重跑 |
| 结果未知，赶交付，有人建议换任务B再发 | 核对原回执，不以时间压力转为重发授权；说明当前可用成果和待确认范围 | 将UNKNOWN猜为失败，绕过同集保护或自行允许重复费用 |
| 一段连续两次修复仍是同样矛盾 | 对比真正变化、重查前情/约束冲突，提出不同根因的窄测试；无有效新方向则升级 | 只把“再认真一点”发给同一人，重置修复轮次 |
| 文字无实质问题，只是主控更偏爱另一种镜头 | 保留现稿；可给一条不阻塞的建议 | 改掉全部镜头来体现主控存在，导致1+1小于2 |
| 网页滚不动，模型没有代码工具 | 保留可用稿，技术故障与内容状态分开；提交复现位置、错误与维护请求 | 主控宣称修好了网页，或重新生成文本试图解决CSS问题 |
| 单集还有一段没完成，额度已到停止线 | 保存正确部分，向用户一次说明还差什么、需要哪项授权；其他独立已授权任务不受影响 | 主控自抬额度，或者把缺段稿当完整稿交付 |

正常任务不需要把以上每个案例都读入；只加载与当前问题有区分价值的例子。
