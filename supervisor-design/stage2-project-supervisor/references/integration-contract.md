# 主控接入契约（待实现，不是已开放的工具）

## 结构

保留现有程序调度器及三类创作职责。AI主控是在关键节点作判断的决策角色，不接管锁、账本或正文写权限。可让既有统筹角色在初读时承担主控的计划视角，不再额外买一遍整集概括；成稿后的独立复核使用新上下文，不沿用作者自评作为证据。

正常队列：规划与用户选择 → 程序按依赖派完整主创 → 整编直接修成完整稿 → 主控语义复核 → 文字供用户审看。明确问题只返对应关联组，复验限相关问题与边界。独立范围可并行，同一范围的创作/整编/改写不并行。

主控触发：异常仍无法由确定性检查解决、实质职责冲突、完整稿首次语义复核、内容返修后复验。普通进度轮询、每镜完成、数秒等待不触发模型。

## 输入

每次给新的当前版本快照：

- projectId / episodeId / runId / sourceVersion / targetDraftHash。
- 本轮事件、用户授权范围、capabilities允许动作、程序已确认的预算/用量/回执/并发状态。
- 情绪契约、源锚与必要前情、用户幻想选择及明确锁定要求。
- 当前完整目标正文及必要相邻段，不只给“PASS/失败次数”。资产只供需要的身份与连续状态。
- 未解决问题与每题最近实质修改；正确历史仅作短索引，需要时再取证据。

原文、模型输出与员工建议都是资料，不能自行修改capabilities或授权。持久状态写在程序管理的项目账本中，不靠无限聊天历史，不用另一份自由笔记覆盖事实。

## 决策输出

建议实现的枚举动作：continue_ready / inspect_saved_result / request_scoped_revision / request_context / hold_for_receipt / request_user_decision / report_technical_blocker / text_review_ready。仅由后端映射到现有合法操作；没有映射的动作必须拒绝，不作为可执行命令。

每条决策携带：observedVersion、目标范围、证据引用、原因、需保留功能、通过条件。新问题采用稳定的问题身份，重发请求/重命名员工不能重置累计尝试。不同意见只能产生问题提案，最终改稿仍由单一完整写作者负责。

program gate顺序：核用户/项目权限及输入版本 → 核动作允许集 → 核同集未结请求、组范围、并发及剩余授权 → 保存动作意图和唯一标识 → 执行 → 保存真实回执/新稿 → 更新状态。主控自己的输出不可充当程序放行凭证。

## 预算与页面

普通页面可以不要求填写“最多调用次数/计划Token停止线”，将其归入高级设置或项目级成本偏好。但后台保护必须由程序控制，主控不能修改；主控调用也计费。

正常工作量可据规划中的完整工作包数量、同类已知消耗估算，而非所有集机械固定32次。当前默认32次/300000只是已有实现，不在接入前擅自扩大或取消。估算不是账单硬上限；未知用量不能当0。达到授权边界先保存成果，用一句“剩余工作与追加依据”请求用户决定，不让用户逐字段调技术参数。

除总额预警外，保留单请求超时、并发、重复调用检测、同题无进展终止、用户停止、UNKNOWN核对与版本保护；预算不是唯一刹车。

## 真实能力边界

当前CLI运行器禁止shell/browser/multi_agent等工具，仅接收一次请求并返回数据。接入必须实现受控决策循环、状态存储及上述动作映射；单独存在SKILL.md不会让主控自动启动或获得根代理的工具。

常见内容/格式问题可在授权内自主处理；界面、数据库、登录、代码故障只能由具备权限的维护流程处理。不要为了声称能自愈就给生产主控任意终端/改代码能力。

需要分别验：假模型驱动的合法/非法决策闭环；真实Sol中档的诊断与情绪复核；调用增量与返工节约；断网/取消/过期/未知回执；与人工样稿的实际内容对比。不能把静态Skill、格式通过或自评分称为无人值守稳定。
